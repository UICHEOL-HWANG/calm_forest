# 링크드인 분석 카드뉴스

게임 플레이 데이터 분석(가설 → 탐색 → 차트 → 판정)을 링크드인 캐러셀로 압축하는 작업 공간.
**인스타그램 카드뉴스(상위 `tools/cardnews/`)와는 목적도 발행 경로도 다르다.**

## 파이프라인

```bash
cd tools/cardnews
node linkedin/build-cards.mjs analysis-story        # decks/<슬러그>.json → templates/NN-*.html
node linkedin/render.mjs --deck analysis-story     # 그 덱의 카드만 → out/*.png (1080×1350)
```

| 경로 | 용도 | git |
|---|---|---|
| `decks/<slug>.json` | **카드 내용의 유일한 원본.** 카피·수치·차트 정의 | 추적 |
| `templates/card.css` | 공유 디자인 시스템 | 추적 |
| `templates/NN-*.html` | 빌더가 생성 — **직접 고치지 말 것**(다음 빌드에 지워진다) | 추적 |
| `templates/_archive/` | 예전 한 장짜리 요약 포스터. 자동 렌더 대상 아님 | 추적 |
| `assets/trails.svg` | 배경 네온 궤적. `make-trails.mjs` 가 생성 | 추적 |
| `out/*.png` | 최종 산출물 | ignore |

⚠️ `assets/figs/` 와 `crop-figs.py` 는 **차트를 직접 그리기로 바꾸기 전의 잔재**다.
아무것도 참조하지 않는다. 지워도 된다.

**이 디렉토리 밖은 건드리지 않는다.** 상위의 `deck.mjs` · `publish.mjs` · `queue.mjs` ·
`cron-*.sh` 는 인스타 자동 발행 파이프라인이다. 링크드인 덱은 `linkedin/decks/` 아래
의미 있는 slug 로 만든다(`deck-NN.json` 금지).

## 카드 추가하기

`decks/<slug>.json` 의 `cards` 배열에 넣는다. 블록은 세 종류다.

```jsonc
{ "id": "slug", "trail": "hero|band|edge", "eyebrow": "04 · 섹션명",
  "title": "두 줄까지<br>줄바꿈", "lede": "표지에만 쓰는 도입부",
  "pills": [{ "text": "칩 문구", "tone": "rose|cyan|" }],
  "blocks": [
    { "stat": "59%", "tone": "cyan", "text": "설명(<b>강조</b> 가능)",
      "pills": [], "chart": { "type": "…" } },       // 근거 블록
    { "kind": "note", "title": "제목", "body": ["문단", "문단"] },  // 마무리 블록
    { "kind": "kicker", "text": "한 줄 결론" }
  ] }
```

`trail` 은 배경 궤적의 양이다 — `hero`(표지) · `band`(차트 1개) · `edge`(차트 2개).
**차트가 두 개인 카드는 반드시 `edge`.** 안 그러면 아래쪽 막대가 궤적과 겹쳐 지저분해진다.

## 차트

matplotlib PNG 를 얹지 않는다. 흰 배경이 충돌하고 축 글씨가 깨진다.
`build-cards.mjs` 가 **카드 디자인 언어로 직접 그린다**(인라인 SVG). 네 종류:

| type | 쓸 곳 | 필드 |
|---|---|---|
| `stackedBar` | 항목별 구성비 | `max`, `legend[{label,color}]`, `rows[{label,segs[],note}]` |
| `column` | 분포·단계별 감소 | `bars[{label,v}]`, `highlight[인덱스]` |
| `funnel` | 줄어드는 경로 | `steps[{label,v,note}]` — `v:0` 은 점선 빈칸으로 그려진다 |
| `dotRange` | 비율 + 오차 범위 | `max`, `points[{label,p,lo,hi,note}]`, `caption` |

원본 수치는 `ml/reports/figs/*.png` 와 `docs/analysis/ANALYSIS_GATES.md` 에서 옮긴다.
**차트를 새로 계산하지 말 것** — 카드는 이미 판정이 끝난 값을 옮겨 적는 자리다.
`dotRange` 의 `lo`/`hi` 는 원본과 같은 방식(95% 윌슨)으로 계산했고, 카드 위에서는
"오차 범위"라고만 부른다.

## 작성 규칙

작업하면서 사용자가 직접 교정한 것들이다. 새 카드도 전부 여기에 맞춘다.

### 제목
- **대제목은 번호 + 명사구다.** `1. 아무것도 안 한 기기` · `4. 가설 검정 결과`.
  한국어 보고서는 대제목을 문장으로 쓰지 않는다. "열어보니 해석이 안 됐습니다" 같은 문장은 **중제목(`lede`)으로 내린다.**
- 대제목이 명사구가 되면 눈썹 자리가 비어 보인다. 거기에 **데이터 구간과 출처**를 넣는다
  (`2026.07.26 – 08.31 · 초기 분석`). 장식이 아니라 어느 시기 무슨 자료인지 밝히는 자리다.

### 말
- **지어낸 말을 쓰지 않는다.** 실제로 쓰는 한국어로 쓴다. 이번에 걷어낸 것들:
  `무행동 기기` `로그 신뢰도` `입구 지표` `세그먼트 감사` `재방문 신호 탐색` `전체 채널`
  `관대 판정` `접속 성실도` `단위 탓`. 설명이 필요한 말은 이미 실패한 말이다.
- **전문용어 금지.** 윌슨 구간 → "오차 범위", 표본 오염 → "기록이 섞여 있었다",
  AUC·이벤트 밀도 → 쉬운 말로 풀어 쓴다. 숫자는 그대로 두고 이름만 바꾼다.
- **"놀다"가 아니라 "플레이하다".** `28분을 더 플레이했습니다`.
- 제목과 본문이 같은 말을 두 번 하지 않는다.

### 가설 행 (`ledger`)
- **질문형으로 쓰고 물음표를 붙인다.** `유저들이 마지막으로 플레이하다 종료하는 지점은 벌목일까?`
  서술형(`게스트가 막히는 벽은 벌목이다`)보다 읽는 사람이 답을 기다리게 된다.
- `sub`는 **"아닙니다"로 시작해 근거 수치를 댄다.** 한 문장이면 더 좋다.
- **설명이 두 줄로 넘어가면 그 행만 높아져 줄이 어긋난다.** 한 줄에 맞춰 줄인다.
- 판정 칩은 짧게: `기각` `일부 지지` `지지`. `part: true` 면 시안색(살아남은 쪽).

### 시기를 섞지 않는다 — 가장 크게 틀렸던 것
- **한 카드 안에 다른 시기 데이터를 끌어오지 않는다.** 초기 분석(2026.07.26–08.31),
  베타 테스트(09.09–09.15, 10명), 그 이후 분석은 **서로 다른 구간이다.**
  베타 가설(Hβ1~8)을 초기 분석 카드에 넣으면 읽는 사람이 오해한다.
- 카드를 만들기 전에 **그 수치가 어느 구간 것인지 먼저 확인한다.** `ANALYSIS_GATES.md` 의
  분석 실행 날짜(9월)와 **데이터 구간**(7~8월)은 다르다. 헷갈리면 노트북을 연다.
- 다른 시기 얘기가 꼭 필요하면 **별도 블록으로 분리**하고 그렇다고 적는다.

### 수치
- **기록에 있는 값만 쓴다.** 노트북·`ANALYSIS_GATES.md` 에서 옮기고, 새로 계산하지 않는다.
- **평균과 중앙값을 구분한다.** 기록이 중앙값이면 "평균"이라고 쓰지 않는다.
  카드에서 용어를 피하고 싶으면 숫자만 남긴다(`5~6가지`).
- **기록에 없는 결론을 만들어 넣지 않는다.** 사용자가 판단을 덧붙이라고 하면 그렇게 하되,
  그게 기록이 아니라 지금 내리는 판단이라는 걸 먼저 알린다.
- 사용자가 준 문장에 수치 오류가 있으면 **고쳐서 넣고 무엇을 고쳤는지 말한다.**
  공개되는 카드라 틀린 숫자가 나가면 안 된다.

### 증빙 스크린샷 (`shots`)
- 의미 있는 영역만 **미리 잘라서** `assets/shots/` 에 둔다. 통짜로 넣으면 작아져서 안 보인다.
- 높이를 고정(`.shot img { height }`)해 나란히 세운다. **푸터가 밀리면 높이부터 줄인다.**

### 끝내기 전에
- **렌더한 PNG 를 직접 열어서 확인한다.** 코드만 봐서는 안 보이는 사고가 난다 —
  가장 높은 막대의 값 라벨이 잘리고, 이미지를 넣으면 푸터가 화면 밖으로 밀린다.

## 색·차트 규칙

- **계열색은 로즈 `--rose` 와 시안 `--cyan` 둘뿐이다.** `dataviz` 스킬의 검증
  (다크 밴드·색각·대비)을 통과한 값이라 임의로 바꾸지 않는다. 골드는 텍스트 악센트 전용,
  슬레이트는 중립 막대 전용. **값의 크기에 따라 투명도를 바꾸지 않는다**(색이 순위를 뜻하게 된다).
- 차트 안 글자에는 계열색을 입히지 않는다(`.c-label` `.c-value` `.c-tick` 사용).
- 상위 `STYLE.md`(인스타 게임 목소리)는 여기 적용하지 않는다.
- 카드 한 장에 차트는 최대 2개. 더 넣으면 축 글씨가 읽히지 않는다.

## 🚨 덱이 여럿일 때 — 덮어쓰기 사고 방지

**2026-09-20에 실제로 한 번 날아갔다.** 코덱스가 토스 덱을 만들면서 같은
`decks/analysis-story.json` 에 써 버려 기존 10장짜리 덱 원본이 사라졌다. 이 디렉토리는
git 추적 밖이라 되돌릴 이력이 없었고, 렌더된 PNG와 대화 기록으로 복원해야 했다.

### 작업 시작 전에 확인할 것

```bash
ls tools/cardnews/linkedin/decks/*.json     # 이미 있는 덱을 먼저 본다
```

### 규칙

1. **새 덱은 새 slug 파일을 만든다.** `decks/<내-슬러그>.json`. 남의 덱 파일을 열어 내용을
   바꾸지 않는다. 기존 덱에 카드를 *추가*하는 것과 덱을 *교체*하는 것은 다르다 —
   교체가 필요하면 먼저 사람에게 묻는다.
2. **빌드는 slug 를 명시한다.** `node linkedin/build-cards.mjs <슬러그>`.
   인자를 빼면 `analysis-story` 가 대상이 되므로, 다른 덱을 만들면서 빼먹으면 덮어쓴다.
3. **`templates/NN-*.html` 은 빌더가 만드는 자리다.** 빌더는 `decks/.<슬러그>.manifest.json`
   에 자기가 쓴 파일명을 적어 두고 **다음 빌드에 그 목록만 지운다** — 다른 덱 카드는 건드리지
   않는다. 다만 손으로 쓴 HTML 은 어느 덱 것도 아니므로 `decks/` 아래 자기 폴더에 보관한다.
4. **`out/` 도 공유된다.** 카드 `id` 가 겹치면 남의 PNG 를 덮어쓴다. 덱마다 id 를 구분되게
   짓는다(`toss-entry`, `beta-ledger` 처럼 내용이 드러나게). 표지도 마찬가지다 —
   `cover` 는 두 덱이 동시에 쓰기 쉬우니 `toss-cover` 처럼 붙인다.
5. **렌더는 `--deck <슬러그>` 로 한다.** 인자 없이 돌리면 `templates/` 안의 *모든* 덱이
   렌더돼 남의 PNG 까지 다시 생긴다.
5. **덱을 합칠 때는 JSON 블록으로 옮긴다.** HTML 을 그대로 갖다 붙이면 페이지 점(dots)과
   번호가 안 맞는다. `card.css` 클래스만 쓴 카드라면 `ev`·`note`·`ledger`·`shots` 블록으로
   그대로 옮겨진다.

### 남의 카드를 가져올 때

용어와 문체는 **이 README 의 「작성 규칙」에 맞춰 다시 쓴다.** 실제로 코덱스 카드를
합치면서 `저밀도/고밀도` → `20회 미만/이상`, `의도 행동` → `직접 조작한 행동` 으로 고쳤다.
가져온 카드만 다른 말투를 쓰면 한 덱으로 안 읽힌다.
