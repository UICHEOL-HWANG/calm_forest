# 🧪 베타 A/B 테스트 설계 (2026-09-02)

베타테스터 10명 · 1주일. A/B 번들 실험(개편판 3종)과 운영자 전용 베타 관제 대시보드.
예측 모델(이탈 예측)은 베타 데이터 수집 후 다음 주에 별도 기획한다 — 이 문서 범위 밖.

## 결정 요약

| 항목 | 결정 |
|---|---|
| 실험 구조 | **번들 A/B 5:5** — A군 5명=개편판 3종 전부, B군 5명=현행판 (실험별 독립 배정은 10명 규모에서 셀당 1명꼴이라 기각) |
| 배정 방식 | **명단 테이블** — Supabase `beta_testers`(email → grp)로 직접 지정. 해시 자동 배정은 10명에서 쏠림 위험이라 기각 |
| 계정 | 전원 **구글 OAuth 신규 가입** → `created_at` 기준일 사용 가능 |
| 일반 유저 | 명단에 없으면 기존 로직대로 `control` — 실험 밖, 게임플레이 변화 없음 |
| 튜토리얼 개편 | **17단계 유지 + 순서 재배치** (재미 단계 전진) — 단축판·체크리스트형 기각 |
| 보상량 개편 | **가입 후 3일 부스트 ×1.5** (출석·퀘스트·판매) — 전액 상향은 인플레 위험이라 기각 |
| 난이도 개편 | **미니게임별 첫 3회 관대 판정 ×1.3** — 러버밴딩(복잡)·전역 완화(숙련자 재미 손실) 기각 |
| 관제 | **운영자 전용** `dashboards/beta_monitor.html` — 기존 admin_analytics 인증 패턴 재사용. 테스터 본인용 뷰는 범위 밖 |

## 1. 배정 인프라

- Supabase 테이블 `beta_testers`: `email text PK, grp text CHECK (grp IN ('A','B')), note text`.
  RLS: 로그인 유저는 **자기 이메일 행만** SELECT 가능. 쓰기는 service role만.
- `js/supabase-client.js` — 로그인 완료(applySession) 후 자기 행 조회:
  - 행 있음 → `state.variant = 'beta_A' | 'beta_B'`
  - 행 없음/게스트/오프라인 → 기존 `assignVariant()` 결과 (현행 유지)
- `CONFIG.EXPERIMENT = 'beta'` 로 전환. i18n 실험은 전면 롤아웃 상태 — 언어 결정 로직
  (`detectLang`)이 EXPERIMENT 값 변경에 영향받지 않는지 구현 시 확인.
- variant는 이미 모든 Supabase 이벤트·GA4 유저 속성(`ab_variant`)에 실려 나가므로
  트래킹 추가 작업 없음.

## 2. 변형 파라미터 — `js/tuning.js` 신설

산재한 상수는 건드리지 않고, 분기가 필요한 값만 모은다.

```js
export const TUNING = {
  rewardBoost:  { days: 3, mult: 1.5 },   // A군만 — 출석·퀘스트·판매 보상
  firstTryEase: { tries: 3, mult: 1.3 },  // A군만 — 미니게임 판정창·타이밍 관대
  tutorialOrder: [/* A군 재배치 배열 — §3 */],
};
```

- 보상 배율은 `giveReward` 경유 지점에 적용. **원장에 boost 적용 여부를 기록**해
  분석 시 원값 복원이 가능하게 한다.
- "가입 후 3일"은 Supabase `user.created_at` 기준 (전원 신규 OAuth 가입 전제).
- 관대 판정: 미니게임별 시도 횟수를 세이브에 저장, 첫 3회는 판정 계수 ×1.3.
  대상: 배 운행(장애물)·바다낚시·안개 리듬·조각 등 판정창이 있는 미니게임.

## 3. 튜토리얼 재배치 (A군)

스텝 내용·개수(17)는 그대로, 순서만 변경. 가설: 이탈 원인은 길이가 아니라 "재미없는 초반".

- A군: 이동 → 도구 → 벌목 → **🎣낚시 → 🏠집짓기 → 입장 → 꾸미기** → 밭갈기 → 씨앗
  → 물주기 → 수확 → 판매 → 시세 → 퀘스트 → 채굴 → 조각 → 도감
- B군: 현행 순서 유지.
- 의존성 검증: 집짓기는 목재 필요(벌목 뒤 OK), 꾸미기는 입장 뒤 OK, 낚싯대는 기본 도구 세트 OK.
- `tutorial_step` 이벤트에 **순서 인덱스 + 스텝 key** 둘 다 기록 → 군간 스텝 퍼널 비교.

## 4. 베타 관제 대시보드 — `dashboards/beta_monitor.html`

"베타 관제" 목업(아티팩트, 2026-09-01)을 실페이지로 승격.

# 🧪 2차 설계 (2026-09-06) — 4겹 실험 · 2026-09-09(수) 시작

1차 설계(위)의 번들 A/B는 그대로 두고 세 겹을 더 얹는다. **사람을 5:5로 나누는 축은 번들 하나뿐**이다.
나머지는 세션 단위(배너), 같은 사람의 전후 비교(맵), 짝지은 선호도(마지막 날)로 잰다.

## 0. 일정

| 날 | 날짜 | 게임 | 테스터 |
|---|---|---|---|
| D0 | 9/8(화) | 명단 등록·`main` 배포·폰 검증 완료 | 안내문 받고 구글 가입 |
| D1~D7 | 9/9(수)~9/15(화) | 번들 A/B 적용 · 매 세션 배너 동전 | 하루 최소 1회 접속 · 저녁 일지 3분 |
| D1~D2 | 9/9~9/10 | 바다터·안개숲 둘 다 잠김 | |
| D3 | 9/11(금) | 각자 **첫 번째 맵** 열림 | |
| D5 | 9/13(일) | **두 번째 맵** 열림 | |
| D7 | 9/15(화) | 마지막 | 일지 + 선호도 문항 2개 |
| D8~ | 9/16~ | 집계·보고 | 실험 공개·보상 |

## 1. 배정 (실험 전 고정)

| 테스터 | 번들 | 맵 여는 순서 |
|---|---|---|
| 5명 | `beta_A` (개편 3종) | 3명 `sea_first`(바다터 D3 · 안개숲 D5) / 2명 `mist_first`(반대) |
| 5명 | `beta_B` (현행) | 2명 `sea_first` / 3명 `mist_first` |

- 번들과 맵 순서를 엇갈려 넣는다 — 한 실험이 다른 실험과 한 몸이 되지 않게.
- `beta_testers` 테이블에 `map_order text CHECK (map_order IN ('sea_first','mist_first'))` 추가. 배정은 이메일 명단을 받아 무작위로 채운 SQL 로 넣는다.
- 배너 arm 은 명단과 무관 — 세션마다 클라이언트가 동전을 던진다(`TUNING.churn.treatRate` 0.5).
- 전원 구글 OAuth 신규 가입. `user.created_at` 이 D1 기준일이다.

## 2. 네 겹의 실험

| 실험 | 단위 | 처치 | 지표(순서 고정) | 판단 |
|---|---|---|---|---|
| ① 번들 A/B | 사람 5:5 | 튜토리얼 재배치 · 3일 보상 ×1.5 · 첫 3회 관대 판정 | 해본 활동 가짓수 → 자발 접속 횟수(하루 1회 초과분) → 총 플레이 시간 | 방향만. 세 지표가 같은 방향이면 신호, 갈리면 무효 |
| ② 힌트 배너 | 세션 동전 | 곧 나갈 것 같을 때 비차단 배너 | 배너 뒤 60초 생존율, treat vs control | 방향만 |
| ③ 맵 계단식 열기 | 같은 사람 전후 | 바다터·안개숲을 D3/D5 에 엇갈려 개방 | 열기 전날 대비 당일 플레이 시간·방문 수, 다음 날 재방문 | 두 순서에서 같은 방향이면 맵 효과, 한쪽만이면 요일 효과 |
| ④ 선호도 | 10명 짝지음 | D7 설문 2문항 | 한쪽 9명 이상 | 9명 이상이면 유의(이항 p=0.022), 아니면 무 |

**잴 수 없는 것(미리 적어둔다)**: 이탈·유지율. 유급 테스터는 일주일 하기로 한 사람이라 떠나지 않는다. ③은 "관심도"까지만 말한다.

## 3. 테스터 지침

**알려주는 것**
- 9/9(수)부터 9/15(화)까지 7일. 매일 최소 한 번 접속해서 **자유롭게** 논다(더 해도 됨. 얼마나 더 하는지가 지표라 "하루 1번만" 이라고 못 박지 않는다).
- 저녁에 게임 메뉴의 일지 버튼으로 3분짜리 일지.
- "콘텐츠가 며칠에 걸쳐 차례로 열립니다."
- 보상은 7일 완주 + 일지 7회 기준.

**숨기는 것(D7 설문 뒤 공개)**: 두 팀이 다른 버전인 것 · 배너가 실험인 것 · 맵 여는 날이 사람마다 다른 것.

## 4. 일지 (직접 만든 폼 · `calmforest.cloud/beta/diary`)

구글 설문지 대신 직접 만든다 — 게임 로그인이 이어져 **누가 며칠째 쓴 일지인지 자동으로 붙고** 그날 플레이 기록과 조인된다.

- 페이지 `beta/diary.html` (새 폴더, 빌드 목록에 추가). `dashboards/` 와 분리.
- 저장은 Supabase `beta_diary` (email · day · q1~q4 · q5·q6 · created_at). RLS: 본인 행만 insert/select. Worker 라우트 없음.
- 게임 ☰ 메뉴에 버튼 1개, 베타 테스터(`beta_*`)에게만 보임.
- 운영자 관제 `beta_monitor` 에 일지 탭 + 맵 열림 상태.
- **매일 같은 4문항**, D7 에만 2문항 추가.

| # | 문항(초안 · 검수 필요) | 형식 |
|---|---|---|
| 1 | 오늘 뭐 했어요? | 자유 |
| 2 | 어디서 막히거나 지루했어요? | 자유 |

| 6 (D7) | 처음 10분 순서 두 가지 영상 중 어느 쪽이 좋아요? | A / B |

일지를 쓰면 더 열심히 놀게 되는 효과는 양쪽 팀에 똑같이 걸려 상쇄된다. 팀을 들키는 질문("튜토리얼 순서 어땠어요?")은 넣지 않는다.

## 5. 맵 잠금 규칙

- 대상: `beta_A`/`beta_B` 만. 일반 유저는 영향 없음.
- 기준일: `user.created_at` 의 KST 날짜 = D1. `day = 오늘 − D1 + 1`.
- `sea_first`: 바다터 `day >= 3`, 안개숲 `day >= 5`. `mist_first`: 반대.
- 잠긴 입구에 가면 코치·배너로 "N일차에 열려요". 열리는 날 첫 접속에 1회 안내.
- 동굴은 잠그지 않는다 — 튜토리얼 채굴·조각 단계가 막힌다.
- 파라미터는 `js/tuning.js` 에: `mapGate: { sea_first: {sea:3, mist:5}, mist_first: {sea:5, mist:3} }`.
