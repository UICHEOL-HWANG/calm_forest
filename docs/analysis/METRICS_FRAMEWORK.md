## 1. 목적

### 프로젝트 주제 한 문장

> calm forest에 처음 온 플레이어의 57%가 첫 주에 온보딩을 하거나 잠깐 둘러보기만 하고 수확·물고기 낚기·퀘스트 완료 같은 획득 행동 없이 떠나며, 이들의 2주차 재방문율은 3.6%로 획득 행동을 한 플레이어(16.1%)의 4분의 1에 그친다.

| 첫 7일(0~6일차)에 | 인원 | 8~21일차 재방문 |
|---|---|---|
| 획득 행동 1번 이상 | 62 | 10 (16.1%) |
| 획득 행동 0번 | 83 (57%) | 3 (3.6%) |
| └ 온보딩까지만 (캐릭터·인트로·튜토리얼) | 36 | 첫 주 플레이 중앙값 5.6분 |
| └ 둘러보며 시도 (주민 대화 22·의뢰 수락 12·벌목 11·씨 뿌리기 6) | 45 | 중앙값 3.1분 |
| └ 로그인·출석 기록뿐 | 2 | — |

- 대상: 첫 접속 8/6~9/16 신규 145명, 웹·토스, 페르소나(P1) 제외, 혼합 키 · 스크립트 `dev/active/metrics-framework/validation/new_user_first_week.py`
- **인과 아님.** 첫 주 방문일이 같은 사람끼리 보면 차이가 줄어든다(1일 방문 4.9% vs 1.3%, 2일+ 38% vs 33%). "첫 획득을 앞당기면 재방문이 는다"는 A/B 로 검증할 **가설**이다
- 재방문 양성 13명 — 표본이 작다

### 지표 체계의 목적

"이번 주 calm forest 가 나아졌나?"에 숫자 하나와 그 숫자를 움직이는 레버 몇 개로 답한다.

| 우선순위 | 답하려는 질문 |
|---|---|
| 1 | 사람들이 이 게임을 **매일 잠깐씩 습관처럼** 다시 찾는가 |
| 2 | 새로 온 사람이 게임의 재미(첫 획득 행동)까지 도달하는가 |
| 3 | (품질 기준) 측정 방법이 설명 가능하고 엄밀한가 |

## 2. 북극성 지표

> **하루 평균 가꾼 주민 수** (Daily Tending Villagers)
> 지난 7일 동안 "가꾼 하루"를 보낸 (주민 × 날)의 수 ÷ 7

| 요소 | 규칙 |
|---|---|
| 주민 | 로그인 계정 = `user_id`, 게스트 = `client_id`. 게스트 기기가 나중에 로그인하면 그 기기의 과거 기록을 계정으로 합친다. **단 한 기기에 로그인 계정이 2개 이상이면 합치지 않는다** (누구 기록인지 모름). 구현 `validation/person_key.py` |
| 하루 | KST 자정 기준, 세션 시작 시각 |
| 가꾼 하루 | 아래 **획득 행동** 중 1회 이상 |
| 표시 | 7일 이동 평균. 주간 보고는 그 주 값 |
| 모집단 | **공식** = 페르소나·개발자 제외, 베타테스터는 베타 기간(9/9~9/15)만 제외 · **원본** = 필터 없음. 항상 나란히 표시 |
| 플랫폼 | 웹 · 토스. 안드로이드(로그 없음)·itch(획득 행동 0)는 계측 수정 후 편입. **GA4 에서 platform 속성이 비어 있으면 웹으로 본다** |

### 획득 행동 16종

| 분야 | 이벤트 |
|---|---|
| 농사 | `harvest_crop` 수확 · `coop_collect` 달걀 · `honey_collect` 꿀 |
| 낚시·채집 | `fishing_catch` · `sea_catch` · `firefly_catch` · `forage_pick` · `mine_ore` |
| 만들기 | `craft_item` 제작 · `craft_claim` 밤사이 가공 수령 · `cooking_result` 요리 · `cafe_serve` 카페 · `carve_result` 조각 |
| 마을 | `quest_complete` 퀘스트 · `star_result` 천문대 · `duel_result` 밤손님 |

**뺀 것과 이유**
- `dex_discover` — 수확·낚시의 부산물, 같은 행동을 두 번 셈
- 스토리·튜토리얼·집 완성 — 1회성 진행, 습관이 아님
- `cook_eat` — 소비 행동
- 물 주기·파종·벌목 — 얻는 것이 없음 (사용자 결정: "무언가를 손에 쥐고 나간 날 = 획득 행동을 한 날")
- 꾸미기·잡담 — 근거 §7 V2 (활동일의 4.3%, 재방문율도 낮음)

## 3. 계산 구조

```
session_logs ─▶ 공통 필터 ─▶ 주민 키 통합 ─▶ (주민×날) 가꾼 여부 ─▶ 7일 평균 ─▶ 공식 값
                                                                         └▶ 원본 값 (필터 없이)
GA4 events  ─▶ 같은 정의 ───────────────────────────────────────────▶ 그림자 값 (대조용)
```

- **공식 원천 = `calm_forest_raw.session_logs`** (session_id 별 최신 행의 `counts` JSON). 혼합 키에 필요한 `user_id`·`client_id`·`is_guest` 가 한 행에 다 있는 유일한 원천
- **그림자 = GA4 `events_*`**. 같은 정의를 이벤트 단위로 계산해 계측 이상을 감지
- SQL 위치: `sql/analytics/metrics/` — 공통 필터 1 · 북극성 1 · 대조 1 (담당 Codex)
- 출력 열: `period, platform, variant(official|raw), value, numerator, denominator`

## 4. 운영 규칙

| 규칙 | 내용 |
|---|---|
| **재계산** | 키 통합 때문에 과거 값이 바뀔 수 있다 → 매번 전체 재계산, 보고에 계산일 표기 |
| **그림자 경보** | 로그인 계정 기준 SL↔GA4 가꾼 (주민×날) 일치율이 **95% 미만 2주 연속**이면 계측 점검 (기준선 98.4%) |
| **목록 추가** | 새 획득 행동은 추가일을 변경 기록에 남기고 차트에 세로선. 과거 재계산 없음 (과거엔 없던 행동) |
| **목록 삭제** | 과거까지 재계산 |
| **읽기** | 주간 등락은 해석하지 않는다. **의미 있는 변화 = 최근 4주 평균이 직전 4주 값의 95% CI 밖**. 차트엔 항상 CI 띠 |

## 5. 지표 트리

### 분해식 (항등식)

```
북극성 × 7  =  주간 방문 주민 수  ×  1인당 방문일  ×  방문일 중 가꾼 비율
                   (폭)              (빈도)             (품질)
```

북극성이 움직이면 세 요인 중 어디서 움직였는지 정확히 나뉜다.

| 단계 | 지표 | 정의 | 목표 |
|---|---|---|---|
| **NSM** | 하루 평균 가꾼 주민 수 | §2 | 습관 |
| **L1 폭** | 주간 방문 주민 수 | 그 주 세션이 1개 이상인 주민 | |
| └ L2 | 신규 | 그 주가 첫 방문 | 활성화 |
| └ L2 | 유지 | 지난주에도 방문 | 습관 |
| └ L2 | 복귀 | 그 주 방문자 중 신규도 유지도 아닌 나머지 (§5-0 정의 1) | 습관 |
| **L1 빈도** | 1인당 방문일 | 방문일 합 ÷ 방문 주민 | 습관 |
| └ L2 | 습관 주민 비율 | 주 4일 이상 방문한 주민 ÷ 방문 주민 | 습관 |
| **L1 품질** | 방문일 중 가꾼 비율 | 가꾼 (주민×날) ÷ 방문 (주민×날) | 습관 |
| └ L2 | 분야별 획득 비중 | 농사·낚시채집·만들기·마을 | |
| └ L2 | 빈손 방문의 마지막 위치 | 획득 행동이 0 인 날의 `last_place` 분포 | |
| **활성화** | 7일 내 첫 획득 행동 비율 | 신규 중 첫 7일 안에 가꾼 날 ≥ 1 | 활성화 |
| └ L2 | 첫 획득 행동까지 시간 | 첫 세션 시작 → 첫 획득 행동 이벤트 | 활성화 |

활성화는 **신규 → 유지** 사이의 다리다. AARRR 의 Activation·Retention 은 이 트리를 그대로 쓴다 (M3).

### 견제 지표

| 지표 | 막으려는 것 |
|---|---|
| 빈손 방문 비율 (= 1 − 품질) | 출석 보상 같은 장치로 방문만 부풀리기 |
| 코인 순증가 속도 (`econ_logs` 획득 − 사용, 주민당) | 획득을 쉽게 만들려는 보상 남발 → 경제 인플레 |
| 세이브 실패율 (`save_load_failed` ÷ 로드 시도) | 지표가 오르는 동안 데이터 유실 같은 품질 사고가 묻히기 |

## 5-1. AARRR

```
방문 → 게임 진입 → 활성화 → 유지(북극성) → 수익
(추천: 메타 광고·지인 추천 이벤트 진행 때 설계)
```

| 단계 | 주 지표 | 정의 | 상태 |
|---|---|---|---|
| **Acquisition ①** 방문 | 첫 방문 수 | GA4 `first_visit` 한 사람 (플랫폼별) | ✅ |
| **Acquisition ②** 게임 진입 | 진입 전환율 | 방문 중 익명 계정(`user_id`)이 생긴 비율. 그 차이가 **입구 이탈** (현재 44%, 웹 34%·토스 89%) | ✅ GA4 기준 |
| **Activation** | 7일 내 첫 획득 행동 비율 | 신규 중 첫 7일 안에 획득 행동 1번 이상 (현재 43%) | ✅ |
| **Retention** | 2~3주 차 재방문율 + **북극성** | 8~21일차 재방문 · 하루 평균 가꾼 주민 수 | ✅ |
| **Revenue** | 주간 결제 전환율 | 그 주 결제 주민 ÷ 방문 주민. 매출·ARPPU 병기 | 🔴 결제 0 (Paddle 라이브 대기) |
| └ 선행 | 코인 소비 주민 비율 | 코인으로 무언가를 산 주민 ÷ 방문 주민 | ✅ |
| └ 퍼널 | 결제 단계 전환 | 프리미엄 노출 → 결제창 → 결제 단계 → 결제 완료 | 🟠 이벤트 있음, 데이터 0 |
| **Referral** | — | **범위 제외.** 이후 메타 광고·지인 추천 이벤트 진행 때 설계·측정 (현재 공유 링크 유입 0, 사진 공유 3명) | ⏸ |

- 유입을 두 칸으로 나눈 이유: GA4 방문자가 게임 진입자의 약 2배다. 한 칸으로 합치면 가장 큰 누수(입구 이탈)가 퍼널에서 사라진다
- 수익의 선행 지표: 현금 결제가 열리기 전에도 "사고 싶어 하는가"를 코인 소비로 본다. 결제가 열리면 코인 소비자가 첫 결제 후보군

## 5-2. L3 — 지표별 계산 근거 (로그)

SL = `calm_forest_raw.session_logs` · EC = `calm_forest_raw.econ_logs` · GA4 = `analytics_547127440.events_*`

| 지표 | 원천 | 필드·이벤트 | 상태 |
|---|---|---|---|
| 방문 | GA4 | `first_visit` · `user_pseudo_id` | ✅ |

## 6. 정한 것과 이유 (결정 기록)

| 결정 | 선택 | 이유 |
|---|---|---|
| 목표 | 습관 > 활성화 > 엄밀성 | 사용자 결정 |
| 리듬 | 매일 잠깐 | 출석·일일 의뢰·밤사이 가공 등 게임 설계가 하루 주기 |
| 가꾼 날 기준 | 획득 행동을 한 날 | 사용자 결정 — 켜기만 한 날·물만 준 날 제외 |
| 사람 키 | 혼합 (계정/기기) | 토스 = 계정이 정확, 웹 게스트 = 기기뿐 |
| 묶는 방식 | 합계형 (사람×날 ÷ 7) | 폭과 빈도를 한 숫자에. 문턱형·비율형은 L2/L1 로 |
| 모집단 | 공식 + 원본 병기 | 제외 효과를 숨기지 않음 |
| 원천 | SL 공식 + GA4 그림자 | 혼합 키는 SL 에서만 가능, GA4 로 계측 이상 감지 |
| 플랫폼 | 웹·토스 | 안드로이드·itch 는 계측 결함 |
| 유입 | 방문 + 게임 진입 두 칸 | 입구 이탈을 퍼널에서 보이게 |
| 추천 | 범위 제외 | 캠페인 전 — 메타 광고·지인 추천 이벤트 때 설계 |
| 수익 | 결제 전환 + 코인 소비 선행 | 결제 0 이어도 지불 의향을 본다 |
