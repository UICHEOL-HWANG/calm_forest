# 🎯 게임 데이터 분석가 지원 로드맵 — calm forest 로 채울 것

**작성** 2026-10-16 · **기준 공고** 게임사 데이터 분석가 (담당 업무 5 · 자격 요건 5)
**원칙** 새 기술을 쌓기보다 **이미 한 분석을 "결정 → 변경 → 측정"으로 끝까지 닫는 것**이 최우선이다.

---

## 0. 한 줄 진단

calm forest 는 공고의 **도구·방법론 요건은 이미 거의 다 갖췄다** (SQL 지표 체계, 파이프라인, A/B 사전등록, 모델 3종, 이상 탐지 DAG).
비어 있는 건 두 가지다.

1. **판정까지 간 실험이 없다.** 게이트 원장(`docs/analysis/ANALYSIS_GATES.md`)의 G2 판정 대부분이 "방향만 / 판정 불가"다. 원인은 방법이 아니라 **표본**(코호트 ~200명, 칸마다 n<30).
2. **"인사이트 → 프로덕트 변경 → 지표 변화" 로 닫힌 사례가 없다.** 공고의 "프로덕트를 고도화할 수 있는 인사이트", "KPI 문제 지점 정의 → 솔루션 제공"은 결과까지 보여줘야 증명된다.

## 2. 목표 8개 — 우선순위 순

### 🥇 G-4 · E1 첫 5분 수확 실험을 최종 판정까지 (가장 중요)

공고 5개 업무 중 업무3·4·5, 자격 요건 3을 한 번에 증명한다.

- 사전등록 기준 그대로: 주 지표 5분 안 첫 획득 31% → 50%, **무리당 100명**, 최대 12주
- **필요 조건은 유입**이다. 지금 주 신규 7~26명 → 100명×2 무리를 12주 안에 채우려면 **주 신규 ≥ 17명을 꾸준히** 유지해야 한다 → G-4a
- 끝나면 남길 것: 결과 페이지 1장 (효과·CI·가드레일·결정: 전면 적용 / 롤백 / 재실험)
- **Done:** "E1 은 X%p 올렸고 [CI], 가드레일 위반 없음, 그래서 전원 적용했다" 한 문장을 쓸 수 있다
- 효과가 없어도 실패가 아니다. "사전등록한 기준으로 효과 없음을 확인하고 접었다"도 면접에서 강한 이야기다

**G-4a 유입 확보 (G-4 의 선행 조건)** — 분석가 목표가 아니라 사업 목표지만, 표본이 없으면 모든 판정이 "방향만"에서 멈춘다.
- 토스(입구 이탈 11%) 비중 늘리기, 웹 입구(이탈 64%)는 E2 로 처리
- 채널별 신규·진입률을 주간으로 기록 → 이것 자체가 업무5 (마케팅 협업) 증거가 된다

### 🥈 G-3 · 닫힌 루프 사례 2건

"분석 → 변경 → 측정"을 끝까지 간 사례.

| 후보 | 분석 | 변경 | 측정할 것 |
|---|---|---|---|
| ① 튜토리얼 | B4: 건너뜀 21% vs 코치 시작 53% | E1 (환영 모달을 첫 수확 뒤로) | E1 결과 = G-4 와 같은 사례 |
| ② 판매가 | P1: 시세 탄력성 +4.37 | 시세 폭 조정 or 판매 알림 | 코인 순증가 가드레일 · 판매 기기 수 |
| ③ 웹 진입 | W1~W4 + C6 (계정 48% vs 게스트 11%) | E2 로그인 화면 건너뛰기 | 진입률 25% → ? |

- **Done:** 2건 각각 "전 → 후" 숫자와 해석 한계를 한 장으로

### 🥉 G-8 · 케이스 스터디 3개 (포트폴리오)

공고 요건5 ("Deep Dive 해서 현상 이해와 액션 아이템까지")를 그대로 보여주는 형식.

1. **첫 5분 진단 → E1** — 문제(59% 가 획득 없이 떠남) → 분해(입구 / 캐릭터 선택 후) → 원인 가설(튜토리얼) → 실험 → 결과
2. **북극성 지표 설계** — 왜 DAU 가 아니라 "하루 평균 획득 유저"인가, W×F×Q 분해식으로 8/17 주(품질)와 9/28 주(폭) 하락을 구분한 사례
3. **데이터 신뢰성** — 페르소나·베타·localhost 오염을 G1 에서 걸러낸 과정, 관리도 이상 탐지를 DAG 로 운영한 것

각 케이스 구조: **상황 → 질문 → 데이터 → 방법 → 결과 → 결정 → 한계** (1~2 페이지, 차트 3장 이내)

- **Done:** 면접에서 각 케이스를 3분 / 10분 두 버전으로 말할 수 있다

### G-5 · 직군별 의사결정 메모 3장

같은 분석을 상대에 맞춰 바꾸는 연습. 공고의 "마케팅·기획·사업 협업"에 대한 증거.

| 받는 사람 | 기존 분석 | 메모 한 줄 예 |
|---|---|---|
| 마케팅 | F2 릴스 발행일 | "발행일 신규 1.6배(CI 0.69~3.59) — 아직 판정 불가, 발행 4주 더 + UTM 별도 랜딩 필요" |
| 기획 | B4 튜토리얼 · E1 | "튜토리얼은 첫 수확 뒤로 — 실험 결과 X" |
| 사업 | 코인 경제 C1~C5 · 수익 선행 | "상위 3기기가 코인 순증가 52~97% — 과금 설계 전 중앙값 기준으로 보자" |

- 형식: 결론 1줄 → 근거 숫자 3개 → 요청할 결정 → 한계
- **Done:** 3장 작성, 각 1페이지

### G-1 · BI 툴 갱신

- **Tableau Public**: 기존 배포본(35일 표본)을 북극성 트리(NSM → W·F·Q → 활성화 퍼널) 구조로 갱신. 데이터는 `infra/airflow/dags/tableau_sheets.py` 경로 그대로
- **Looker Studio**: GA4→BigQuery 위에 활성화 퍼널 1장. 공고에 이름이 나온 툴을 하나 더 손에 익힌다
- Superset 은 선택. 시간이 남으면 Docker 로 로컬에 띄워 같은 지표 1장
- **Done:** 공개 링크 2개, 각 대시보드에 "이 화면으로 답하는 질문" 1줄

### G-2 · 트래킹 플랜 1장

공고 업무2 "유저 액션 기반으로 로그 설계"에 대한 직접 증거. 지금은 `GA4_GUIDE.md` §2 · `metrics.js` · `logger.js` 에 흩어져 있다.

- 표 형식: 이벤트명 · 발생 시점 · 파라미터 · 연결 지표(북극성 트리 위치) · 원천(GA4 / session_logs / econ_logs) · QA 쿼리
- 설계 원칙 3줄: 사람 키 통합 규칙, 실험 arm 부착 규칙(E1 `exp_arm` 25개 한도), 대조 경보(일치율 95%)
- **Done:** 새 기능(예: 연못) 하나를 이 표에 추가하는 과정을 예시로 남김

### G-7 · 모델을 실험의 처치로

요건4 "패턴 모델링"을 "예측이 맞았다"에서 "예측으로 행동을 바꿨다"로 올린다.

- 후보: `ml/api/retention_guidance.py` 또는 LTV 조기 예측(첫날 획득 행동 수 단일 신호 +0.47) → 하위 20% 예측 유저에게만 안내 노출 → 무작위 대조
- 주의: 지금 표본으로는 G-4 와 유입을 나눠 먹는다. **E1 판정 이후**에 시작
- **Done:** 사전등록 1장 + 배정 구현. 판정까지는 이 로드맵 밖이어도 된다

### G-6 · SQL·통계 테스트 대비 (프로젝트 밖)

calm forest 는 데이터가 작아 실무형 SQL 테스트(윈도우 함수, 리텐션 코호트, 퍼널, 세션화)를 대규모로 연습하기 어렵다.

- 같은 문제를 calm forest 스키마로 다시 푸는 연습: 코호트 리텐션 표, 퍼널 전환, 세션화(30분 규칙), 연속 출석
- 통계 질문 준비: 표본 크기 계산(E1 100명 근거), 다중 비교, 판정 불가와 효과 없음의 차이, 이중차분(H-N1) 가정
- **Done:** 문제 20개 풀이 노트, 시간 재고 풀기

## 5. 하지 않을 것

- 새 모델 종류 늘리기 (노트북 24 "모델 패밀리 비교"로 충분)
- 판정 기준을 결과 보고 바꾸기
- 게임 기능 개발에 분석 시간 쓰기 — 단, E1·E2 처럼 **실험을 위한 구현**은 예외
