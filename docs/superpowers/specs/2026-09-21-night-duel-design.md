## 한 줄

밤사이 털린 🐾 흔적을 조사하면 도둑이 그 자리에 나타나고,
**동물마다 다른 3판 승부**로 가져간 작물을 되찾는다. 이기면 그 동물은 며칠간 발길을 끊는다.

## 풀려는 문제

1. **방어가 수동적이다.** 지금 밤손님을 막는 수단은 허수아비 1개(확률 −25%p)와 울타리 4개(−20%p)뿐이고,
   둘 다 **한 번 세워두면 끝**이다. 매일 할 일이 되지 못하고, 다 세운 뒤엔 밤손님이 배경이 된다.
2. **털린 아침에 할 수 있는 게 없다.** 접속하면 이미 결판이 나 있고, 플레이어는 결과를 통보받는다.
   흔적 조사(수집품·씨앗 2)는 위로일 뿐 되돌리는 행동이 아니다.
3. **도둑을 본 적이 없다.** 🦝너구리·🐗멧돼지는 이름과 발자국 크기로만 존재한다.
   누가 털어갔는지가 아침을 바꾸지 않는다.

## 하지 않는 것 (경계)

- **싸우지 않는다.** 일기토 구도(마주 서기·기싸움)는 가져오되 때리고 맞는 연출은 넣지 않는다.
  승부는 가위바위보와 그릇 맞추기다. 힐링 톤을 깨는 순간 이 기능은 실패다.
- **패배에 벌을 주지 않는다.** 지면 이미 잃은 것이 그대로일 뿐, 추가 손실·비용·쿨다운이 없다.
  접속이 벌이 되지 않게 한다는 밤손님의 기존 원칙을 그대로 잇는다.
- **무대를 새로 짓지 않는다.** 요리·조각처럼 전용 클로즈업 무대로 전환하지 않는다.
  사건은 **털린 밭 그 자리**에서 벌어져야 인과가 끊기지 않는다.
- **밤손님을 없애지 않는다.** 발길 끊기는 동물당 최대 2밤이고 서버가 상한을 강제한다.
  계속 이겨서 밤손님이 영영 안 오는 상태는 만들지 않는다.
- **`js/game.js`에 몰지 않는다.** 15,901줄이다. 규칙은 `js/duel/` 순수 모듈로, game.js에는 확장점 훅만 둔다.

## 1. 흐름

```
아침 접속 → (기존) 서버 판정 → 작물 사라짐 + 🐾 흔적 1~3개
   ↓ 흔적 조사 (기존 조작 그대로 — 도구 불필요·모바일 액션 버튼)
흔적 보상 즉시 지급(수집품 도감 + 씨앗 2) · 흔적 소모 · 즉시 저장
   ↓ 그 자리에서 덤불이 흔들리고 도둑이 나타난다
카메라 클로즈업 · 동물별 3판 승부 · 선택은 DOM 오버레이
   ↓
승 → 그 동물이 가져간 작물 전부 되찾기 + 2밤 발길 끊기
패 → 잃은 건 그대로, 벌 없음 ("다음엔 안 봐준다"며 덤불로)
```

**대결은 흔적 자리에서 벌어진다.** 숲 어귀로 이동시키거나 전용 무대로 전환하지 않는다.
카메라만 플레이어와 동물을 옆에서 잡는 클로즈업으로 밀고, 끝나면 원래 시점으로 돌아온다.
[js/game.js:9280](../../../js/game.js) `applyStationCamera()` 가 쓰는 문법과 같다 — 마을에 선 대상을 그대로 비추고,
카메라와 대상 사이를 가리는 오브젝트는 잠깐 숨긴다(`hideKilnOccluders` 와 같은 처리가 필요하다).

**하루 한 번, 동물당 한 번.** 흔적이 3개 나와도 대결은 그 동물의 **첫 조사**에서 한 번이다.
이기면 그 동물이 가져간 작물을 **전부** 되찾는다. 남은 흔적은 지금처럼 조사 보상(수집품·씨앗)만 준다 —
회수는 작물이고 흔적 조사는 수집품이라 보상이 겹치지 않는다.

너구리와 멧돼지가 같은 밤에 둘 다 올 수는 없다(서버가 `rollAnimal` 로 하나만 고른다).
동물당 한 번이라는 규칙은 미래에 동물이 늘어날 때를 위한 것이고, 오늘은 곧 **하루 한 번**과 같다.

### 리롤 방지

대결에 들어가는 순간 **흔적을 지우고, 조사 보상을 먼저 주고, 저장한다.**

- 새로고침해도 흔적이 없어 다시 못 한다.
- 중간에 창을 닫아도 조사 보상은 이미 받았으므로 손해가 없다.
- 그래서 **가위바위보 상대 수와 그릇 위치는 클라이언트 난수여도 안전하다.**
  서버 왕복이 없어 토스·itch·오프라인에서 똑같이 돈다.

밤손님 판정이 서버 HMAC 결정값인 이유(새로고침 리롤 방지)와 결론은 같고 수단만 다르다.
저쪽은 결과를 고정해서 막고, 이쪽은 기회를 소모해서 막는다.

## 2. 두 게임

축을 갈라둔다. [js/craft/minigame.js](../../../js/craft/minigame.js) 가 "밀가루는 고르기, 포도는 박자 —
같은 손놀림이 되지 않게 축을 달리했다"고 적어둔 규칙을 따른다.

### 🐗 멧돼지 · 기싸움 — 가위바위보 3판 2선승

| 항목 | 값 |
|---|---|
| 승리 조건 | 먼저 2승 |
| 비김 | 그 판은 무효, 다시 낸다(판수에 안 든다) |
| 상대 수 | 균등 난수 — 버릇·힌트 없음 |
| 기대 승률 | **50%** |
| 조작 | ✊ ✌️ 🖐️ 버튼 한 번 |

순수 운이다. 관찰로 이길 여지를 주면 아래 그릇 섞기와 축이 겹친다.
멧돼지는 **배짱**이고, 연출(마주 서기 → 노려보기 → 동시에 냄)이 무게를 맡는다.

### 🦝 너구리 · 그릇 섞기 — 3판 전승

| 항목 | 값 |
|---|---|
| 승리 조건 | 3판 **전부** 맞히기 |
| 바가지 | 3개 |
| 섞기 횟수 | 1판 4회 · 2판 6회 · 3판 8회 |
| 섞기 속도 | 1판 0.45초/회 · 2판 0.38초 · 3판 0.32초 |
| 조작 | 바가지 탭 한 번 |
| 기대 승률 | **60~75%** (실력 게임 — 실측 후 속도로만 조정) |

난이도는 **섞기 속도로만** 조절한다. 횟수와 속도를 같이 흔들면 어느 쪽이 어려웠는지 지표로 가를 수 없다
(`COURSE_MULT`·`fireScore` 가 이미 쓰는 규칙).

전승 조건이라 멧돼지(2선승)보다 빡빡해 보이지만, 한 판의 승률이 다르다 —
멧돼지는 판당 50%이고 너구리는 잘 보면 90%대다. 합쳐서 너구리 쪽이 조금 더 유리하며, 그 편이 성격에 맞는다.
**둘 다 실측 후 조정한다.** 위 수치는 출발점이다.

## 3. 발길 끊기

이기면 그 동물이 **2밤** 오지 않는다. 세이브에 만료일을 둔다.

```js
gameState.night.truce = { boar: '2026-09-23', raccoon: null }   // 이 날짜까지(포함) 안 온다
```

[js/night-visit.js](../../../js/night-visit.js) 어댑터가 판정 요청 body 에 `truce` 를 실어 보내고,
[functions/api/night-visit.js](../../../functions/api/night-visit.js) 가 **상한을 강제한 뒤** 그 동물을 후보에서 뺀다.

```
서버 검증: truce[animal] 이 오늘보다 크고 (오늘 + 2일) 이하일 때만 인정.
  · 두 동물 다 유효 → { visited: false, reason: 'truce' }
  · 한쪽만 유효  → 남은 동물로 고정(rollAnimal 무시)
```

**왜 서버가 상한을 재는가** — 서버는 상태를 저장하지 않으므로 클라이언트가 보낸 날짜를 믿을 수밖에 없다.
그래도 상한을 서버에 두면 "세이브를 고쳐 1년짜리 휴전을 만드는" 경로는 막힌다.
매일 갱신해서 영구 방어를 만드는 조작은 여전히 가능하지만, 싱글플레이 힐링 게임이고
그 조작으로 얻는 것이 "아무 일도 안 일어나는 밤"이라 이득이 없다. 이 판단을 여기 남겨둔다.

**허수아비·울타리와 겹치지 않는다.** 저쪽은 세워두고 잊는 수동적 확률 깎기,
이쪽은 아침마다 벌어내는 능동적 방어다. 둘을 곱해 쓰는 것이 자연스럽다 —
허수아비로 습격을 줄이고, 그래도 털린 날엔 되찾아 온다.

## 4. 데이터 · 마이그레이션

### 흔적에 작물 종류를 보존한다 (필수)

지금 흔적은 `{ x, z, animal, loot }` 뿐이라 **무엇을 훔쳤는지 잊는다.**
도난 시 `clearCrop()` 으로 `cropType` 이 지워지므로, 회수하려면 흔적에 실어둬야 한다.

```js
// js/game.js resolveNightVisit() — 흔적 생성 지점
const t = { x, z, animal: v.animal, loot: v.loot, crop: c.p.cropType?.id || '' };
```

**옛 세이브 폴백**: `crop` 이 없는 흔적은 일반 작물로 본다(`inventory.crop += 1`).
밤손님 흔적은 하루 안에 정리되는 단기 데이터라 마이그레이션 코드 없이 자연 소멸한다.

### 회수 지급 규칙

[js/game.js:14061](../../../js/game.js) `tryHarvest()` 와 **같은 규칙**을 쓴다. 되찾은 것은 수확물이지 밭 복원이 아니다.

| 작물 | 지급 |
|---|---|
| 일반 | `inventory.crop += 1` (씨앗은 주지 않는다 — 수확이 아니라 회수다) |
| 고급 (wheat·corn·grape) | `inventory[id] += 1` |

**밭은 되살리지 않는다.** 성장 단계까지 복원하면 도난이 없던 일이 되고,
빈 밭을 다시 갈고 심는 다음 행동이 사라진다.

### 새 세이브 필드

```js
gameState.night = {
  lastDate, traces,                              // 기존
  truce: { boar: null, raccoon: null },          // 🆕 발길 끊기 만료일
  duelDate: null, duelDone: [],                  // 🆕 오늘 대결한 동물 (날짜가 바뀌면 비움)
}
```

전부 없으면 기본값으로 채우는 기존 복원 문법(`{ lastDate: null, traces: [], ...saved.night }`)이 그대로 흡수한다.

### 동물 조형

**시안 3개를 렌더해 나란히 비교받은 뒤 확정한다** (PC·모바일 같이).
지난 텃밭 방문객 작업에서 9차까지 갔던 전철을 피한다. 그때 얻은 규칙을 그대로 적용한다 —
부속을 꽂지 말고 형태로 승격시키고, 통과한 수치를 재사용하고, 촘촘한 반복을 피한다.
사용자가 준 멧돼지 레퍼런스(저폴리·어두운 갈색·굵은 목덜미·낮은 머리)를 비교 기준으로 쓴다.

## 7. 트래킹

기능과 **같은 디테일로** 심는다. 지난 퀘스트 작업에서 `quest_id` 를 빼먹어 다음 날 분석이 막혔다.

| 이벤트 | 파라미터 | 보려는 것 |
|---|---|---|
| `duel_start` | `animal`, `game`(rps·shells), `crops`(걸린 작물 수) | 흔적 조사 → 대결 진입률 |
| `duel_result` | `animal`, `game`, `win`(0·1), `rounds`(치른 판수), `recovered`(회수 개수) | **실제 승률** — 설계 50% / 60~75% 와 대조 |
| `duel_quit` | `animal`, `game`, `round`(중단 시점) | 중간 이탈(창 닫기·뒤로) |
| `night_visit` | 기존 + `truce`(0·1) | 발길 끊기가 습격을 얼마나 줄였나 |

축은 전부 키값(`boar`/`raccoon`, `rps`/`shells`)으로 보낸다 — 표시 이름을 보내면 i18n 에 따라 갈라진다.
`duel_result.win` 은 **다음 날 BigQuery 에서 재검증**한다.

## 8. i18n · 모바일

- **문구는 선검수.** 버튼·안내의 한국어 후보를 먼저 확정한 뒤 만든다. 특히 ✊✌️🖐️ 세 버튼과
  승·패 안내 문장. 확정 후 `js/i18n-en.js` 에 ko/en 동시 등록한다.
- **통문장을 키로.** `" · "` 글루나 `{0}` 조합 프롬프트는 영어에서 어순이 깨진다. 전체 문장을 정확 키로 쓴다.
- **모바일 3단 레이아웃.** 선택 버튼은 프롬프트 줄에, 안내는 컨텍스트 슬롯에 둔다.
  대결 중에는 기존 액션 버튼·상호작용 프롬프트를 정지시킨다
  ([js/game.js:11867](../../../js/game.js) 가 요리 미니게임에서 쓰는 처리와 같다).
- **클로즈업 줌**은 세로 화면에서 화각이 좁아지는 만큼 뒤로 뺀다(`applyStationCamera` 의 `k` 보정).
  **실측으로 잡는다** — 추측한 값을 쓰지 않는다.

## 9. 성공 기준

| 지표 | 목표 | 근거 |
|---|---|---|
| 흔적 조사 → 대결 진입률 | 80%+ | 조사하면 바로 이어지므로 이탈할 이유가 없다. 낮으면 진입 연출이 겁을 준 것 |
| 대결 승률 (rps) | 45~55% | 설계 50%. 벗어나면 난수·판정 버그 |
| 대결 승률 (shells) | 60~75% | 벗어나면 섞기 속도로 조정 |
| 중간 이탈률 | 10% 미만 | 높으면 대결이 길거나 지루하다 |
| 밤손님 흔적 조사율 | 기능 전 대비 상승 | 되찾을 수 있게 되면 조사할 이유가 커진다 |

## 10. 열린 질문

- **연속 승리 처리** — 2밤 휴전 중에는 다른 동물만 온다. 그 동물도 이기면 이틀간 밤손님이 완전히 없다.
  이게 너무 조용하면 휴전을 1밤으로 줄인다. 실측 후 판단.
- **첫 등장 안내** — 처음 대결할 때 규칙 설명을 `firstHint` 로 한 번 띄운다. 문구는 선검수 대상.
- **소리** — 등장(덤불), 냄/맞힘, 승·패 4종이 필요하다. 기존 `Sound` 재사용 범위는 구현 때 판단.
