# 🏠 집 실내 다층화 + 층별 고급 가구 — 설계

작성 2026-09-17 · 상태: 설계 승인 대기

## 1. 배경

집 외관은 2026-09-10 리디자인으로 4종이 됐다. 그런데 **외관만 바뀌고 실내는 그대로다.**

| 단계 | 외관 모델 주석 | 실내(현재) |
|---|---|---|
| 3 코티지 | "**단층** 크림 스투코" | 방 1개 (`INT_HALF 7`) |
| 4 브릭 로프트 | 아트리움 + 천창 | 방 1개 |
| 5 펜트하우스 | "**2층** 모던 하우스" | 방 1개 |
| 6 루프탑 빌라 | "2층 유리 매스(**내부 계단 노출**) + 윙 지붕 = **루프탑 테라스**" | 방 1개 |

밖에서는 이미 2층집이고 계단까지 조형돼 있는데 들어가면 단층이다. 800코인을 내고 5단계를 지어도
증축 보상이 "밖에서 보는 것"에서 끝난다.

동시에 후반 코인 싱크가 부족하다 — 코인을 쓰는 곳은 🧩구성품 12종(40~900🪙)뿐이고,
실내 가구 22종은 전부 작물·생선으로 산다.

## 2. 목표 / 비목표

**목표**
- 증축 단계가 실내에서도 체감되게 한다 (위층 해금).
- 꾸미기 표면적을 넓히고, 그 위에 코인 전용 고급 가구를 얹어 후반 싱크를 만든다.

**비목표 (명시적으로 하지 않는다)**
- 층에 기능·미니게임을 넣지 않는다. 층은 **꾸미기 캔버스**다. (사용자 결정)
- 계단을 걸어 올라가게 만들지 않는다. → §4.2
- 🌷화단(실외 꽃 심기)은 **이번 범위 밖**. → §9

## 3. 설계 ① — 층 지도

증축 단계가 곧 층 해금이다. 별도 해금 조건을 만들지 않는다(증축이 이미 코인·자재를 받았다).

| 단계 | 층 구성 | 위층 크기(half) | 성격 |
|---|---|---|---|
| 3 코티지 | 1층만 | — | 지금 그대로 |
| 4 브릭 로프트 | 1층 + 🪜 다락 | 4.5 | 천창 아래 작은 층 |
| 5 펜트하우스 | 1층 + 🏢 2층 | 6.0 | 정규 크기 |
| 6 루프탑 빌라 | 1층 + 2층 + ☀️ 루프탑 | 5.0 | **실외 층** — 하늘·밤별, 야외 가구 전용 |

1층은 `INT_HALF 7` 유지.

**층 인덱스는 `f` 하나로 통일한다.** `f=0` 1층 · `f=1` 위층 · `f=2` 루프탑.
`f=1`의 생김새는 단계가 정한다 — 4단계엔 다락(4.5), 5단계부터 2층(6.0)으로 **넓어진다**.
다락에 놓았던 가구는 좌표가 그대로 유효하므로(작은 영역 → 큰 영역) 그대로 승계된다.
증축하면 내 위층이 넓어지는 체감이 한 번 더 생긴다.

**루프탑을 실외로 두는 이유**: 층 3개가 전부 똑같은 네모 방이 되는 걸 피한다.
크기·조명·놓을 수 있는 가구가 층마다 달라서, 기능을 넣지 않아도 층마다 성격이 생긴다.

## 4. 층 전환

### 4.1 문법
계단 오브젝트를 두되 **걸어 올라가지 않는다.** 근접하면 프롬프트가 뜬다:

```
🪜 2층으로      (위층에서는) 🪜 1층으로 · ☀️ 루프탑으로
```

나가는 문(`🚪 나가기`, `dist2D(INT.x, INT.z-INT_HALF) < 1.7`)과 **똑같은 문법**이다.

### 4.2 왜 걸어 올라가지 않는가
박물관 계단에서 실제로 겪은 세 가지가 반경 7짜리 방에서는 더 심하게 나온다:
계단을 못 찾는다 / 확대하려는데 계단을 타고 이동된다 / 조형물이 계단에 가린다.
층 전환을 프롬프트로 하면 이동 마찰 0, 카메라 문제 0이고,
층은 한 번에 하나만 렌더하므로 드로우콜도 늘지 않는다.

## 5. 설계 ② — 층별 고급 가구

**해금은 층에 묶고, 배치는 자유.** 5단계를 지으면 2층 가구가 상점에 풀리고,
그걸 1층에 놓든 다락에 놓든 자유다. 예외는 루프탑 야외 가구(실외 전용).

**화폐는 코인 전용.** 기존 22종(`pay: 'crop'|'fish'`)은 그대로 두고, 고급은 코인으로만 산다.

가격은 구성품 상점의 기존 계단식 대역에 맞춘다 (40/60/80 → 120/150/200 → 250/300/400 → 500/700/900).

|---|---|---|---|
| 4단계 | 🪑 흔들의자 | 120 | |
| 4단계 | 🔭 망원경 | 150 | 다락 천창 아래 |
| 4단계 | 🧳 여행 트렁크 | 180 | |
| 5단계 | 🛁 욕조 | 250 | |
| 5단계 | 🖼️ 큰 그림 | 280 | |
| 5단계 | 💠 샹들리에 | 300 | 밤 점등(`houseWindows` 등록) |

**전부 살 필요가 없다는 점이 중요하다** — 구성품은 외관에 다 붙지만 가구는 방에 다 못 놓는다.
고르는 재미가 곧 싱크다.

## 6. 저장 구조

```js
house: { decor: [], stored: {}, addons: [], bedGiven: false }
//              ↑ [{id,x,z,rot}] → [{id,x,z,rot,f}]   f 없으면 0(1층)
```

`f` 필드만 추가한다. **없으면 0으로 읽는다** — 기존 세이브의 가구는 전부 1층에 그대로 남는다.

> ⚠️ 여기는 세이브 덮어쓰기 사고가 났던 자리다. 읽기 실패를 신규 세이브로 오인하지 않게,
> `f` 부재와 `house` 부재를 반드시 구분해서 다뤄야 한다.

## 8. 함정

### 8.1 가구 메시는 scene 직속이다
`decorMeshes`는 `interiorGroup`의 자식이 아니라 scene 직속이고, `setSpaceVisible`이 일괄로 켜고 끈다.
방은 월드 `(0,0,52)`에 실제로 서 있고 마을 이동 한계는 반경 42다.
**과거 이 때문에 "맵 끝에 피아노·장롱이 떠 보인다"는 제보가 실제로 났다**(2026-09-15).
층별 토글로 바꿀 때 같은 사고가 재발할 자리다 — 층이 바뀔 때 이전 층 가구를 반드시 끈다.

### 8.2 🏖️ 옥상 파라솔 세트와 공간 충돌
6단계 구성품 `rooftop_set`(900🪙, `js/house/addons.js:216`)이 이미 옥상 파라솔·라운지 체어를 **외관에** 붙인다.
루프탑을 올라갈 수 있는 층으로 만들면 같은 공간을 두 시스템이 다툰다.

**해결**: 이미 산 사람은 그 파라솔·라운지 체어가 **루프탑 층에 실제로 놓여 있게** 한다. 추가 비용 없이.
"구성품으로 샀던 게 진짜 앉을 수 있는 게 됐다"는 쪽이 맞다. 안 산 사람은 빈 테라스에서 시작한다.

### 8.3 드로우콜
층은 한 번에 하나만 렌더하므로 순증은 없다. 다만 고급 가구는 메시 수가 많으므로
가구당 재질별 병합을 지킨다(카페 32→24 패턴).

## 9. 보류 — 🌷 화단

"펜트하우스 단계부터 집 밖에 화단을 만들어 꽃을 심는다"는 안은 **다음 배포로 미룬다**(사용자 결정).

검토 결과만 남긴다:
- 🌷꽃밭(`flowerbed`, 작물 2)이 **이미 야외 장식에 있다**(`js/game.js:599`).
  꽃 4송이 색이 코드에 고정돼 있어(`js/game.js:8997`) 열 개를 놓아도 전부 똑같다.
- 살아남으려면 두 구분선을 **동시에** 지켜야 한다:
  **거두지 않는다**(밭과 구분 — 온실 기각 사유) + **종류를 고른다**(기존 꽃밭과 구분).
- 새 시스템이 아니라 **기존 꽃밭의 고급 승격**으로 만든다. 배치·옮기기·보관은 기존 야외 장식 시스템을 탄다.
- 꽃 씨앗은 상인에게 코인으로 판다(싱크 한 번 더).
- 함정: 화단당 꽃 메시 4~6개 × 마당 10개 = 60개 순증. 화단당 병합 필수.

## 10. 검증

- 단위: 층 인덱스 규칙·클램프·`f` 마이그레이션(없으면 0)을 순수 함수로 분리해 테스트.
- 시각: `?house=4|5|6` + 층 전환으로 각 층 캡처. 낮·밤 둘 다(점등 가구 확인).
- 회귀: **마을 북쪽 끝(반경 42 경계)에 서서 가구가 떠 보이지 않는지** — §8.1 재발 확인.
- 세이브: 기존 세이브(가구 있는 것)를 불러 1층에 그대로 있는지.
- 모바일 실측(프롬프트 줄 위치).
