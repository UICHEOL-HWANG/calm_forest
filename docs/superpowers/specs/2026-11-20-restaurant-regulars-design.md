# 🍽️ 식당 단골 이웃 기획

2026-11-20. 브랜치 `feat/restaurant-regulars`(fix/restaurant-stock-p1 위). 앞선 식당 기획: `2026-10-31-restaurant-quest-design.md` 3.3절("손님은 마을 이웃"), 호감도 2차: `2026-11-12-npc-affinity-design.md`.

## 1. 목적

식당 손님이 지금은 이웃 모형만 빌려 쓴다. 이름·취향·호감도와 이어지지 않아서 영업이 마을 이야기와 따로 논다. 손님을 진짜 돌아온 이웃으로 만들고, 좋아하는 메뉴를 대접하면 호감도가 오르고, 자주 대접하면 단골이 되어 편지와 메뉴판 이름표로 돌려받게 한다.

## 2. 사용자 결정 (2026-11-20)

| 항목 | 결정 |
|---|---|
| 호감도 | 별 4 이상으로 내면 좋아하는 메뉴 +2, 다른 메뉴 +1. 선물과 같은 하루 상한(이웃당 +2)을 함께 쓴다 |
| 손님 | 마을에 돌아온 이웃만. 영업 중에는 그 이웃을 마을에서 숨긴다 |
| 단골 보상 | 단골 편지(이웃당 1통) + 식당 벽 단골 메뉴판 |
| 진행 | 1단계(손님=이웃·취향·호감도·주문표 얼굴·숨김·수첩 한 줄) → 2단계(편지·메뉴판) |

## 3. 손님

- 후보: 호감도 대상 이웃 중 식당과 겹치는 역할을 뺀 8명. 농부 삼촌, 목수 아저씨, 낚시꾼 할아버지, 숲지기 오소리, 별 보는 아이, 사공 오리, 목장 아주머니, 큐레이터 할아버지. 요리사 판다(주방 주인 격), 올빼미(배달), 방랑 상인은 손님으로 오지 않는다.
- 돌아온 이웃만 온다(`js/world/unlocks.js` `isUnlocked`). 같은 이웃이 한 영업에 동시에 두 자리에 앉지 않는다.
- 비어 있는 이웃이 없으면 카페의 나그네 손님(`CAFE_GUESTS`) 중 한 명이 온다. 나그네는 호감도·단골과 상관없다. 식당이 열린 시점에 돌아온 이웃이 1~2명뿐일 수 있어서, 이 대체가 없으면 영업에 손님이 거의 오지 않는다.
- 영업 중 마을 숨김: 손님이 식당에 들어온 순간부터 나갈 때까지 그 이웃을 `setNpcHidden(o, true)`로 숨기고, 나가면 해금 상태에 맞게 되돌린다. 영업을 중간에 그만두면(나가기·안내 받기) 모두 되돌린다.

## 4. 좋아하는 메뉴

이웃마다 하나로 고정한다. 메뉴가 늘면 표만 바꾼다.

| 이웃 | 메뉴 | 이유 |
|---|---|---|
| 농부 삼촌 | 🍙 주먹밥 | 쌀 농사 |
| 목수 아저씨 | 🍙 주먹밥 | 일하다 손에 들고 먹기 |
| 별 보는 아이 | 🍙 주먹밥 | 밤에 별 보며 먹기 |
| 낚시꾼 할아버지 | 🐟 생선구이 | 낚시 |
| 사공 오리 | 🐟 생선구이 | 물가 |
| 숲지기 오소리 | 🍲 생선국 | 숲 밤이 쌀쌀함 |
| 목장 아주머니 | 🍲 생선국 | 따뜻한 국 |
| 큐레이터 할아버지 | 🍲 생선국 | 느긋한 식사 |

- 주문: 그 별 단계 메뉴에 좋아하는 메뉴가 있고 재고가 있으면 절반 확률로 좋아하는 메뉴를 시킨다. 나머지는 지금처럼 고른다.
- 생선국은 별2부터라, 별1에서는 생선국을 좋아하는 이웃도 다른 메뉴를 시킨다(+1만). 별을 올릴 이유가 하나 더 생긴다.

## 5. 호감도

- 서빙 별점이 4 이상일 때만 오른다. 좋아하는 메뉴 +2, 다른 메뉴 +1.
- 실제 증가량은 `giftGain(hints().affGift, today, npc, love)`가 정한다. 선물과 같은 상태를 쓰므로 하루 이웃당 +2를 넘지 않는다. 증가분이 0이어도 단골 횟수(6절)는 센다.
- 적용은 `gainAffinity(npc, gain, 'restaurant')`. 단계가 오르면 기존 토스트·편지·꾸미기가 그대로 나온다.
- 서빙 순간 탁자 위 별 표시 옆에 하트를 띄운다(증가분이 있을 때만). 월드 말풍선은 이모지만 쓴다.
- 첫 영업 연습판(`first`)에서는 손님이 이웃이어도 호감도·단골을 세지 않는다.

## 6. 단골

- 좋아하는 메뉴를 별 4 이상으로 다섯 번 대접하면 그 이웃이 단골이 된다. 한 번 단골이면 계속 단골이다.
- 저장: `restaurant.regulars = { [npc]: { fav: 횟수, done: bool } }` (예: `{ farmer: { fav: 3, done: false } }`). `sanitizeRestaurant`가 모르는 이웃·음수를 거른다. 옛 세이브는 빈 객체로 시작한다.
- 단골이 되는 순간: 결과 카드에 한 줄 표시(문구는 검수 후), GA4 `restaurant_regular { npc }`.

## 7. 화면

- 주문표: 지금 칸(탁자 번호·메뉴·인내 막대)에 이웃 이모지 얼굴을 더한다. 좋아하는 메뉴 주문이면 작은 하트 표시. 배치는 시안 3개를 PC·모바일로 비교해 고른다(1단계).
- 주민 수첩: 이웃 카드에 "좋아하는 메뉴 🍙"와 단골 여부 한 줄. 문구 후보 검수 후 넣는다(1단계 끝).
- 단골 메뉴판(2단계): 식당 벽에 단골 이웃 얼굴·이름이 하나씩 붙는 판. 조형 시안 3개를 실제 식당에 세워 PC·모바일로 비교한다.
- 단골 편지(2단계): 이웃 8명 × 1통. 기존 소식함 "편지" 칸으로 온다. 문구 8통을 먼저 검수한다.

## 8. 코드 구조

| 파일 | 역할 |
|---|---|
| `js/restaurant/regulars.js` (새) | 순수 규칙: 손님 후보 표·좋아하는 메뉴 표, 손님 고르기(해금·자리·나그네 대체), 메뉴 고르기, love 계산, 단골 기록 |
| `js/restaurant/session.js` | 손님에 `npc` 붙이기, 메뉴 고르기를 regulars 규칙으로 |
| `js/restaurant/runtime.js` | 서빙 이벤트에서 `env.onGuestServed` 호출, 주문표에 얼굴 |
| `js/restaurant/rules.js` | `sanitizeRestaurant`에 regulars |
| `js/spaces/restaurant.js` | 이웃 모형으로 손님 만들기, 마을 숨김·되돌림, `giftGain`·`gainAffinity` 연결 |
| `js/affinity/book-ui.js` | 수첩 한 줄 |
| 2단계 | 편지 데이터·메뉴판 조형 |

session.js 는 이웃 해금 상태를 모르게 둔다. 지금 앉을 수 있는 이웃 id 목록은 runtime 이 env 에서 받아 createSession 옵션으로 넘긴다.

## 9. 트래킹

- 기존 `restaurant_service`에 `regular_n`(그 영업에서 대접한 이웃 수)만 더한다. 파라미터 상한(이벤트당 ≤5, 코드 키 ≤23) 확인.
- 새 이벤트 `restaurant_regular { npc }` 1개.
- 호감도는 기존 `affinity_stage`의 `via: 'restaurant'`.

## 10. 테스트

- regulars.js 단위 테스트: 해금 안 된 이웃 제외, 동시 중복 없음, 나그네 대체, 좋아하는 메뉴 확률(시드 고정), love 계산(별 3 이하 0), 하루 상한 공유(선물로 2 받은 날 0), 단골 5회 판정, sanitize.
- session 테스트: 손님에 npc가 붙고, 후보가 비면 나그네.
- wiring 테스트: spaces/restaurant.js 가 `gainAffinity`·`setNpcHidden`을 부른다.
- 미리보기: 이웃 2명만 돌아온 세이브로 영업 → 나그네 섞임, 호감도 토스트, 마을 숨김·복귀 확인.

## 11. 범위 밖

새 메뉴, 별5·6, 나그네 손님 호감도, 손님별 대사.
