# 공간 연결 2차 · 연못 키우기 + 마당 식탁 · 설계

**작성** 2026-11-12 · 사용자와 대화로 결정(시안 비교 6건) · 1차 스펙 `dev/archive/fish-tank-link/pond-spec.md`
**dev docs** `dev/active/space-link-v2/` · **시안** `sims/pond-action-sim.html` · `sims/pond-grow-sim.html` · `sims/cook-table-count-sim.html` · `sims/cook-table-action-sim.html` · `sims/space-link-onboarding.html`

## 0. 왜

- 1차(10/16)로 첫 물고기를 낚으면 마당 연못이 생기지만, 보기만 하는 장식이라 밋밋하다
- 로드맵 2번(요리)은 아직 0줄이다
- 가장 큰 문제는 도달이다. 10/16~11/04 새 기기 1,338대 중 **물고기를 낚은 기기 6.4%(85대)**, **요리한 기기 1.8%(24대)**. 아무리 잘 만들어도 그 앞에 서는 사람이 거의 없다(GA4 조회, 2026-11-12)
- 그래서 이번 묶음은 세 가지를 같이 한다: ① 연못과 식탁에 "할 수 있는 것"을 붙이고 ② 키울 거리를 주고 ③ 언제 이어 줄지(온보딩)를 정한다

## 1. 공통 틀

모든 공간 연결 물체는 같은 세 층을 갖는다.

| 층 | 연못 | 식탁 |
|---|---|---|
| 전시 | 잡은 물고기가 헤엄침(1차 그대로) | 만든 레시피별 최고 등급 접시 |
| 수첩 (다음 목표) | 📒 물고기 수첩 | 📖 나의 요리책 |
| 하루 한 번 | 🍞 먹이 주기 | 🥄 오늘의 한 입 |
| 키우기 | 넓히기 3단계 · 🪷 꾸미기 · 💕 이름 붙이기 | 7종째 긴 식탁으로 바뀜 |

- 물체 가까이 가면 오른쪽 아래 행동 버튼(연못 🐟, 식탁 🍽️), 누르면 창
- 수첩 창은 한 번 만들어 두 곳에서 쓴다(칸 그리드 + 빈 칸 ❔ + 아래 힌트 줄 + 이동 버튼)
- "하루 한 번" 판정은 `kstDate()` 날짜 문자열 비교

## 2. 연못

### 2-1. 📒 물고기 수첩
- 강 7칸(`FISH_KINDS`) + 바다 4칸(`SEA_SPECIES`). 잡은 칸은 채움, 바다는 최고 무게 표시
- 빈 칸 ❔를 누르면 힌트 한 줄: 계절 한정 4종은 "❄️ 겨울에만 강에서 낚여요" + 그 계절까지 남은 날, 나머지는 장소(부두·바다터)
- 이동 버튼은 장소가 있을 때만("부두로" → 기존 목표 화살표). 계절이 안 맞으면 남은 날만 보여 주고 버튼 없음
- 수첩 아래에 "넓히기" 줄(2-3)

### 2-2. 🍞 먹이 주기
- 하루 1번. 먹이를 던지면 물고기가 수면 가까이 몰려와 물결 고리(기존 메시 위치만 바꾸는 연출, 2초)
- 그 뒤 🍀 낚시 행운 30초(`buffs.luck`, 기존 버프 표 재사용). 창에 "부두로" 버튼
- 오늘 이미 줬으면 창에 "내일 다시 줄 수 있어요"
- 광고: 하루 1번을 쓴 뒤 "🎬 광고 보고 한 번 더"(반복 자리 `pond_feed_more`, §6)

### 2-3. 넓히기 3단계
밭 넓히기(`js/farm-stage.js` FARM_STAGES)와 같은 단계 표 구조에 "수첩 n종" 조건을 더한다.

| 단계 | 이름 | 조건(초안 값, 밸런스는 구현 때 경제 표로 재확인) | 생기는 것 |
|---|---|---|---|
| 1 | 연못 | 첫 물고기(1차 그대로) | 강 7칸, 바다 대어 1마리 |
| 2 | 넓은 연못 | 수첩 4종 · 돌 20 · 목재 20 · 🪙200 | 반지름 1.5배, 바다 대어 4마리, 꾸미기 자리 2칸 |
| 3 | 큰 연못 | 수첩 8종 · 돌 60 · 목재 40 · 🪙500 | 작은 섬 + 징검다리, 종당 최대 2마리, 꾸미기 자리 4칸 |

- 지금 연못 = 1단계. 기존 유저는 잃는 것 없음
- 자리: 넓어진 반지름이 다른 시설·길·주민 동선과 겹치지 않는지 테스트로 강제(1차의 자리 테스트 확장). 3단계 반지름에서 겹치면 중심을 옮기지 않고 반지름 상한을 낮춘다
- 충돌체 반지름도 단계를 따른다
- 넓히는 순간 연출: 물가 돌이 바깥으로 밀려나며 물이 차오르는 2초, 카메라는 살짝만
- 모자란 재료 줄에 "어디서" 한 줄 + 광고 버튼(§6)

### 2-4. 🪷 꾸미기
- 2단계부터 물가 흰 고리 자리(2칸 → 3단계 4칸). 소품 4종 초안: 징검다리 · 석등 · 연꽃 · 작은 분수
- 코인으로 들인다(코인 소비처). 광고로 우회하지 않는다
- 석등 밤 발광은 블룸 임계 0.85 아래(나룻배 교훈). 소품은 재질별 병합, 드로우콜 증가 측정
- 소품 조형은 구현 전에 시안 3개 이상 비교(메모리 design-compare-before-ship)

### 2-5. 💕 이름 붙이기
- 수첩에서 잡은 물고기 칸을 누르면 이름 입력. 안내 없이 스스로 발견하게 둔다
- 이웃이 구경 올 때 연못 물고기 위에 이름표 → 남에게 보이는 글자라 **닉네임 금칙어(`js/nickname-filter.js`) + 신고·차단 체계** 범위
- 길이 상한 8자, 저장 전 금칙어 검사, 서버(이웃 showcase)에서도 같은 검사

## 3. 마당 식탁

### 3-1. 전시
- 첫 요리를 완성하면 집 앞마당에 체크 식탁보 둥근 식탁이 생긴다
- 접시 = `gameState.kitchen.best`에서 **정식 레시피만**(자유 냄비 제외), 레시피당 1개, 테두리 색 = `cookTier(best)` 등급(금·은·흰)
- 1~6종 둥근 식탁 + 의자, 7종부터 긴 식탁 + 벤치(접시 2줄). 7종째 순간 바뀌는 컷
- 상태형: 매번 `kitchen.best`에서 다시 계산. 전시용 새 저장 필드 없음

### 3-2. 📖 나의 요리책
- 11칸(`RECIPES`). 만든 칸은 등급 테두리, 빈 칸 ❔
- ❔를 누르면 필요한 재료 + "주방으로" 버튼. 재료가 화덕·발효통 가공품이면(밀가루·포도즙) 그 시설을 알려 준다
- 재료 부족 줄에 광고 버튼(§6, `cook_ingredient`)

### 3-3. 🥄 오늘의 한 입
- 하루 1번. 식탁에 올라간 요리 중 하나를 골라 먹으면 그 요리의 버프가 짧게 걸린다
- 지속 = 30초 × 등급 배율(`cookTier().mult`). 찬장 요리는 줄지 않는다(찬장 `eatDish` 와 다른 경로, 같은 버프 표)
- 광고: 하루 1번을 쓴 뒤 "🎬 광고 보고 한 입 더"(반복 자리 `table_bite_more`)

## 4. 온보딩 · 언제 이어 주나

원칙: **E6가 재는 구간(첫날 집 지붕까지)과 1장 본 흐름(지붕 → 옷 가게 코치 → 🦉 서쪽 다리)은 건드리지 않는다.** 지붕 완성 순간엔 코치 `dress` 단계와 올빼미 다리 창이 이미 줄 서 있어서, 그 사이에 끼우면 세 안내가 부딪힌다(2026-11-12 사용자 결정: 다리 다 고친 뒤).

| 순간 | 안내 | 근거 |
|---|---|---|
| 다리를 고친 뒤(1장 완료), 창·코치·다른 안내·연출이 모두 비고 마을에 5초 머문 때 | ① 마당 채우기: 🦉 "마당이 좀 허전하지?" → 호수 부두 화살표 → 첫 캐스팅 무조건 성공 → 마당에 연못 생김 → 연못 화살표 → 먹이 주기 1회 → "내일 또 먹이 줄 수 있어요" | 다리 수리는 집 완성 뒤라 반복 광고(`repeatOpen`)도 이미 열려 있다. 도달은 지붕 완성자의 일부라 지붕 직후안보다 적다 |
| 다음 날 | 전날 연못을 만들고 오늘 아직 안 들어온 사람에게만 FCM 푸시 "🐟 연못 물고기들이 기다려요"(가공 완료 푸시와 같은 규칙, KST 20:10~22:50 크론, **Android·iOS 앱만**) → 접속 시 연못 화살표 1회 → 먹이 → 수첩 처음 열기 → ❔가 다음 목표 | 웹·토스는 푸시가 없어 첫날 "내일" 문장만 남는다 |
| 수첩 4종 되는 순간 | 넓히기 카드 1회 | |
| 2단계 연못 | 꾸미기 자리 안내 1회 | |
| 3장 첫 요리 완성 | 마당에 식탁 생기는 컷 → 식탁 화살표 → 오늘의 한 입 1회 → 요리책 ❔ 안내 | 요리는 3장(부엌의 가지)에서 열린다 |

- 이미 연못이 있는 사람은 ①을 건너뛰고 "먹이 주기"만 1회 안내
- 다리를 첫날 못 고친 사람: 고치는 날 같은 안내. 이미 다리를 고친 기존 유저(E3 처치·기존 기기)도 다음 접속에 한 번 받는다
- 안내 규칙(메모리 onboarding-arrow-guidance): 한 번에 목표 하나 + n/N, 금색 CSS 화살표(이모지 금지), 건물 관통 금지(경유점), 안내 중 무관한 버튼·말풍선 숨김, 첫 시도는 반드시 성공, 단계마다 `guide_step`
- 안내 엔진은 기존 `js/guide/`(goal-guide·route·step-card) 재사용
- 검증: 화살표만 따라가는 봇으로 집 → 부두 → 연못 완주
- 지붕 전·다리 전에 넣지 않는 이유: 바닥까지 간 기기 중 같은 날 지붕까지 가는 비율이 56%뿐이라 곁길이 집 완성(재방문 38% vs 11%)과 1장 완료를 깎을 수 있다
- 안내 엔진은 식당·포구 섬이 쓰는 `createGuide` + `createGuideView`(금색). E6가 켜고 끄는 `goalGuide` 가 아니다. 진행 중엔 `goalGuide` 의 `otherGuide` 에 들어가 그쪽 화살표를 숨긴다

## 5. 실험

### E3 (공간 연결 묶음)
- 연못 행동·넓히기·꾸미기·이름, 식탁 전체, 위 온보딩 안내 = 모두 `spaceLinkOn()` 뒤
- 사전등록 `dev/active/metrics-framework/space-link-experiment-prereg.md` **개정 2**(결과 보기 전): 묶음에 보상(먹이·한 입 버프)과 안내가 들어갔으므로 판정은 "공간 연결 묶음(보상·안내 포함)" 효과. 보조 지표로 먹이 주기·한 입 사용률, 안내 단계별 통과율 추가
- 대조 무리는 지금처럼 아무것도 없음

### E6 (안내 개편)
- 주 지표(첫날 지붕 완성) 뒤에서만 동작하므로 겹치지 않는다. 가드레일(첫날 세션 길이)에는 연못 안내가 양쪽 무리에 같은 비율로 들어간다(E3 해시는 독립) → 사전등록에 교란 요인으로 한 줄 적는다

## 6. 광고 (보상형)

`docs/superpowers/specs/2026-11-09-progress-prepass-rewarded-design.md` 규칙 그대로: 보상형만, 모자란 재료 줄 옆에만, 길 찾기 문제엔 안 붙임, 지급량은 비용표에서 계산, 하루 합산 안전 상한 30회, prepass 처치 무리에만, 웹은 애드센스 승인 전 버튼 없음.

| 자리 | slot | 주는 것 | 분류 |
|---|---|---|---|
| 연못 넓히기 재료 부족 | `pond2` · `pond3` | 모자란 돌·목재, `prepassGrant`(PREPASS_CAPS 목재 10·돌 6) | 진행 자리(장소별 분석 표에 추가, 성공 = `pond_expand` stage ≥ n, 72시간) |
| 요리책 재료 부족 | `cook_ingredient` | 그 레시피 1회분 모자란 재료, CAFE_CAPS 상한 | 진행 자리(성공 = 그 레시피 `cooking_result`, 24시간) |
| 먹이 주기 하루 1번 뒤 | `pond_feed_more` | 먹이 한 번 더(버프 포함) | 반복 자리(`REPEAT_SLOTS`, 퍼널만) |
| 오늘의 한 입 하루 1번 뒤 | `table_bite_more` | 한 입 더 | 반복 자리 |

- 반복 자리는 `repeatOpen()` 뒤에만(집 완성 전엔 안 보임)
- 광고로 열지 않는 것: 계절 한정 물고기(그 계절에 오는 게 목적), 꾸미기 코인(코인 소비처 보호), 수첩 n종 조건
- 버튼 형식: "🎬 광고 보고 🪵 8개 받기" + 반짝임 테두리(prepass 결정), 문구는 검수 후 확정

## 7. 데이터

### P1 은 `hintsSeen` 안에 둔다 (2026-11-12 확인)
`applySave` 는 아는 필드만 골라 담고 저장은 통째로 덮어써서, **새 최상위 필드는 옛 클라이언트가 다음 저장 때 지운다.** `hintsSeen` 은 통째로 펼쳐 복사돼 옛 클라이언트에서도 살아남는다(값 타입 검사 없음, 서버 제약은 세이브 512KB 상한뿐). 그래서 P1 은 새 최상위 필드 없이 아래 키만 쓰고, 단독 배포가 가능하다.

| 키 | 값 | 뜻 |
|---|---|---|
| `hintsSeen.pondDay` | `'2026-11-12'` | 연못이 처음 생긴 KST 날(라이브로 생길 때만). 다음 날 푸시 판정 |
| `hintsSeen.pondFeedDay` | `'2026-11-12'` | 마지막으로 먹이 준 KST 날 |
| `hintsSeen.pondFeedAd` | `{ d: '2026-11-12', n: 1 }` | 광고 한 번 더 횟수(`dayCount`·`bumpDay`) |
| `hintsSeen.yardFill` | `true` | 마당 채우기 안내 끝 |
| `hintsSeen.pondD1` | `true` | 다음 날 첫 접속 안내(연못 → 먹이) 끝 |
| `hintsSeen.pondBook` | `true` | 수첩을 처음 열었음 |

P2 이후(넓히기 단계·소품·이름)는 아래 `spaceLink` 필드를 쓰고 5곳 동시 배포하거나, 같은 이유로 `hintsSeen` 에 둘지 P2 계획 때 정한다.

### 새 저장 필드 (P2 이후, 예시 값)
```js
gameState.spaceLink = {
  pondStage: 1,
  pondDeco: ['bridge'],
  fishNames: { maple_carp: '단풍이' },
  feedDay: '2026-11-12',
  biteDay: '2026-11-12',
  ads: { feed: { d: '2026-11-12', n: 1 }, bite: { d: '2026-11-12', n: 0 } }
}
```
- `pondStage` 1~3(없으면 1), `pondDeco` 들인 소품 id(자리 순서), `feedDay`·`biteDay` = 그날 `kstDate()`, `ads` = 반복 자리 하루 횟수(`dayCount`·`bumpDay` 재사용)
- 전시(연못 물고기·식탁 접시)는 1차처럼 `dex.fish`·`sea.best`·`kitchen.best`에서 파생, 저장 안 함
- 새 최상위 필드라 **옛 클라이언트가 세이브할 때 지우는지 확인**하고, 지운다면 5곳 동시 배포(메모리 deploy-checklist). 1회성 안내 여부는 기존 `hintsSeen` 맵 재사용
- 이웃 showcase 확장: `pond: { stage, deco[], names{} }`, `table: { dishes[{id, tier}] }`. 화이트리스트·타입 검사·이름은 서버에서 금칙어 재검사. SQL 은 풀러로 직접 실행(메모리 sql-run-direct-pooler)

## 10. 테스트

- 넓히기: 단계별 조건 충족/부족 · 수첩 n종 계산 · 최고 단계에서 maxed · 반지름이 주변 시설과 겹치지 않음(3단계 포함)
- 먹이·한 입: 같은 날 두 번 불가 · 날짜 바뀌면 가능 · 광고 한 번 더는 하루 1번을 쓴 뒤만 · `repeatOpen` 전엔 광고 없음
- 수첩: 계절 힌트·남은 날 계산 · 모르는 id 무시 · 바다 최고 무게
- 식탁: 자유 냄비 제외 · 레시피당 1개 · 등급 테두리 · 6종 둥근 → 7종 긴 식탁 · 모르는 id 무시
- 이름: 8자 상한 · 금칙어 거부 · 빈 문자열 = 이름 지움
- 광고 지급: 비용표 기반 · 상한 적용 · 끝까지 본 것만
- 스위치: `spaceLinkOn()` off 면 버튼·안내·식탁 메시 없음
- 이웃 SQL: 잘못된 타입·모르는 id·긴 이름·금칙어 → 걸러짐
