# 계절 스탬프 카드 설계

- 날짜: 2026-11-16 (설계 승인: 화면 A안 "칸 격자 카드")
- 선행: 계절 한정 2차(`feat/season-limited-v2`, 반디·채집물·계절 끝 푸시)
- 시안: `sims/season-stamp-compare.html` A안
- 상태: 설계 승인. **경제 수치 2개는 확인 대기**(아래 "확인 대기"). 구현 계획은 writing-plans 로 따로 만든다.

## 왜

계절(14일)마다 할 일 8개를 한 장에 모아, 한정 종 찾기 말고도 이번 계절에 다시 올 이유를 만든다. 데이터(GA4 11/2~11/15, 634명)상 91% 가 하루만 오고, 2~4일 오는 50명이 다시 오게 만들 대상이다. 문턱은 이 그룹이 닿을 수 있게 낮췄다.

## 범위

- 계절마다 칸 8개짜리 카드 1장. 4칸 중간 보상, 8칸 완주 보상.
- 진입: 출석 카드의 계절 줄, 메뉴의 계절 아이콘. 새 HUD 버튼 없음.
- 게스트 포함.
- 계절이 끝나면 카드는 기념으로 남는다(보상은 그 계절 안에만 받음).

범위 밖: 지난 카드 모아 보기 화면(기록만 남기고 화면은 나중), 친구와 비교, 푸시 연동(계절 끝 푸시 문구는 그대로).

## 칸 (모두 세이브 상태로 판정)

| # | 칸 | 판정 | 데이터 근거(2~4일 유저) |
|---|---|---|---|
| 1 | 한정 물고기 | `dex.fish[id]` | 11/6~ 14명 |
| 2 | 한정 반디 | `dex.bug[id]` | 신규 |
| 3 | 한정 채집물 | `dex.forage[id]` | 신규 |
| 4 | 출석 3일 | 이번 카드의 출석 날짜 수 ≥ 3 | 출석 5일은 0% |
| 5 | 수확 20번 | 이번 카드 수확 수 ≥ 20 | 26% |
| 6 | 요리 1번 | 이번 카드 요리 수 ≥ 1 | 3번은 16% |
| 7 | 이웃 방문 1번 | 이번 카드 이웃 방문 수 ≥ 1 | 12% |
| 8 | 날씨 2종 | 이번 카드에서 본 날씨 종류 ≥ 2 | 측정 불가(비·눈만 기록됨), 봄 확률표 기준 계산 |

1~3 은 `seasonLimited()`(js/season.js) 결과를 그대로 쓴다. 이전 계절에 이미 잡은 종도 도감에 있으면 칸이 찬다(다시 잡게 하지 않는다).

## 상태 모델

세이브에 누적 수확·이웃 방문 카운터가 없어서(확인: `gameState.kitchen.cooked` 는 자유주방 전용) 카드 전용 상태를 새로 둔다.

```
gameState.stamp = {
  key: 'spring-3',            // 계절 id + seasonInfo().cycle. 바뀌면 새 카드
  days: ['2026-11-06', ...],  // 출석 날짜(중복 없음, 최대 14)
  harvest: 0, cook: 0, visit: 0,
  weather: ['clear', 'rain'],
  claimed: { mid: false, end: false },
  past: [{ key, filled, endClaimed }]  // 기념 기록, 최근 8개만
}
```

- 키가 바뀌는 첫 판정에서 지난 카드를 `past` 로 옮기고 새로 시작한다. 옛 세이브에는 `stamp` 가 없으므로 빈 카드로 시작(소급 없음).
- 증가 지점: 출석(`checkDailyBonus`), 수확(`harvest_crop` 을 보내는 곳), 요리(카페·자유주방 완료), 이웃 방문(`neighbor_visit_start`), 날씨(하루 첫 접속의 `WEATHER`).
- 순수 함수 `stampCells(stamp, limited, dex)` → `[{ id, on, progress }]` 를 새 모듈 `js/stamp-card.js` 에 두고 테스트한다. game.js 에는 연결 줄만.
- 서버 저장 구조는 기존 세이브 jsonb 그대로(새 테이블 없음). 운영 `game_saves` 의 제약은 크기 제한뿐이라 SQL 변경 없음.

## 보상

- 4칸: 코인 (확인 대기, 제안 🪙 30). 출석 보상 5~30, 배지 20~100 사이.
- 8칸: 그 계절 한정 꾸미기 1종. 계절별 4종을 새로 만든다(조형 시안 게이트 별도).
- 보상은 "받기" 버튼으로 직접 받는다. 지급은 기존 `giveReward(..., 'stamp', key)` 원장 경로.

## 화면 (A안)

- 출석 카드와 같은 크림 카드. 머리 `🌸 봄 스탬프 3/8 · 12일 남음`, 진행 막대(4칸·8칸 표시), 4×2 격자, 보상 두 칸, 확인 버튼.
- 채운 칸은 기울어진 분홍 도장 테두리, 빈 칸은 회색 아이콘.
- 문구 후보는 구현 전 다시 검수받는다(엠대시·"놀다"·화살표 이모지 금지). 영어 패턴은 `js/i18n-en.js`.

## 트래킹

새 GA4 이벤트 2개(코드 키 23개 상한 안): `stamp_cell` { season, cell }, `stamp_claim` { season, tier: mid|end, filled }. 칸 id 는 위 표의 영문 id(`fish`, `bug`, `forage`, `att`, `harvest`, `cook`, `visit`, `weather`)로 GA4·원장·세이브에서 같게 쓴다.

## 출시 주의

- 새 꾸미기 id 가 생기므로 5곳(웹·토스·Play·iOS·itch) 동시 배포.
- 계절 한정 2차가 먼저 나가야 한다(1~3칸이 새 종에 의존).

## 확인 대기

1. 4칸 보상 🪙 30 으로 확정할지.
2. 8칸 보상으로 계절 한정 꾸미기 4종을 새로 만들지(만든다면 조형 시안 3안씩 게이트).
