## 0. 확정된 선택 (브레인스토밍에서 합의)

| 질문 | 결정 |
|---|---|
| 과수원을 어디에 두나 | **마을 밖 독립 공간** — 텃밭 안 구획이 아니라 별도 인스턴스 |
| 나무를 어떻게 얻나 | **상점에서 묘목 구매** — 야생 나무 접붙이기·씨앗 드롭이 아님 |
| 다 자란 나무의 성격 | **물을 줘야 열리는 나무** — 방치해도 죽지 않고, 그날 열매만 안 열림 |
| 과수원 내부 배치 | **자연형 숲 과수원** — 굽은 오솔길과 가로지르는 시냇물, 나무 자리는 흩어져 있음 |
| 물주기 부담 해소 | **A + C 조합** — 시냇가 반경은 물 면제(기본) + 광역 물조리개 도구 업그레이드(후반) |
| 과일 종류 | **5종** — 🍎사과 · 🍐배 · 🍑복숭아 · 🍊감 · 🌰밤 |
| 진입 방식 | **해금** — 기존 잠금 UI 재사용, 조건은 고급 작물 1회 수확 |

### 왜 독립 공간인가

텃밭 안 구획이 렌더·이동·미니맵 비용이 없어 싸지만, "굳이 마을 밖으로 나온 보람"이 안 생긴다.
유저가 원한 건 과수원이라는 **장소**다. 비용(공간 하나당 렌더·이동·미니맵·안내)을 치르고 독립 공간으로 간다.

### 왜 자유 배치인데 물주기가 안 무너지나

자유 배치는 그 자체로는 최악의 동선이다. 나무 10그루가 흩어지면 매일 왕복이 고역이 된다.
**시냇물을 급수원으로 만들어** 이 단점을 선택지로 바꾼다 — 시냇가는 자리가 한정돼 있으므로
"편한 자리 몇 그루 vs 손 가는 자리 여러 그루"라는 고민이 생기고, 동선은 플레이어가 스스로 푼다.

## 1. 위치

### 마을 안 입구 — 정동쪽 `(22, 0, 2)`

기존 입구가 여덟 방향 중 일곱을 이미 쓰고 있다. **정동쪽만 비어 있다.**

| 방향 | 차지한 것 | 좌표 |
|---|---|---|
| 북 | 🛶 나루터 | (0, -15) |
| 북서 | 🌫️ 안개 숲 | (-17, -17) |
| 북동 | 🌊 바다터 | (14.5, -12.5) |
| 서 | ⛏️ 채굴 동굴 | (-14, 3) |
| 서쪽 끝 | 🏛️ 박물관 | (-26, 5) |
| 남 | 🌱 텃밭 | (0, 7) |
| 남동 | ☕ 카페 · 🌟 계곡 | (4, 14) · (7, 26) |
| 남서 | 🍄 채집 숲 | (-18, 23) |
| **동** | **🍎 과수원 언덕길** | **(22, 2)** |

- 가장 가까운 이웃인 🌊바다 입구와 거리 약 15 — 프롬프트가 겹치지 않는다.
- 마을 중심에서 눈에 들어오는 거리라 발견성이 좋다. 박물관(-26)처럼 끝에 처박히지 않는다.
- 동쪽이라 아침 해가 뜨는 방향 — 첫 방문 그림이 좋다.

> **Task 6 정적 분석 결과(2026-09-17).** 브라우저를 켤 수 없어 `isBlocked(22, 2)` 실측은 아직 못 했다.
> 대신 `obstacles` 배열(고정 구조물·게이트류·NPC 위치)을 코드로 전수 조사했더니 고정 배치물과는
> 겹치지 않는다 — 가장 가까운 건 호수(`LAKE`, 16, 9)로 거리 약 9.2, `LAKE_R`(6)보다 충분히 멀다.
> 진짜 위험은 `buildWorld()`가 매 접속마다 `Math.random()`으로 다시 뿌리는 배경 나무 14그루였다
> (반경 8~30 밴드, 시드 없음 — 세션마다 배치가 달라진다). 이 나무들이 다른 게이트 7곳은 모두
> `dist2D(...) < N` 회피 조건으로 피해 가는데 `(22, 2)`만 그 목록에 없어서, 대략 8%(거친 추정)의
> 세션에서 나무가 입구를 막을 수 있었다. 다른 게이트와 같은 패턴으로 나무 배치 회피 목록에
> `dist2D({x,z}, ORCHARD_GATE) < 4.5` 조건을 추가해 이 위험을 없앴다(`js/game.js`, `buildWorld()`).
> **다만 이걸로 "확인됨"이라 말할 수는 없다** — 실제 브라우저에서 `isBlocked(22, 2)`를 호출해
> 최종적으로 자리가 비어 있는지 보는 건 아직 아무도 하지 않았다. 다음에 브라우저를 켤 수 있는
> 사람이 그 한 번의 확인을 마저 해 주길 바란다.

### 과수원 인스턴스 — `(0, 0, 160)`

이 저장소는 공간마다 월드 좌표를 멀리 떼어 인스턴스로 쓴다.

| 공간 | 좌표 |
|---|---|
| 🏠 실내 | (0, 52) |
| 🌱 텃밭 | (0, 84) |
| **🍎 과수원** | **(0, 160)** |
| ⛏️ 광산 | (0, 250) |
| ☕ 카페 | (0, 320) |
| 🏛️ 박물관 | (0, 360) |
| 🌫️ 안개 숲 | (0, −250) |
| 🛶 강 | (0, −400), 코스 620 |
| 🌊 바다 | (400, 0) |

텃밭(84)에서 76, 광산(250)에서 90 떨어진다. 과수원 반경을 20으로 잡아도 겹치지 않는다.
공간 플래그는 `atOrchard` 를 추가하고 `outdoorZone()` · `spaceFlags()` · `shadowActiveFor()` 에 함께 등록한다.

## 2. 해금

### 조건 — 고급 작물 아무거나 1회 수확

🌾밀 · 🌽옥수수 · 🍇포도 중 하나를 거두면 열린다.

채택률 0%인 고급 작물이 처음으로 존재 이유를 갖는다. 고급 씨앗을 살 동기가 생기고,
과수원은 공짜가 아니라 번 것이 된다. 밭 단계·코인 누적·출석 일수 같은 대안은 전부 고급 작물과
무관해서 그 콘텐츠를 죽은 채로 둔다.

### 잠금 UI는 기존 것을 그대로 쓴다

베타 맵 게이트(`river`/`sea`/`mist`)용으로 만든 한 벌이 이미 있다.

- 잠긴 입구 프롬프트 · 토스트 (`js/game.js` 의 `blockIfLocked`)
- 전체 지도에서 흐리게 (`villagePlaces()` 의 `locked`)
- 열린 날 첫 접속 배너 (`announceMapOpens`)
- `map_locked` GA4 이벤트

### 규칙을 일반화한다

현재 `isMapLocked` 는 **베타 전용**이다.

```js
// js/tuning.js — 지금
export function isMapLocked({ variant, mapOrder, createdAtIso, nowMs }, map) {
  if (!/^beta_/.test(variant || '')) return false;   // ← 일반 유저에겐 아무것도 안 잠긴다
  ...
}
```

여기에 **진행도 게이트**를 더해 "베타 날짜 게이트 **또는** 진행도 게이트"로 만든다.
닭장이 쓰는 방식(🔥2일 연속 출석, `COOP_STREAK`)도 같이 흡수해 해금 규칙이 한 군데로 모이게 한다.

```js
// 진행도 게이트 표 — 순수 데이터, 판정은 순수 함수
export const PROGRESS_GATE = {
  orchard: { kind: 'advHarvest', n: 1 },   // 고급 작물 1회 수확
};
export function isProgressLocked(gate, progress) { ... }
```

세이브에 `progress.advHarvest` 카운터를 둔다. 세이브 기반이므로 **유저별로 열리는 시점이 자연히 다르다.**

### 해금 직후 묘목 2그루 지급

처음 올라갔을 때 빈 언덕을 보고 나가는 걸 막는 안전장치다. 🍎사과 묘목 2그루를 준다.

## 3. 과수원 내부

### 구성

- 굽은 오솔길 몇 갈래
- 가로지르는 시냇물 (급수원이자 조형)
- **나무 자리 10개** — 흩어진 흙 자리. 상한은 10으로 고정한다(§5 인플레 방어)
- 시냇가 자리는 그중 **4개** — 나머지 6개는 시냇물에서 멀다

### 심는 법 — 새 도구를 만들지 않는다

🌰씨앗 도구 순환에 묘목 5종이 합류하고, **과수원 안에서만** 후보에 뜬다.
고급 작물의 `nextSeedSel()` · `SEED_ORDER` 와 같은 문법이고, 도구 슬롯이 늘지 않으며
유저가 이미 아는 동작이다.

## 4. 나무의 일생

| 상태 | 내용 |
|---|---|
| 🌱 묘목 | 심은 직후. 작은 줄기만 |
| 🌿 자라는 중 | 종류별 3~5일 (날짜 경계 기준) |
| 🍎 열매 참 | 조건이 맞으면 매일 아침 열매가 달림 |
| 🌳 빈 가지 | 딴 직후. 다음 날 다시 열림 |

**나무는 죽지 않는다.** 물을 안 주면 그날 열매가 안 열릴 뿐이다.
"애써 키운 게 죽는다"는 마음 편한 게임 톤과 충돌한다.

### 물

나무마다 `watered` 플래그가 있다. **일일 정산이 도는 순간 `watered` 가 켜져 있으면** 그날 열매가 달리고,
플래그는 정산 직후 꺼진다. 즉 "오늘 준 물이 다음 정산의 열매를 만든다" — 물을 주고 바로 열리지 않는다.

- **시냇물 반경 5 안** — 자동 충족(정산 때 항상 켜진 것으로 친다). 기준점은 **시냇물 중심선에서 가장 가까운 점까지의 거리**이지 시냇물 시작점이 아니다. 💧우물이 반경 안 밭을 촉촉하게 하는 규칙과 같은 문법(`inRadiusOf`)
- **반경 밖** — 물조리개로 직접 줘야 `watered` 가 켜진다. 하루에 여러 번 줘도 효과는 같다(중복 없음)
- **후반 완화 (1차 배포 범위 밖)** — 작업대에서 🚿넓은 물조리개 업그레이드. 한 번 뿌리면 반경 안 나무가 전부 젖는다.
  "잘 드는 낫이 옆 칸까지 거둔다"(`sickle`)와 같은 결이다.
  나무가 6그루를 넘는 유저가 실제로 생긴 뒤(`trees` 파라미터로 확인) 별도 계획으로 붙인다.
  그때까지 `tree_water` 의 `method` 는 `manual` 과 `stream` 두 값만 나온다.

### 수확

나무 앞 액션으로 과일 **2개**. 자동 수집은 없다 — 직접 와서 따야 한다.
이 "따러 가는 행위"가 벌통(자동 지급)과 과수원을 가르는 지점이고, 다시 올 이유 그 자체다.

안 따면 **3일치(6개)** 까지 쌓이고 멈춘다. 무한히 쌓이면 일주일에 한 번만 와도 되고,
그러면 매일 올 이유가 사라진다.

### 🪓 베기 — 나무를 없애고 자리를 되찾는다

**왜 필요한가.** 자리가 10개로 고정이고 나무가 영구인데 없앨 길이 없으면, 제일 싼 🍎사과로 열 자리를
채운 유저는 🌰밤으로 갈아탈 방법이 영원히 없다. 묘목에 등급을 나눠 놓고 갈아탈 길을 안 주면
등급을 나눈 의미가 없어진다. 성장 경로가 통째로 막힌다.

**기존 벌목 문법을 그대로 쓴다.** 🪓도끼로 친다 — 숲 나무와 같은 `hp` 방식이라 도끼 3번,
강철 도끼 2번이다. **여러 번 쳐야 쓰러진다는 것 자체가 실수 방지**라 따로 확인 창을 띄우지 않는다.
🪏삽은 밭 전용이라 쓰지 않고, 새 도구도 만들지 않는다.

| 규칙 | 값 |
|---|---|
| 도구 | 🪓도끼 (강철 도끼면 한 번 덜 친다) |
| 열매가 달린 나무 | **못 벤다** — 먼저 수확해야 한다(🪏삽이 "작물 있는 밭은 안 된다"와 같은 규칙) |
| 목재 보상 | 묘목 **1** · 자라는 중 **2** · 다 자란 나무 **3** |
| 묘목값 환불 | **없다** |
| 벤 자리 | 즉시 빈 자리가 되어 바로 다시 심을 수 있다 |

**목재 인플레는 구조적으로 불가능하다.** 숲 나무는 30초마다(`TREE_RESPAWN_SEC`) 목재 3개를
공짜로 준다. 과수원 나무는 최소 90🪙를 치러야 최대 3개다 — 목재 1개당 30🪙 대 0🪙다.
과수원에서 목재를 캐는 건 어떤 계산으로도 손해다.

단계 비례 보상은 그 위에 얹는 두 번째 자물쇠다. 심자마자 베면 1개뿐이라 묘목을 사고 베는
짓이 더욱 무의미해지고, 동시에 "다 키운 나무를 밀어낼 땐 그만큼 돌려받는다"는 감각도 생긴다.

### 일일 정산

🐝벌통·🐛해충과 **같은 날짜 게이트**(`farm.pestDate` 패턴)를 쓴다. 접속 시 하루가 지났으면 한 번 돈다.
성장 진행 · 물 상태 판정 · 열매 부착 · 상한 체크가 이 한 곳에서 일어난다.

## 5. 경제 — 코인 소스가 아니라 싱크다

### 제약

`UPGRADES` 주석에 이렇게 적혀 있다 — *"보상량을 늘리면 코인 인플레가 생기는데, 지금은 코인이 남는 게 문제다."*
과수원을 돈 버는 곳으로 만들면 안 된다.

### 표

| 과일 | id | 묘목값 | 자라는 기간 | 하루 열매 | 그냥 팔면 |
|---|---|---|---|---|---|
| 🍎 사과 | `apple` | 90🪙 | 3일 | 2개 | 5🪙 |
| 🍐 배 | `pear` | 130🪙 | 3일 | 2개 | 6🪙 |
| 🍑 복숭아 | `peach` | 180🪙 | 4일 | 2개 | 8🪙 |
| 🍊 감 | `persimmon` | 240🪙 | 4일 | 2개 | 10🪙 |
| 🌰 밤 | `chestnut` | 300🪙 | 5일 | 2개 | 12🪙 |

판매가는 `SELL_PRICE` 에 합류하고 기존 시세 변동(일 0.7~1.3배)을 그대로 받는다.

### 팔면 푼돈, 요리하면 큰돈

그냥 팔면 기본 작물(5🪙)보다 겨우 나은 수준이라 **회수에 12~18일** 걸린다.
반면 카페 요리는 28~78🪙를 받는다(`CAFE_PAY`). 과일 2~3개로 만든 디저트를 내면 **2~3배**가 된다.

부수 효과가 크다 — 🍳자유주방·☕카페는 지금 재료가 부족해 안 돌아가는데, 매일 열리는 과일이 그 파이프에 흘러든다.

### 인플레 방어

- **나무 자리 10개 상한.** 10그루를 종류별로 고루 채웠을 때 하루 판매 수입은 대략 **160~180🪙** 다(2개 × 5~12🪙 × 10그루). 이 수치가 낚시·채집 하루 수입과 어느 선인지는 **배포 전에 `econ_logs` 로 실측해 맞춘다** — 지금은 근거 없는 추정이다
- **코인 싱크 합계** — 10그루를 다 채우면 묘목값만 1,000~3,000🪙. 밭 3단계 증축(450🪙)을 넘는 게임 내 최대 단일 싱크가 된다

## 6. 트래킹

[[feature-tracking-checklist]] 7항을 전부 적용한다. `quest_id` 누락 사고(2026-09-13)의 재발 방지다.

### 6-1. 식별자 통일

과일 5종의 id를 한 문자열로 못 박는다: `apple` · `pear` · `peach` · `persimmon` · `chestnut`

- 묘목 인벤 키 `sap_<id>` · 과일 인벤 키 `<id>`
- **GA4 파라미터 · `econ_logs.item` · 도감 키 · 세이브 필드가 전부 이 문자열**
- 표시용 한글("사과")은 절대 보내지 않는다 — i18n·리네임으로 깨진다
- `seedKeyOf()` 처럼 `fruitKeyOf()` 헬퍼 한 곳에서만 만든다

> ⚠️ **자리 번호(`slot:3`)로 종류를 대신하지 않는다.** `courier:3` 9건이 복원 불가로 남은 그 실수다.

### 6-2. 생애주기 전 구간에 같은 id

| 이벤트 | 파라미터 |
|---|---|
| `orchard_unlock` | `via` (해금 트리거가 된 고급 작물 종류) |
| `orchard_enter` | `trees` (보유 나무 수) |
| `sapling_buy` | `kind`, `coin`, `trees` |
| `sapling_plant` | `kind`, `near_stream`(0/1), `trees` |
| `tree_mature` | `kind`, `grew_days` |
| `tree_water` | `kind`, `method`(`manual`\|`stream`\|`sprinkler`) |
| `fruit_ready` | `kind`, `n`, `watered`(0/1) |
| `fruit_harvest` | `kind`, `n`, `stacked_days` |
| `fruit_capped` | `kind` — 3일치 상한에 걸려 멈춤 |
| `tree_chop` | `kind`, `stage`, `wood`, `trees`(벤 뒤 남은 그루 수) |

`tree_chop` 의 `stage` 가 중요하다 — 다 자란 나무를 미는 건 "갈아타기"이고 묘목을 미는 건
"잘못 심었다"는 뜻이라 두 행동의 의미가 정반대다. `stage` 없이는 둘을 못 나눈다.

한 칸이라도 `kind` 가 빠지면 구매 → 파종 → 수확 퍼널 join 이 끊긴다.

### 6-3. 분석 축은 키값으로

나중에 반드시 물어볼 축을 미리 파라미터로 박는다.

- `near_stream` — 시냇가 면제를 실제로 쓰는가. **§3 설계가 먹혔는지 판정하는 유일한 지표**
- `method` — 수동 / 시냇물 / 스프링클러 중 무엇으로 물을 주는가
- `watered` — 물을 안 줘서 열매를 못 받은 날이 얼마나 되는가
- `trees` — 보유 그루 수. **몇 그루째부터 이탈하는지**가 여기서 나온다

### 6-4. DB를 둔다

과수원은 리텐션이 존재 이유라 GA4만으로는 위험하다(광고차단 유실 + 일별 export라 당일 확인 불가).
**`orchard_events` 테이블을 처음부터 둔다.** `game_logs` 는 좌표 전용이니 섞지 않는다.

묘목 구매·과일 판매는 기존 `econ_logs` 를 쓰되 `item` 에 위 id를 그대로 넣는다.

> 🚨 **API를 신설하면 `worker/index.js` 에 라우트 등록을 반드시 같이 한다.**
> `dex-notes`·`daily-quests` 가 이것 때문에 404가 났다.

### 6-5. GA4 예약 파라미터 금지

`source` `medium` `campaign` `campaign_id` `term` `content` — 이 여섯은 GA4가 유입 소스로 읽어
**그 세션의 유입을 통째로 덮어쓴다.** 2026-09-14에 30일 세션의 38%가 오염된 사고다.

과수원에서 밟기 쉬운 자리가 있다 — 물 출처를 `source: 'stream'` 으로 보내고 싶어지는데 **절대 안 된다.**
그래서 §6-2 표에서 `method` 로 이름을 잡았다. `renameReservedParams` 가 막아주긴 하지만 처음부터 안 쓴다.

### 6-6. 배포 전·후 검증

- **배포 전** — `session_logs.counts` 키가 자동 집계되는지, 새 id가 `econ_logs` 에 실제로 찍히는지 조회로 확인
- **배포 다음 날** — GA4 BigQuery export는 일별이라 당일엔 검증이 안 된다. 다음 날 한 번 더 본다
- GA4 export는 되돌릴 수 없다. 파라미터 누락은 곧 **그 기간 데이터 영구 손실**이다

## 7. 구현 구조

이 저장소의 확립된 패턴을 따른다 — **순수 규칙 모듈 + `node:test` → `game.js` 는 그리기만.**

| 파일 | 역할 |
|---|---|
| `js/orchard.js` (신설) | 과일 표 · 성장/물/수확 판정 · 일일 정산 규칙. DOM·Three 의존 없음 |
| `tests/orchard.test.mjs` (신설) | 위 규칙의 수치를 못 박는다 |
| `js/tuning.js` (수정) | `PROGRESS_GATE` · `isProgressLocked` 추가, `isMapLocked` 일반화 |
| `js/game.js` (수정) | `atOrchard` 공간 · 입구 게이트 · 렌더 · 액션 배선 |

**`js/game.js` 에 규칙을 넣지 않는다.** 이미 11,475줄이고, 새 규칙은 모듈로 뺀다는 것이 이 저장소의 규칙이다.

### 나무 조형

기존 `spawnTree()` 를 재사용한다 — 줄기(`tree.trunk.geo`) + 합친 잎덩이(`tree.canopy.geo`)로 **그루당 드로우콜 2**.
과일나무는 여기에 **잎 색과 열매 인스턴스만** 얹는다. 열매는 종류별 색만 다른 인스턴스라 드로우콜이 늘지 않는다.

### 세이브

```
orchard: {
  trees: [{ x, z, kind, planted, growth, watered, fruit }],
  settleDate: 'YYYY-MM-DD',   // 일일 정산 게이트 (farm.pestDate 와 같은 패턴)
}
progress: { advHarvest: 0 }   // 해금 판정용 카운터
```

`plots` 와 같은 직렬화 규칙을 따른다 — **켜진 값만 기록**해 옛 세이브와 호환되게 한다.

## 8. 이 설계가 답하지 못하는 것

- **과일 디저트 레시피를 몇 개 추가할지** — 요리 쪽 설계가 따로 필요하다. 이 스펙은 과일이 재료로 흘러든다는 방향만 정한다
- **묘목값·판매가가 실제로 맞는 수치인지** — 배포 후 `sapling_buy` · `fruit_harvest` 로 확인해 조정한다
- **나무 자리 10개가 적당한지** — `trees` 파라미터로 몇 그루째 이탈이 생기는지 보고 정한다
- **과수원 확장 단계를 둘지** — 밭처럼 단계 증축을 붙일 수 있으나 이번 범위 밖이다
