# 주민 호감도 2차: 관계 단계 · 편지 · 전용 아이템

- 날짜: 2026-11-12
- 상태: 설계 확정(2026-11-13), 문구 확정(`dev/active/npc-affinity/npc-affinity-copy.md`), 구현 전
- 시안: `sims/npc-affinity-directions.html`(방향), `sims/npc-affinity-details.html`(세부)
- 조사 원자료: dev docs `dev/active/npc-affinity/npc-affinity-context.md`

## 1. 왜

지금 호감도는 숫자 하나(`gameState.affinity[npcId]`)이고, 오르면 생기는 일이 ❤️3마다 작은 답례와 ❤️6 도면 의뢰뿐이다.

| 관찰 (세이브 3,062개, GA4 9/4~11/11) | 값 |
|---|---|
| 집 3단계↑ 463명 중 주민 호감도 ≥1 | 59명 (13%) |
| 어떤 주민이든 ❤️6↑ | 9명 |
| 도면 보유 / 금빛 도구 제작 | 6명 / 5명 |
| 선물 받은 주민 1위 | 🦉 올빼미 35명·145번 (쌓아도 열리는 것 없음) |
| 카페 접객 425번 | 손님 8종 호감도로만 감 (쓰이는 곳 없음) |
| 대화창에서 "할 말 없음" 상태를 본 사람 | 상인 68 · 큐레이터 56 · 판다 37 |

문제는 깊이가 아니라 **다음에 무엇이 있는지 안 보이고, 쌓아도 쓸 데가 없다**는 것이다. 하트는 5개까지만 그려지고 문턱 6은 게임 안 어디에도 안 나온다.

목표: 집 완성 뒤 플레이어가 주민과 며칠에 걸쳐 친해질 이유를 만든다. 보상은 집과 마당에 남는 아이템으로 준다.

| 결정 | 선택 |
|---|---|
| 방향 | A 관계 단계 + C의 편지 |
| 관계 표시 | 대화창 칩 + 📒 주민 수첩 |
| 편지 전달 | 📮 소식함에 "편지" 칸 |

| 보상 아이템 추가 | 단계 보상에 아이템을 함께 만든다 |

## 3. 단계표

| 단계 | 문턱 | 보상 | 편지 |
|---|---|---|---|
| 👋 아는 사이 | ❤️1 | 수첩에 그 주민 칸이 열림 | 없음 |
| 🏡 이웃 | ❤️3 | 그 주민 전문 재료 꾸러미 | ✉️ |
| 🤝 친구 | ❤️6 | 📜 금빛 도구 도면 의뢰(지금 있는 것). 판다·올빼미는 전용 보상 | ✉️ |
| 💛 단짝 | ❤️10 | 🎁 그 주민 전용 꾸미기 1개 | ✉️ |
| 🌳 가족 | ❤️15 | 🖼️ 그 주민 탁상 액자 + 이름표에 🌳 | ✉️ |

- 대상: 마을 주민 10명 + 🦉 올빼미 = 11명. 카페 손님 8종은 이번 범위 밖(§11).
- 지금의 "❤️3마다 씨앗3·작물1 답례"(`addAffinity`)는 없애고 단계 보상이 대신한다. 15를 넘어서도 호감도는 계속 오르되 보상은 없다(수첩에 숫자만).
- ❤️6 도면 의뢰의 문턱(`HIDDEN_AFFINITY`)과 우선순위 규칙은 그대로 둔다. 단계표가 그 값을 읽는다(한 곳에서만 정의).

|---|---|
| 🧑‍🌾 농부 | 씨앗 6 · 작물 3 |
| 👷 목수 | 목재 10 |
| 🧙 상인 | 🪙 30 |
| 🎣 낚시꾼 | 🪱 미끼 2회분 · 물고기 2 |
| 🐼 판다 | 밀가루 2 · 꿀 2 |
| 🦡 오소리 | 채집물 5 |
| ⭐ 별 아이 | 반딧불이 2 |
| 🦆 사공 | 물고기 3 · 목재 5 |

| 🧑‍🦳 큐레이터 | 돌 6 · 석탄 2 |
| 🦉 올빼미 | 🪙 30 |

### 3.2 판다·올빼미 친구 보상 (❤️6, 도면이 없는 두 사람)

- 🐼 판다: 💎1 · 밀가루 3
- 🦉 올빼미: 💎1 · 🪙 50

### 3.3 단짝 전용 아이템 (❤️10) 가안

모두 야외 장식(`OUTDOOR`, `hidden: true`, `quest: 'affinity'`). `grantDecor` 가 `quest` 가 있는 야외 장식을 🧺 보관함(`outdoorStored`)에 넣는 길을 그대로 쓴다. 이름은 문구 검수 대상.

| 주민 | 아이템 |
|---|---|
| 🧑‍🌾 농부 | 🥕 채소 수레 |
| 👷 목수 | 🪑 흔들의자 |
| 🧙 상인 | ⛺ 보라 천막 |
| 🎣 낚시꾼 | 🎣 낚시 쉼터 |
| 🐼 판다 | 🎋 대나무 찜기 탁자 |
| 🦡 오소리 | 🍄 버섯 등불 |
| ⭐ 별 아이 | 🔭 작은 망원경 |
| 🦆 사공 | 🛶 꽃배 화분 |
| 🐔 목장 | 🐣 병아리 둥지 |
| 🧑‍🦳 큐레이터 | 🏺 유리 진열장 |
| 🦉 올빼미 | 📮 올빼미 우체통 |

- 3D 모양은 주민 실루엣·색과 이어지게(목수=테라코타, 상인=보라 등). 렌더는 3안 이상 비교 후 확정(메모리 design-compare-before-ship, visitor-art-lessons).
- 밤에 빛나는 것(버섯 등불·망원경)은 기존 정원등 발광 규칙을 따른다. 블룸 임계값을 넘지 않게.

### 3.4 가족 탁상 액자 (❤️15)

- 실내 장식(`DECOR`, `hidden: true`) 11개 id(`frame_<npcId>`), 모델은 틀 하나를 공유하고 사진 면만 주민별로 바뀐다(주민 얼굴·고유색).
- 벽걸이 배치는 아직 없다. 작은 소품(`sm: true`)으로 만들어 식탁·찬장 상판(`top`)이나 바닥에 놓는다. 벽걸이는 만들지 않는다.
- 사진 면은 캔버스 텍스처(이름표 `makeNameTag` 와 같은 방식, `toneMapped:false`). 이모지 얼굴이 아니라 주민 머리 모양을 그린 일러스트로 할지는 렌더 비교에서 정한다.
- 가족 단계 주민은 마을 이름표 앞에 🌳 를 붙인다.

## 4. 호감도가 오르는 길

| 길 | 지금 | 바뀌는 것 |
|---|---|---|
| 선물 | +1 (목걸이·별빛 유리병 +2), 제한 없음 | **주민당 하루 +2까지.** 넘으면 선물은 받지만 하트는 안 오르고, 대사로 알려 준다("오늘은 마음만 받을게" 류, 문구 검수) |
| 반복 의뢰 완료 | +1 | 그대로 (상한에 안 셈) |
| 카페 접객 | 손님 8종에게만 | 그대로 (이번 범위 밖) |
| 🦉 일일 의뢰 5건 모두 완료 | 없음 | **올빼미 +1** (하루 한 번). 올빼미 호감도의 출구 |

- 하루 기준은 KST 날짜(`todayStr()`), 다른 일일 카운터와 같다.
- 선물 상한은 "하트"에만 걸린다. 선물 재료 소모·🦉 의뢰의 `gift` 진행은 그대로 일어난다.
- 상한 도달 전에 수첩·대화창 칩이 "오늘 ❤️ 2/2" 를 보여 줘 헛선물을 막는다.

예상 소요: 한 주민만 선물로 파면 ❤️15 까지 약 7일(반복 의뢰가 끼면 5~6일). 여러 주민을 함께 키우면 하루에 여러 칸이 오른다.

## 5. 화면

### 5.1 대화창 칩

- 지금 하트 줄(`#npc-hearts`, 5개 상한 + ×n)을 칩 하나로 바꾼다: `🤝 친구 ❤️7/10`. 0이면 `선물 하나면 시작` 류 안내(문구 검수).
- 칩을 누르면 📒 주민 수첩이 그 주민을 고른 채로 열린다.
- 대화창 높이는 지금과 같게. 모바일 375px 에서 이름·칩 한 줄(실측 2026-11-13). 320px 에서 이름이 긴 주민(큐레이터·낚시꾼 할아버지)은 한 줄에 안 들어가므로 대화창 머리에 줄바꿈을 허용해 칩이 이름 아랫줄로 내려간다.

### 5.2 📒 주민 수첩

- ☰ 메뉴에 새 항목, 대화창 칩에서도 열림. `anyModalOpen()` 셀렉터에 직접 넣는다(npc-map-legibility 함정).
- 첫 화면: 주민 11명 카드 격자(PC 4열, 모바일 3열). 카드 = 얼굴·이름·단계 칩·"다음 ❤️n 보상 아이콘". 아직 0인 주민은 "아직" + 시작 안내.
- 카드를 누르면 그 주민 상세: 다섯 단계 세로 목록(받은 칸·지금 칸·남은 칸), 다음 보상 미리보기(아이콘+이름), 오늘 선물 하트 n/2, 받은 편지 목록(누르면 소식함 편지 칸으로).
- 아직 마을에 안 돌아온 주민(`js/world/unlocks.js` 숨은 이웃)은 수첩에도 안 보인다.

### 5.3 단계가 오른 순간

1. 주민 머리 위 이모지 말풍선(단계 이모지, 예: 🤝). 글자는 넣지 않는다(world-bubble-emoji-only).
2. HUD 알림 한 줄: `🤝 목수 아저씨와 친구가 됐어요!` + 둘째 줄 `✉️ 편지가 왔어요 · 📮 소식함`(문구 검수).
3. ☰ 메뉴와 📮 소식함 항목에 빨간 점.
4. 보상은 편지를 열어 [받기]를 누를 때 지급(꾸러미는 가방, 아이템은 🧺 보관함). 편지를 안 열어도 보상은 사라지지 않는다.

### 5.4 📮 소식함 편지 칸

- 지금 소식함(우편함 B안: 목록+상세 2단, 720px 아래는 상세가 밀려 들어옴)에 탭 두 개: `📮 소식` / `✉️ 편지`.
- 편지 목록: 주민 얼굴 우표(`leadEmoji` 와 같은 자리) · `목수 아저씨 · 단짝` · 안 읽음 점. 최신이 위.
- 편지 상세: 머리(✉️ 주민 이름의 편지 · 단계), 본문 2~4문장, 동봉 칩(🎁 꾸러미/아이템), [받기] → 받은 뒤엔 `받았어요` 비활성.
- 편지는 서버 `notices` 가 아니라 클라이언트에서 만든다(단계표+편지 문구표에서 파생). 서버 테이블·RLS 변경 없음.
- 소식함 자동 표시(출석 모달 다음 'new')는 공지만 다룬다. 편지는 위 5.3 의 알림·빨간 점으로 알린다.

## 6. 데이터·세이브

새 최상위 세이브 필드는 옛 클라이언트가 다음 저장 때 지운다(space-link-v2 스펙 7절). 그래서 새 상태는 모두 `hintsSeen` 안에 둔다.

| 키 | 값 | 뜻 |
|---|---|---|
| `gameState.affinity` | `{ builder: 7, ... }` | 기존 그대로(숫자) |
| `hintsSeen.affStage` | `{ builder: 2, ... }` | 단계 보상(편지)을 **발행한** 가장 높은 단계 인덱스(0~4). 단계가 숫자에서 파생돼도 "보상 발행"은 따로 기록해 두 번 주지 않는다 |
| `hintsSeen.affClaim` | `{ 'builder:3': 1, ... }` | 편지 동봉 보상을 받은 것. 키 = `npc:문턱` |
| `hintsSeen.affRead` | `{ 'builder:3': 1, ... }` | 읽은 편지 |
| `hintsSeen.affGift` | `{ d: '2026-11-12', by: { builder: 2 } }` | 오늘 선물로 오른 하트(날이 바뀌면 통째로 새로) |
| `hintsSeen.affOwlDay` | `'2026-11-12'` | 올빼미 일일 완료 +1 을 준 날 |

- 새 아이템 id: 야외 장식 11 + 실내 액자 11 = 22개. **옛 클라이언트가 모르는 꾸미기 id 를 세이브에서 지우므로 웹·토스·itch·Android·iOS 5곳 동시 배포**(minigame-decor-drops 와 같은 규칙).
- 서버 쪽 변경 없음(보상 꾸미기는 원장 `purchases` 가 아니라 클라이언트 지급. 초대·가입 보상 장식처럼 서버 가드 목록에 넣지 않는다).

### 6.1 이미 호감도가 높은 기존 유저

- 첫 접속 때 `affinity` 에서 단계를 계산해 `affStage` 보다 높은 단계의 편지를 한꺼번에 발행한다(상인 ❤️31 이면 편지 4통). 알림은 한 줄로 묶는다(`✉️ 편지 4통이 왔어요`).
- 이미 받은 도면은 그대로. 친구 편지는 "도면 고마웠어" 식으로 내용만 오고 도면 의뢰를 다시 열지 않는다(`blueprints` 를 보고 갈래).

## 7. 모듈 구조

새 코드는 `game.js` 가 아니라 `js/affinity/` 아래에(split-files-not-gamejs).

| 파일 | 맡는 일 | 의존 |
|---|---|---|
| `js/affinity/stages.js` | 순수. 단계표·`stageOf(n)`·`nextOf(n)`·`pendingLetters(affinity, affStage)`·`giftGain(today, affGift, npc, love)` | 없음 (테스트 대상) |
| `js/data/npc-letters.js` | 순수 데이터. 주민×단계 편지 본문(ko), 꾸러미·아이템 표 | 없음 |
| `js/affinity/index.js` | 게임 연결. `addAffinity` 대체, 단계 상승 감지 → 알림·빨간 점·트래킹, 보상 지급(`giveReward`·`grantDecor`) | game.js 상태 |
| `js/affinity/book-ui.js` | 📒 주민 수첩 DOM | ui |
| `js/affinity/letters-ui.js` | 소식함 편지 칸 | 소식함 모달 |
| `js/affinity/art.js` | 단짝 11종·액자 틀 모델 | THREE |

- `outdoor-decor.js addAffinity` 는 `js/affinity/index.js` 로 옮기고, 선물·반복 의뢰·카페 호출부가 같은 함수를 쓴다. 카페 손님 id(`guest_*`)는 단계 로직을 타지 않는다.
- 문구는 한국어 원문 키 + `js/i18n-en.js`(i18n-architecture). 편지 44통은 en 번역 포함.

## 8. 계측

GA4 파라미터 키 상한 23 안에서(ga4-param-limit). 새 키는 `stage` 하나만 늘리고 나머지는 기존 키(`npc`, `source`, `from`)를 쓴다. 구현 전에 현재 키 목록과 대조.

| 이벤트 | 파라미터 | 언제 |
|---|---|---|
| `affinity_stage` | npc, stage(1~5), source(gift/repeat/serve/daily/retro) | 단계가 오를 때(기존 유저 소급분은 source=retro) |
| `affinity_gift_capped` | npc | 오늘 상한을 넘긴 선물 |
| `npc_book_open` | from(chip/menu), npc | 수첩 열기 |
| `affinity_letter_open` | npc, stage | 편지 열기 |
| `affinity_reward_claim` | npc, stage | [받기] |

- 단짝 아이템을 실제로 마당에 놓았는지는 기존 `store_outdoor`/배치 이벤트로 본다.
- 다음 날 BigQuery 로 재검증(feature-tracking-checklist).

### 8.1 볼 지표

- 주: 집 3단계↑ 유저 중 주민 호감도 ≥1 비율(지금 13%)과 ❤️3(이웃) 도달 비율.
- 보조: 1인당 이웃↑ 주민 수, 단짝 도달자 수, 단짝 아이템 배치율, D7 재방문(집 완성 코호트, 배포 전후).
- 가드레일: 일일 코인·💎 발행량(이웃 꾸러미·친구 보상 때문), 선물 제작 수.

## 9. 실험 교란

- E3(공간 연결)·E6(안내 개편)은 첫날(지붕·다리·연못) 구간 대상. 호감도는 집을 다 지은 뒤 콘텐츠라 주 지표와 직접 겹치지 않는다.
- 첫날 구간에 호감도 안내(수첩 소개·칩 강조)를 넣지 않는다. 수첩 첫 안내는 집 완성 뒤 첫 선물 때.
- E3 가드레일(첫날 세션 길이)에 영향이 없도록 단계 알림은 집 완성 전에는 뜨지 않게 한다(첫날에 반복 의뢰가 열리지 않으므로 실제로 거의 없음).
- 배포일을 E3 사전등록(`dev/active/metrics-framework/space-link-experiment-prereg.md`)에 한 줄 남긴다.
- A/B 는 하지 않는다(보상 아이템이 걸린 진행형이라 무리 간 박탈감). 배포 전후 비교로 본다.
