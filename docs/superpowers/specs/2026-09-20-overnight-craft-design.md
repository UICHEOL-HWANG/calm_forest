## 한 줄

재료를 걸어두고 나가면 **날짜가 바뀐 뒤 첫 접속**에 가공물이 되어 있다.
거는 순간 미니게임을 치르고, 그 결과가 **완성 여부가 아니라 수율**을 정한다.

## 풀려는 문제

1. **D1 이탈 78%** — 접속을 끊는 순간 게임이 멈춘다. 돌아올 때 기다리는 것이 없다.
2. **가공 체인이 1단에서 멈춘다** — 인벤토리 30여 키가 전부 원재료거나 과일이다. 2차 가공물이 하나도 없다.
3. **고급 작물이 판매 전용이다** — `RECIPES` 9종의 재료는 전부 `crop`/`forage`/`fish`/`egg`이고,
   밀·옥수수·포도는 **단 하나의 레시피에도 안 들어간다**. 포도 지지대를 짓고 키운 포도가 팔리는 것 말고 할 일이 없다.
4. **일꾼이 만드는 잉여의 출구가 없다** — 오프라인 12시간 정산으로 작물이 쌓이는데 판매뿐이라 코인만 는다.
   코인은 이미 "쓸 데가 없다"는 피드백이 반복됐다.

## 하지 않는 것 (경계)

- **손실 압박 없음.** "안 오면 썩는다", 기한, 만료를 넣지 않는다. 힐링 톤을 깨고 오히려 이탈을 부른다.
  걸어둔 것은 **언제 와도 그대로 있다.**
- **요리 미니게임을 대체하지 않는다.** 화덕은 밀가루까지만 만들고 빵은 부엌에서 굽는다.
  화덕에서 빵이 바로 나오면 하룻밤 기다리는 편이 썰기·굽기보다 쉬워서 미니게임 4종이 죽는다.
- **판매 마진을 크게 두지 않는다.** 크면 요리·카페·건축을 아무도 안 하고 전부 팔아치운다.
- **`js/game.js`에 몰지 않는다.** 규칙·수치는 `js/craft/` 모듈로, 렌더는 기능 디렉터리로 나눈다.

## 1. 시설 — 마을 화덕 🔥

`js/game.js:658`의 `OUTDOOR` 배열에 한 종을 추가한다. 이 배열은 이미 마을 야외 8종과 `...FARM_BUILDINGS` 7종을
같은 배치 문법으로 흡수하고 있어, 배치·회전·발자국 스냅·충돌·저장(`gameState.outdoor`)이 전부 재사용된다.
`farm: true` 플래그를 **달지 않으면** 텃밭 제약 없이 마을 야외에 놓인다.

| 항목 | 값 | 근거 |
|---|---|---|
| 배치 | 마을 야외 (플레이어가 직접 놓음) | 재료가 밭·과수원·숲·광산 4개 구역에 흩어져 있어 중립 지대가 맞다 |
| **첫 개** | **스토리 보상으로 자동 지급·자동 배치** | `shop_buy` 도달률 8%. 사게 만들면 대부분이 존재를 모른다. `story_chapter_start`는 125명 |
| 추가 제작 | 🪨돌 20 · 🪵목재 15 · 🪙150 | 코인 싱크 겸용 |
| 슬롯 | 화덕 1개당 **2칸**, 최대 3개 = 6칸 | 마을이 화덕으로 뒤덮이지 않게 상한을 둔다 |

**왜 농장 시설이 아닌가** — 과수원(`atOrchard`)은 농장과도 다른 별도 구역이다.
가공소가 한 구역에 귀속되면 다른 구역 재료는 계속 겉돈다. 네 구역 모두 마을을 거쳐 집으로 돌아오므로 마을이 중립 지대다.
2·3단계에서 농장 발효장·과수원 착즙소를 각 구역 전용으로 추가한다(로드맵 참조).

## 2. 주기 — 날짜 경계

걸어둔 슬롯은 **`day`에 기록된 날짜와 오늘이 다르면** 완성이다.
`dateHash` 날짜 시드 문법을 그대로 쓴다 — 날씨·시세·카페 손님·배 코스·과수원이 이미 이 시계로 돈다.

게임 내 하루(`DAY_SPEED = 0.002`, 약 8분)는 **쓰지 않는다.** 한 세션에 여러 번 지나가므로 리텐션 레버가 못 된다.
「잔다」(`doSleep`)는 게임 내 시계만 아침으로 점프시키며, 가공에는 영향이 없다.

정산은 로그인 시 `catchUpWorkers()` 옆에서 `catchUpCraft()`를 호출하고,
완성된 것을 모아 **일꾼 정산 요약과 같은 자리**에 함께 보여준다.

## 3. 품목 3종

거는 순간 미니게임을 치르고, **등급이 수율을 정한다.** 완성 여부는 등급과 무관하다(아쉬워도 최소 수량은 나온다).

| 품목 | 투입 | 산출(등급별) | 미니게임 | 엔진 |
|---|---|---|---|---|
| ⚫ **숯** | 🪵 목재 8 | 2 / 3 / 4 / 5 | 불 조절 — 노릇해질 때 공기구멍 여닫기 | 기존 `grill` |
| 🌾 **밀가루** | 🌾 밀 4 | 2 / 3 / 4 / 5 | 맷돌 돌리기 — 원을 따라 일정한 속도로 드래그 | **신규 `mill`** |
| 🧱 **벽돌** | 🪨 돌 6 · ⚫ 석탄 2 | 2 / 3 / 4 / 5 | 반죽 다지기 — 꾹 눌렀다 목표선에서 떼기 | 기존 `season` |

등급은 기존 요리 4단(😅 🙂 😋 💫)을 그대로 쓴다.

**난이도는 오직 판정창 배율로만 조절한다.** `COURSE_MULT`와 같은 규칙이다 —
속도·단계 수까지 흔들면 어느 쪽이 어려웠는지 지표로 가를 수 없다.

미니게임은 `updateMgScene`의 `mgView.type` 분기에 얹는다. 신규 판정 로직은 `mill` 하나뿐이고,
나머지 둘은 무대·연출·목표만 바꾼다(고기 굽기와 숯가마 불 조절은 같은 엔진이어도 전혀 다르게 읽힌다).

### 수치 초안 — 검토 필요

기존 판매가 기준: `wood 2 · wheat 15 · stone 3 · coal 6`

| 품목 | 투입 원가 | 판매가 | 산출 2~5개 환산 | 판단 |
|---|---|---|---|---|
| ⚫ 숯 | 16 | 9 | 18 ~ 45 | 평균(3.5개) 31 — 소폭 마진 |
| 🌾 밀가루 | 60 | 18 | 36 ~ 90 | 평균 63 — 거의 본전. **주용도는 빵** |
| 🧱 벽돌 | 30 | 12 | 24 ~ 60 | 평균 42 — 소폭 마진 |

**판매는 출구 중 가장 나쁜 선택이 되도록** 잡았다. 밀가루를 팔면 본전이고, 빵으로 구우면 카페에서 56을 받는다.

## 4. 출구 — 가공물이 가는 곳

원칙: **가공물은 코인이 아니라 "할 수 있는 일"로 바뀐다.** 고수익 판매처를 하나 더 얹으면 코인 문제가 악화된다.

| 품목 | 주 용도 | 보조 |
|---|---|---|
| ⚫ 숯 | 고급 요리의 화력 재료 · 도구 강화 | 판매 |
| 🌾 밀가루 | **부엌에서 🥐빵으로** | 판매(본전) |
| 🧱 벽돌 | 집 증축·야외 시설 제작비 절감 | 판매 |

### 🥐 빵 — 부엌 신규 레시피

```
🌾 밀 ──[화덕, 하룻밤]──▶ 🌾 밀가루 ──[부엌 미니게임]──▶ 🥐 빵
```

화덕이 없으면 만들 수 없는 레시피가 생긴다. 화덕이 요리를 **죽이는 게 아니라 요리의 입구**가 된다.

| 항목 | 값 |
|---|---|
| `RECIPES` | `{ id:'bread', cost:{ flour:2 }, stages:['pot','grill'], buff:'speed', dur:150 }` — ★2 |
| `CAFE_PAY` | `bread: 56` (★2 46~48보다 높고 ★3 74보다 낮게) |
| `SELL_PRICE` | `bread: 26` |
| `GIFTS` | 빵 선물 추가 |
| `DEX` | cook 카테고리에 추가 |

★2인데 지속이 150초(★3급)인 이유는 **가공 재료를 쓴 보상**이다. 하룻밤을 기다린 값을 여기서 돌려준다.

**딸려오는 이득:** 밀·옥수수·포도가 드디어 쓸 데가 생긴다. 농장 확장과 포도 지지대를 지을 이유도 같이 생긴다.

## 5. 저장 구조

```js
// gameState.craft — 신규 필드
{
  slots: [
    { st: 'kiln_1',        // 배치된 화덕 레코드 id (gameState.outdoor 참조)
      item: 'charcoal',    // 'charcoal' | 'flour' | 'brick' — 키값, 라벨 아님
      qty: 4,              // 미니게임 등급으로 확정된 산출량
      grade: 2,            // 0~3 (😅🙂😋💫)
      day: '20260920',     // 건 날짜. todayStr() 이 돌려주는 로컬 날짜 키
      done: false }        // 수령 완료
  ]
}
```

완성 판정은 `todayStr() !== slot.day`. 수령하면 슬롯을 비운다.

날짜 키는 `js/game.js:148`의 `dayStr(ms)` / `js/game.js:152`의 `todayStr(offsetDays)` 를 그대로 쓴다.
`dayStr` 주석에 **"고용일 비교에도 쓴다"** 고 되어 있어, 일꾼 시스템이 이미 이 문법으로 하루를 센다.
새 시계를 만들지 않는다.

**마이그레이션:** `js/save-migrate.js`에 `craft` 기본값(`{ slots: [] }`)을 추가한다.
필드가 없는 기존 세이브가 신규로 오인되지 않게 한다 — 읽기 실패를 신규로 착각해 마을을 덮어쓴 사고가 있었다.

## 6. 트래킹

**구현과 같은 수준으로 짠다.** `quest_id`가 빠져 퀘스트 분석이 막혔던 전례가 있다.
축은 전부 **키값**(`item: 'flour'`)이고 표시 라벨을 넣지 않는다.

| 이벤트 | 파라미터 | 왜 필요한가 |
|---|---|---|
| `craft_set` | `item`, `grade`, `score`, `qty`, `slot_idx`, `station_seq` | 무엇을 얼마나 거는가 · 미니게임 난이도 검증 |
| `craft_claim` | `item`, `qty`, `grade`, **`waited_days`** | **핵심 지표.** 며칠 만에 받으러 왔는가 |
| `craft_blocked` | `reason`(`full`\|`no_material`) | 슬롯이 모자란가, 재료가 모자란가 |
| `craft_station_build` | `seq` | 두 번째·세 번째 화덕을 짓는가 |
| `bread_cook` / `bread_serve` | `grade`, `pay` | 밀가루가 실제로 빵까지 가는가 |

**성공 기준**

1. D1 재방문율 22% → **30% 이상** (4주 데이터)
2. `craft_set` 대비 `craft_claim` 비율 **70% 이상** — 걸어둔 걸 받으러 돌아오는가.
   이것이 낮으면 D1이 올라도 이 기능 덕분이 아니다.
3. `craft_set` 도달 인원이 진입 유저의 **40% 이상** — 첫 개 자동 지급이 실제로 작동하는가.

다음 날 BigQuery에서 파라미터가 실제로 적재됐는지 재검증한다.

## 7. UI·조형 — ✅ 시안 확정 (2026-09-20)

시안 파일: [`sims/kiln-sim.html`](../../../sims/kiln-sim.html) (조형) · [`sims/craft-ui-sim.html`](../../../sims/craft-ui-sim.html) (UI)
둘 다 `?dist=..&hgt=..&ang=..&night=1&ui=0` / `?m=mobile&ui=0` 파라미터로 같은 그림을 다시 뽑을 수 있다.

### 이름 — 🔥 **화덕**

`js/game.js` 의 "화덕"은 주석 3곳(8688·8806·8840, 끓이기 무대 소품)뿐이고
**UI 문자열에도 i18n 사전에도 없다** → 이름 충돌 없음.

### 조형 — C안 «낮은 아궁이»

옆으로 긴 덩어리 + 평평한 상판. 채택 이유는 **상판이 표시 면이 되기 때문**이다 —
완성된 산출물이 상판에 쌓여 **가까이 가지 않아도 "다 구워졌다"가 읽힌다.**
이 기능은 "돌아왔을 때 받을 게 있다"가 전부라 그 신호가 멀리서 보이는 값이 크다.
(A 돌 돔·B 원통 굴뚝은 탈락. 함수는 시안 파일에 선택 근거로 남겨 뒀다.)

상태 3종을 조형으로 구분한다.

| 상태 | 겉모습 |
|---|---|
| 빈 화덕 | 입구 어둡고 장작 1개 |
| 굽는 중 | 불꽃 + 장작 2개 |
| 다 구워짐 | 불 꺼짐 · 장작 없음 · **상판에 산출물**(⚫숯 덩어리 / 🌾밀가루 포대) |

**시안에서 실패하고 고친 것 — 다시 하지 말 것**

- 몸통을 `stone(0x5a5148)` 으로 두면 낮에 검게 읽힌다 → `0x9a7358`(따뜻한 흙벽돌).
- 아궁이 입을 **둘** 두면 눈이 되어 얼굴로 보인다 → 입은 하나, 반대쪽은 장작단으로 비대칭을 만든다.
- 불을 입구 원통 **안쪽**에 두면 내벽에 가려 밤에 안 보인다 → 입 앞턱에 걸친다.
- 밀가루 포대를 **세우면** 목·매듭이 생겨 도자기(1차)·등대(2차)로 읽힌다 → **눕혀 쌓고** 세그먼트를 깎아(2,5) 주변 flat shading 과 결을 맞춘다.
- 불꽃을 원뿔로 만들면 "고깔"이다 → 옆모습 프로필(밑동 불룩 → 중간 잘록 → 끝 가늘게)을 `LatheGeometry` 로 돌린다.
- 떠오르는 불똥(Points)은 **쓰지 않는다** — 불꽃 끝에서 동그란 점이 튀어 나가는 것으로 보였다.

### 불꽃

`LatheGeometry` 프로필 회전체 **2겹** — 바깥 주황(`ff7320`) · 안쪽 심지 노랑(`ffd44e`), 세그먼트 6.
서로 다른 박자로 ① 세로로 늘 때 가로가 눌리고 ② 반대 방향으로 천천히 비틀리고 ③ 좌우로 기운다.
점광이 함께 맥동해 밤에 바닥을 밝힌다. 게임 본편은 블룸이 있어 시안보다 더 번진다.

### 가공 창 — B안 «슬롯 띠 + 레시피»

```
🔥 화덕                                    ✕
[⚫숯 ×4 ✓] [⚫숯 🔥] [  비어 있음  ]      ← 슬롯 띠
[        ⚫ 숯 받기        ]               ← 완성분 수령
무엇을 구울까요
 ⚫ 숯      🪵 목재 8 → 2~5개      [걸기]
 🌾 밀가루  🌾 밀 4 → 2~5개        [걸기]
 🧱 벽돌    🪨돌 6 · ⚫석탄 2 …     [걸기]  ← 재료 부족 시 흐리게 + disabled
```

**채택 이유는 클릭 수다.** A·C 는 슬롯의 「걸기」 → 레시피 창이 또 뜸 → 선택으로 **2단계**지만,
B 는 레시피 줄에서 바로 **1단계**다. 하루를 마무리하며 거는 반복 행동이라 마찰을 한 번이라도 줄여야 한다.

- A안(슬롯 카드)은 **모바일에서 탈락** — 세 칸이 세로로 쌓여 340px 폭에서 창이 640px를 넘는다. 6칸은 불가.
- **칩의 상태는 글자가 아니라 기호로**(`✓` / `🔥`). 칸이 3개만 되어도 "다 구워졌어요"가 두 줄로 깨졌다.
- 칸이 6개가 되면 슬롯 띠를 두 줄로 흘린다(`flex-wrap`).

토큰은 게임 것을 그대로 쓴다 — `--panel` 반투명 흰색 + `blur(8px)` + `radius 18`, 강조는 `--mint`.
창 위치·높이는 기존 모달 규약: `bottom: calc(90px + env(safe-area-inset-bottom))`,
`width: min(460px, 92vw)`, `max-height: calc(100dvh - 24px - var(--top-inset))`.

### 📱 모바일 — 실측으로 확정한 규약

**폰 세로 340px 와 작은 폰 320px 둘 다에서 확인했다.** 시안은 `?m=mobile` / `?m=narrow` 로 재현된다.

| 규칙 | 이유(실측에서 깨진 것) |
|---|---|
| 슬롯 띠는 `flex-wrap`, 칩 `min-width: 88px` | 96px 이면 320px 에서 3칸이 2+1 로 흘러 빈 칸이 혼자 한 줄을 먹었다. 88px 면 3칸이 한 줄(88×3+gap16=280 < 288), 6칸은 3×2 로 떨어진다 |
| 칩의 상태는 **기호**(`✓` `🔥`), 글자 금지 | "다 구워졌어요" 를 칩에 넣으면 3칸에서 이미 두 줄로 깨진다 |
| 재료 부족은 **문장이 아니라 색**으로 | "— 돌이 모자라요" 를 붙이니 320px 에서 "요" 한 글자가 다음 줄로 떨어졌다. 모자란 재료만 `#d05a4a` 로 짚고 버튼은 `disabled` — 신호가 이미 둘이다 |
| `.cost` 는 `nowrap` + `ellipsis` | 재료 줄이 길어져도 레이아웃이 밀리지 않게 |
| 창은 바닥 기준 | `bottom: calc(90px + env(safe-area-inset-bottom))` · `max-height: calc(100dvh - 24px - var(--top-inset))` — 기존 모달 규약 그대로 |
| 토스 웹뷰 | `--top-inset` 이 `--toss-reserve(52px)` 를 물고 있다. 상단에 무엇도 직접 붙이지 않는다 |

A안(슬롯 카드)이 탈락한 것도 모바일 때문이다 — 340px 에서 세 칸이 세로로 쌓여 창이 640px 를 넘었고, 6칸은 불가능했다.

**배포 전 실측 항목**: 340·320 두 폭 × 슬롯 3칸·6칸 × 재료 부족 유무. 캡처로 남긴다.

## 8. 구현 순서

1. `js/craft/` 모듈 — 레시피 표·수율·완성 판정 (순수 함수, 테스트 먼저)
