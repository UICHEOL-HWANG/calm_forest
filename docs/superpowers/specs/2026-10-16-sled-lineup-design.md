## 3. 물리 (PHYS_V 1 → 2)

`PHYS` 는 공통 기본값으로 두고 썰매별 덮어쓰기만 둔다. `stepSled`·`tryBoost`·`finalTimeMs` 는 썰매의 물리 묶음을 인자로 받는다(기본값 = 나무 썰매).

| id | baseSpeed | accel | steerRate | boostMult | hitSlowMult | hitRecoverMs |
|---|---|---|---|---|---|---|
| basic(색 3종 포함) | 8.6 | 6.0 | 6.5 | 1.5 | 0.5 | 1500 |
| toboggan | 8.6 | 6.0 | 5.2 | 1.5 | 0.65 | 1100 |
| wind | 9.1 | 6.0 | 6.5 | 1.34 | 0.5 | 1500 |
| acorn | 8.4 | 5.0 | 6.5 | 1.58 | 0.5 | 1500 |
| skiff | 8.6 | 6.0 | 8.2 | 1.5 | 0.5 | 1900 |

이상적 완주(도토리 0/3/7개, 충돌 0): basic 38.55/36.04/32.04 · wind 36.46/34.74/32.02 · acorn 39.50/36.72/32.08.
toboggan·skiff 는 직선 속도가 basic 과 같아 이상적 시간이 같다.

**공정성 테스트**: 도토리 7개 이상적 완주 시간이 모든 썰매에서 basic 대비 ±0.1초 안. 이상적 시간 계산기는 `js/mountain/sled-ideal.js`(순수 함수)로 두고 테스트가 쓴다.

**서버 하한**: 최고 순간 속도 = baseSpeed × boostMult ≤ 13.3 < 24 → 기존 하한 13,750ms 그대로 안전.

## 5. 판매 구조

### 5-1. 데이터
- `js/mountain/sled-lineup.js`(새 파일, 순수): `SLED_LINEUP` = id → { name, ico, line, stats, model, palette, phys, coins, cashWon, needs }. 단일 출처.
- `cafe-catalog.js` 의 썰매 줄은 `SLED_LINEUP` 에서 만든다. 탭 순서: 나무 → 색 3종 → 터보건 → 바람 → 도토리 → 스키프.
- `save.js` `SLED_SKIN_IDS` → 라인업 키 전부. 기존 세이브 그대로 복원된다.

### 5-2. 현금 (펫 방식 복제)
- `js/shop/price-ids.js` 에 `wind: null, acorn: null, skiff: null` 추가 → 시드 스크립트가 채운다.
- 가격 칸: `cashFor(id, null, 3900)` → `{ priceId, label: '₩3,900' }`. priceId 가 null 이면 현금 버튼 없음.
- 웹훅 `priceIndex()`(functions/api/_paddle.js) 에 썰매 줄 추가: `kind: 'sled'`.
- 원장 병합 `applyPurchases`(js/shop/entitlements.js): `kindOf` 에 `'sled'` 추가 → 지급 = `mountain.hut.sleds` 에 id 추가, 회수 = 목록에서 빼고 타는 중이면 `basic` 으로.
- 시드 `buildPlan`(scripts/lib/paddle-seed.mjs): 썰매 줄도 등록(`kind: 'sled'`, 설명 `calm forest 설산 썰매 (능력 썰매)`).
- 서버 프리미엄 가드(`_premium_cosmetic_ids`)에는 **넣지 않는다**. 코인으로도 살 수 있어 원장 없이 가진 상태가 정상이다.

### 5-3. 노출
- 산장 카페 🛷 썰매 탭: 줄마다 이름·한 줄·능력치 점·코인 버튼. 웹이고 `cashAvailable()` 이면 현금 버튼(₩3,900)을 하나 더.
- 앱 플랫폼은 `cashAvailable()` 이 false 라 현금 버튼이 안 보인다.
- 같은 썰매를 코인·현금 둘 다로 사는 경로는 "타기/타는 중" 상태가 막는다.

## 6. 기록·트래킹

- `PHYS_V = 2`. `sled_runs` 에 `sled text` 열 추가, `phys_v` CHECK 를 `in (1, 2)` 로. SQL 은 풀러로 직접 실행한다.
- `sled_runs.sled`: 라인업 id 만 허용하는 CHECK(null 허용 — 옛 클라 행).
- GA4: 기존 `sled_start.sled_skin` 값이 라인업 id 가 된다(새 키 없음). 구매는 기존 `hut_cafe_buy` 에 `pay: 'coin'|'cash'` 1개 추가.
- 분석 메모: 썰매별 평균 기록·충돌 수를 `sled_runs.sled` 로 비교한다. 이상적 시간이 같아도 실제 평균은 실수 허용도에 따라 갈린다. 2주 뒤 실제 데이터로 재조정 여부를 판단한다(재조정 시 PHYS_V 3).
