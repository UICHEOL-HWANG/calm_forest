## 0. 확정된 선택 (브레인스토밍에서 합의)

| 항목 | 결정 |
|---|---|
| **결제 연결** | **이번엔 안 한다.** 사업자가 없다. 아이템부터 만들고 채널은 나중에 순차적으로 연다 |
| **재화 구조** | **이중 가격표** — 상품 한 줄에 현금 가격과 코인 가격을 둘 다 둔다. 새 유료 재화를 만들지 않는다 |
| **현금 전용 잠금** | **없다.** 모든 상품을 코인(노동)으로도 얻을 수 있다. 코인 가격은 의도적으로 비싸다 |
| **1차 범위** | 캐릭터 꾸미기 4슬롯 + 지시형 펫 |
| **펫 성격** | 일꾼과 달리 **지시받아야 움직인다**. 접속 중에만, 플레이어 근처만 |
| **펫 외형** | 성장 3단계로 **실루엣이 바뀐다** |

### 왜 이중 가격표인가

새 유료 재화(별가루 같은 것)를 만들면 채널 3개에서 환율·잔돈·재화 인플레를 동시에 관리해야 한다.
상품마다 가격 두 개를 붙이면 그 전부가 사라진다. 그리고 **지금 결제를 안 붙이기 때문에**
현금 칸을 `null`로 두고 코인 칸만 채우면 오늘 바로 돌아간다 — 나중에 채널이 열리면 그 줄만 채운다.

### 왜 💎gem 을 유료 재화로 쓰지 않는가

`gem`은 이미 채굴 자원이고 퀘스트 보상이다 — 루프탑 빌라 증축 재료, 보석 목걸이 선물,
낫·망치 업그레이드 재료, `SELL_PRICE.gem = 40`.
이걸 유료 재화로 바꾸면 **기존 세이브가 가진 gem이 그대로 유료 재화가 된다.**

## 2. 재화와 가격표

### 2-1. 카탈로그 한 줄의 모양

```js
{ id: 'hat_straw', slot: 'head', ico: '👒', name: '밀짚모자',
  price: { coins: 900, cash: null },    // cash 는 채널이 열릴 때 채운다
  earSafe: 'low',
  desc: '햇볕이 좋은 날에' }
```

`cash: null` = 아직 현금으로 못 산다. UI는 현금 버튼을 **그리지 않는다**(비활성이 아니라 없음).
채널이 열리면 `cash: { krw: 2500, sku: '...' }` 처럼 채워 넣고, UI가 버튼을 하나 더 그린다.

### 2-2. 코인 가격은 왜 비싼가

코인 가격은 "현금 대신 낼 수 있는 값"이다. 싸면 나중에 현금 경로가 죽고, 너무 비싸면 무과금이 목표를 포기한다.
기존 코인 싱크와 같은 눈금 위에 놓아야 감이 맞는다:

| 기존 코인 싱크 | 값 |
|---|---|
| 일꾼 초빙료 | 120🪙 |
| 흔들의자(4단계 가구) | 120🪙 |
| 그랜드 피아노(5단계) | 400🪙 |
| 루프탑 빌라 증축 | 800🪙 |
| 자쿠지(6단계) | 900🪙 |

⚠️ **꾸미기 가격을 이 표보다 낮게 잡으면 안 된다.** 낮으면 유저가 집 증축 대신 모자를 산다.
제안 구간 — 소품 600~900🪙, 눈에 띄는 것 1,200~1,800🪙, 펫 2,500~4,000🪙.
**정확한 수치는 §15 열린 결정.**

### 2-3. 구매는 되돌릴 수 없다

환불·되팔기 없음. 대신 **한 번 산 것은 영구 보유**하고, 장착과 해제는 자유다.

## 3. 앵커 슬롯 — 꾸미기의 뼈대

### 3-1. 왜 앵커인가

`buildAnimalMesh()`([js/game.js](../../../js/game.js))는 플레이어와 캐릭터 선택 프리뷰가
**공유하는 단일 소스**다. 모든 좌표가 `R`(몸 반지름) · `HR`(머리 반지름) · `HY`(머리 높이) 비례라,
장식 하나를 만들면 체형이 다른 동물 7종에 비율이 알아서 맞는다.

`ANIMALS[].extras`(🐼 어깨 무늬 · 🐶 목줄)에 장착 아이템을 밀어 넣는 방법도 있지만 쓰지 않는다:
`extras`는 "이 동물이 타고난 특징"이고, 장착을 바꿀 때마다 캐릭터를 통째로 다시 만들어야 한다.

대신 `buildAnimalMesh`가 **빈 `THREE.Group` 앵커를 만들어 반환**하고,
꾸미기 모듈이 그 앵커에 장식을 꽂는다. 장착을 바꾸면 **앵커의 자식만 교체**되고 캐릭터는 그대로다.

### 3-2. 슬롯 4개

| 슬롯 | 앵커 위치 | 근거 |
|---|---|---|
| `head` 머리 | `(0, HY, 0)` — **머리 중심** | 높이는 아이템이 정한다(아래 참조) |
| `neck` 목 | `(0, HY - HR*0.55, 0)`, 반지름 `HR*0.92` | 🐶 목줄이 이 좌표로 이미 구현돼 있다 |
| `side` 옆구리 | 방향 `(-0.80, -0.22, 0.48)` 의 몸 표면 밖 — **왼쪽 앞** | 가방류. 🦊꼬리를 피한다(§3-3) |
| `back` 등 | `(0, bodyY + R*0.30, -R*bs[2]*0.98)` — **몸 표면** | 망토 전용. 아이템이 자기 두께만큼 밀어낸다 |
| `trail` 발자국 | 앵커 아님 — 월드 공간 이펙트 (§4-4) |

**앵커는 "붙는 면"이고, 그 위 높이·두께는 아이템이 정한다.**
[sims/cosmetic-sim.html](../../../sims/cosmetic-sim.html) 실측에서 이 원칙이 나왔다 —
처음엔 앵커에 고정 오프셋을 박아 뒀는데 둘 다 틀렸다:

- `head` 를 `HY + HR*0.82` 라는 **한 높이**로 잡았더니 🐱고양이에서 챙이 얼굴 한가운데를
  가로질렀다. 동물마다 얼굴을 그리는 높이가 달라(`animal-faces.js`) "머리 위"가 한 값으로
  안 떨어진다. 모자는 `HR*0.70`, 머리띠는 이마 `HR*0.34` 처럼 아이템이 저마다 정해야 한다.
- `back` 의 z 계수 `0.55` 는 몸 표면(`bs[2]` 배)의 **절반, 즉 몸 속**이었다.
  등 뒤에서 찍었는데 배낭이 통째로 파묻혀 보이지 않았다. `0.98` 로 표면에 붙이고,
  아이템이 자기 두께의 절반만큼 바깥(−z)으로 밀어낸다.

머리 위에 띠를 두를 때 **둘레 반지름은 `√(HR² − h²)`** 다(h는 그 높이). 이 값을 안 쓰면
띠가 머리에서 뜨거나 묻힌다.

### 3-3. ⚠️ 함정 두 개

**귀가 모자를 뚫는다.** 🐰토끼 귀, 🐤병아리 볏이 머리에 있다.
머리 장식은 카탈로그에 `earSafe` 를 반드시 적는다:

- `earSafe: 'low'` — 위가 트인 것(화관, 머리띠, 챙만 있는 밀짚모자). 모든 동물에 안전
- `earSafe: 'dome'` — 머리를 덮는 것(털모자, 캡, 버섯 모자)

### 🎩 dome 규칙 — 구멍도 필요 없고 귀를 눕힐 필요도 없다

처음엔 "귀에 구멍을 뚫거나 귀를 눕혀야 한다"고 봤지만, `animal-faces.js` 의 귀 좌표를 재 보니
훨씬 싼 답이 있었다. **모자 아래 테두리를 귀 밑동보다 위에서 끝내면** 귀가 저절로 밖으로 빠져나온다.

| 동물 | 귀 밑동 (× HR) |
|---|---|
| 🐱 고양이 | 0.46 ← 가장 낮다 |
| 🐶 강아지 | 0.51 |
| 🦊 여우 | 0.52 |
| 🐰 토끼 | 0.80 |

```js
const DOME_BOT = 0.50;   // × HR — 모자 아래 테두리. 고양이(0.46)보다 위
// 머리 위쪽만 덮는 캡. thetaLength 를 풀어 아래 테두리를 DOME_BOT 에 맞춘다
const th = Math.acos(DOME_BOT * HR / r);
new THREE.SphereGeometry(r, 20, 14, 0, Math.PI * 2, 0, th);
```

열린 아래 단면은 테두리 띠(torus)로 막는다 — 단면이 보이지 않게 하고 모자에 윤곽도 준다.

🐤병아리 볏은 낮고(≤1.13·HR) 뒤쪽이라 모자 안에 눌린다. **그대로 둔다** — 모자를 쓰면
볏이 눌리는 게 자연스럽고, 그게 오히려 귀엽다.

부수 효과로 🐱고양이 수염 문제도 사라졌다. 캡이 머리 **위쪽만** 덮으니 옆으로 뻗은 수염과 겹치지 않는다.

### ⚠️ 챙만 있는 모자는 만들 수 없다

밀짚모자를 처음엔 "챙만" 으로 만들었다(귀가 구멍으로 지나가게). 구멍 내경 `0.72·HR` 에
그 높이의 머리 단면이 `0.714·HR` — 간격이 `0.006·HR` 이라 **머리가 구멍으로 튀어나온 채
챙만 떠 있었다.** 구멍을 키우면 챙이 머리에서 떨어져 더 이상해진다.

**크라운(머리 덮개)은 필수다.** `DOME_BOT` 규칙이 있으니 크라운을 씌워도 귀는 여전히 빠져나간다.

두 가지를 지킨다:

- **크라운 반지름 > 머리 반지름(1.0·HR).** 작으면 머리가 뚫고 나온다. (밀짚모자는 `1.04·HR`)
- **`scale.y` 로 낮게 누르지 않는다.** 세로만 줄이면 중간 높이의 가로 반지름이 머리보다
  작아져 머리가 다시 뚫고 나온다. 낮게 만들고 싶으면 **반지름으로만** 조절한다.

**🦊여우 꼬리가 등 자리를 먹는다 — 실측으로 확인됨.**

시뮬에서 처음엔 꼬리를 구슬 몇 개로 근사했는데, 실물보다 가늘어서 *"아슬아슬하지만 안 겹친다"*
고 잘못 판정했다. 게임과 같은 `taperedTube` 로 다시 만들자 **배낭이 꼬리에 통째로 먹혔다.**
근사로 클리어런스를 판정하면 안 된다는 교훈이 하나 더 늘었다.

숫자로 보면 피할 데가 없다. 꼬리는 `(0, bodyY + R*0.10, -R*bs[2]*0.86)` 에서 시작해
밑동 반지름 `0.29R` 로 뒤·위로 뻗어 `z = -1.35R`, `y = bodyY + 0.98R` 까지 간다.
등 장식이 놓일 공간과 같은 자리다.

**해결: 가방을 옆으로 맨다** (사용자 제안, 실측 검증 완료).

등 한가운데를 비켜 **왼쪽 앞옆구리**에 매면 충돌 자체가 사라진다. 꼬리는 등 정중앙에만 있기 때문이다.
동물별 예외가 필요 없어 카탈로그도 깨끗하다 — 7종 전부 같은 방향으로 걸린다.

⚠️ **반드시 왼쪽(−x)이다.** 도구 든 손이 오른쪽(`heldGroup.position.x = 0.78`)이라
오른쪽에 매면 도구와 부딪힌다.

### 확정 수치 ([sims/cosmetic-sim.html](../../../sims/cosmetic-sim.html) 검증)

| 항목 | 값 |
|---|---|
| 가방 방향 `BAG_DIR` | `(-0.80, -0.22, 0.48)` 정규화 |
| 표면 띄움 `SURF` | `1.06` |
| 가방 크기 `w` | `R * 0.76` |
| 바구니 반지름 `r` | `R * 0.44` |
| 어깨끈 두께 | `R * 0.078` (바구니 `R * 0.070`) |
| 매달림 `hang` | `-w * 0.26` (바구니 `-r * 0.48`) |

### ⚠️ 여기서 네 번 틀렸고 원인이 전부 같았다 — **몸은 타원체인데 원으로 계산했다**

| 시도 | 증상 | 원인 |
|---|---|---|
| 원형 링 하나로 어깨끈 | 배 앞뒤로 튀어나온 훌라후프 | 링은 원, 몸은 타원 |
| 방향벡터를 그대로 좌표로 | 끈이 통째로 사라짐 | 길이가 1 미만이라 몸 속에 묻힘 |
| 방향벡터 × 체형 배율 | 여전히 묻힘 | 타원체 표면 거리는 그렇게 안 나온다 |
| 정옆(`z=0`)에 매달기 | 끈 끝이 가방 직전에 잘림 | 몸 뒤로 돌아가 가려짐 |

**타원체 표면까지의 거리는 방정식을 풀어야 한다:**

```js
// 방향 (x,y,z) → 몸 표면 밖의 점. a,b,c 는 bodyScale
const t = 1 / Math.hypot(x / a, y / b, z / c);
const p = new THREE.Vector3(x * t * SURF * R, bodyY + y * t * SURF * R, z * t * SURF * R);
```

**끈의 경유점과 가방 앵커를 이 함수 하나로 잡아야 한다.** 좌표를 두 군데서 정하면 또 어긋난다.

### 어깨끈은 링이 아니라 **두 가닥**이다

가방 고리에서 앞으로 한 줄, 뒤로 한 줄이 오른쪽 어깨에서 만난다. 꼬리에 쓰는 `taperedTube` 를
그대로 재사용한다. (링 하나로는 위 표의 첫 줄처럼 훌라후프가 된다.)

※ 만약 링을 쓴다면: `THREE.Euler` 기본 순서 `'XYZ'` 는 Rz를 먼저 적용해서 `rotation.set(π/2, 0, tilt)`
가 **허리를 수평으로 감은 띠**가 된다. `rotation.order = 'ZYX'` 로 바꿔야 "눕힌 다음 기울임"이 된다.

### 슬롯 안에서 붙을 면을 아이템이 고른다

가방·바구니는 `side`, **망토만 `back`**. 망토는 넓은 천이라 꼬리가 위로 빠져나가도 어색하지 않다.

다른 여섯 종은 애초에 문제가 없었다 — 🐱고양이 긴 꼬리는 더 위로 빠지고, 🐶강아지는 말려 있고,
🐰토끼·🐻곰·🐼판다·🐤병아리는 꼬리가 작다.

## 4. 꾸미기 품목 (1차)

수량은 슬롯당 3~4종. 처음부터 많이 만들지 않는다 — 앵커 구조가 맞는지가 먼저다.

### 4-1. 🎩 머리 — 7종

| 아이템 | earSafe | 비고 |
|---|---|---|
| 🧶 털모자 | `dome` | 접힌 테두리 + 꼭대기 방울 |
| 🧢 캡 | `dome` | 앞챙. 챙은 `phiStart` 로 앞쪽 반원만 잘라 납작하게 누른다 |
| 🍄 버섯 모자 | `dome` | 넓은 갓 + 점 5개(그 이상은 환공포증). 점은 갓보다 밖(1.30 vs 1.26) |
| 👒 밀짚모자 | `dome` | 낮은 크라운 + 넓은 챙. **챙만 만들면 머리가 구멍으로 튀어나온다**(아래) |
| 💐 화관 | `low` | 꽃잎을 완전히 납작하게(0.14) 하면 옆에서 안 읽힌다 — **0.34 로 세운다** |
| 🍃 나뭇잎 머리띠 | `low` | 이마에 두른다. 잎은 띠를 따라 **눕혀야** 장식이 된다 |
| ⭐ 별 머리핀 | `low` | 옆머리. 뒤쪽에 박으면 정면에서 안 보인다 |

머리 위에 띠를 두를 때 **둘레 반지름은 `√(HR² − h²)`** 다(h는 그 높이). 이 값을 안 쓰면
띠가 머리에서 뜨거나 묻힌다.

### 4-2. 🧣 목 — 3종

| 아이템 | 가격 | 비고 |
|---|---|---|
| 🧣 목도리 | 900🪙 | 두툼하게(tube `0.34`) **두 겹**으로 감는다. 앞에 매듭 |
| 🔔 방울 목걸이 | 700🪙 | 놋쇠. **적도 이음매 + 아래 슬릿 + 위 고리** 셋이 있어야 방울로 읽힌다 |
| 🎀 나비 넥타이 | 850🪙 | 날개는 꼭짓점이 가운데를 향하는 사각뿔 둘 |

🐶 목줄 조형(`HR*0.92`)이 그대로 템플릿이다. **가장 싸게 만들 수 있는 슬롯.**

**나뭇잎 스카프는 뺐다** (사용자 판정).

### ⚠️ 구체에 천을 늘어뜨릴 수 없다

목도리에 자락을 앞으로 늘어뜨렸더니 **통째로 몸 속에 묻혔다.** 자락 끝이 `y=0.74` 인데
그 높이의 몸 가로반지름이 `0.45` 이고 자락은 `z=0.21` 이었다. 몸이 구체라 아래로 내려오는
천은 **어디에 둬도 묻히거나 붕 뜬다.**

→ **매듭 + 짧은 끝동**으로 대체한다. 저폴리에선 이쪽이 훨씬 깔끔하고 목도리로 잘 읽힌다.

### ⚠️ 목 장식은 그 높이의 **머리** 단면을 넘어야 한다

나비 넥타이를 `0.96r` 에 뒀더니 날개 뒷면(`0.252`)이 그 높이의 머리 단면(`0.309`)보다
안쪽이라 **나비가 머리에 파묻혔다**(🦊여우 기준). `1.28r` 이면 뒷면이 `0.361` 로 확실히 밖이다.

목 앵커 높이에서는 몸이 아니라 **머리가 더 굵다**(0.309 vs 0.247). 몸 기준으로 계산하면 틀린다.

### 금색은 광택이 아니라 색이다

방울은 `metalness 0` · `flatShading` 을 유지한 채 색으로만 놋쇠를 낸다.
[js/tool-tiers.js](../../../js/tool-tiers.js) 2단계 "금" 과 같은 팔레트를 쓴다 —
`0xc9a227` / 밝은면 `0xd9bc5c` / 어두운면 `0x9c7a1c`.

### 4-3. 🎒 가방

메신저 가방 · 바구니 (둘 다 왼쪽 옆구리) · 망토 (등)

가방류를 옆으로 맨 이유는 §3-3 — 등 한가운데는 🦊여우 꼬리 자리다.

### 4-4. 👣 발자국 — 등급 사다리 5종

걸을 때 지나온 자리에 남았다 사라지는 자국. 앵커가 아니라 **월드 공간 이펙트**다.

**값이 올라갈수록 바닥에 있던 게 공중으로 올라온다.** 그게 눈에 보이는 차이라
가격표가 설득력을 가진다.

| 등급 | 아이템 | 가격 | 무엇이 다른가 |
|---|---|---|---|
| 기본 | 🐾 발바닥 | 700🪙 | 바닥에 자국만. **동물마다 다르다**(아래) |
| 기본 | 💧 물방울 | 900🪙 | 젖은 자국 + 파문 한 겹 |
| 고급 | 🌸 꽃 | 1,500🪙 | 자국 자리에 꽃이 핀다 |
| 특별 | ⭐ 별 | 2,200🪙 | 바닥 별 + **떠오르는 작은 별 3개** |
| 특별 | ✨ 반짝이 | 2,600🪙 | 바닥 자국 없이 **빛 알갱이 6개가 공중으로** |

2차(시즌 한정)는 같은 구조에 색과 조각만 바꾸면 된다 — 눈송이 · 낙엽 · 무지개.

### 🐾 발바닥은 동물마다 다르다

같은 자국을 7종이 공유하면 "내 캐릭터가 남긴 것" 이 아니라 그냥 스티커가 된다.
**상품은 하나지만 조형은 캐릭터를 따라간다.**

| 동물 | 자국 |
|---|---|
| 🦊🐶🐱 | 패드 + 발가락 4 |
| 🐻🐼 | 같은 구조를 **크고 뭉툭하게**(패드 `0.74` · 발가락 `0.31`) |
| 🐰 | **길쭉한 뒷발** — 패드가 길고(`z` 1.55배) 발가락이 작다 |
| 🐤 | **세 갈래 새발자국** — 패드가 없고 뒤에 며느리발톱 |

꽃 · 별 · 반짝이는 캐릭터와 무관한 이펙트라 **공통**이다.

### 구현 제약

- 플레이어가 일정 거리(`0.6`) 이동할 때마다 하나 생성, `1.2초` 동안 페이드아웃
- **좌우로 번갈아** 찍는다(`±0.075`). 한 줄로 찍으면 자국이 아니라 점선이다
- 동시 표시 상한 **12개**, 풀에서 재사용 — 매번 생성·파괴하면 드로우콜과 GC가 튄다
- **실내·클로즈업·미니게임 중에는 끈다** (바닥이 없거나 카메라가 붙는다)
- 밤에도 블룸 임계 0.85를 넘지 않는다 (§10-1). 빛나는 특별 등급이 특히 걸린다 —
  `starLit` · `sparkLit` 이 실제로 두 번 초과했다

### ⚠️ 자국은 작아야 자국이다

1차 자국은 **캐릭터 몸통만 했다** — 꽃 하나가 `0.34` 폭인데 플레이어 몸 반지름이 `0.52` 다.
기준 반지름은 **`0.10`**(월드 단위).

### ⚠️ 팔면체를 납작하게 누르면 별이 아니라 마름모다

별을 `OctahedronGeometry` + `scale.y 0.12` 로 만들었더니 그냥 마름모였다.
**삼각뿔 둘을 60° 엇갈려** 겹쳐야 6각 별로 읽힌다.

## 5. 🏪 판매처 — 마을에 서는 가게

꾸미기와 펫을 **같이** 파는 곳. 기존 상점들(🛒`#shop-menu` 팔기/사기 · 🧰뱃사공 창고 ·
🧩집 구성품)과 달리, 이 가게는 **마을에 실제로 서 있고 밖에서 안이 보인다.**
주인이 그 안을 돌아다니는 게 보이는 것이 이 가게의 성격이다.

시안: [sims/shop-sim.html](../../../sims/shop-sim.html)

### 5-1. 이 게임에 없던 패턴이다

집·박물관·전시실은 전부 `interiorFloors` 그룹을 **토글**한다 — 들어가면 실외를 끄고 실내를 켠다.
가게는 그게 아니라 **앞이 열린 디오라마**로 실외 씬에 그대로 선다. 씬 전환이 없어 오히려 단순하다.

이게 가능한 전제는 **카메라가 고정**이라는 것이다:

```
camOffset = (0, 14, 16)        // js/game.js:12231 — 상수
내려보는 각 = atan(14/16) = 41.2°
시선은 늘 −Z        // js/game.js:7317 "정면을 카메라 쪽으로"
```

정면을 **+Z** 로 두면 플레이어가 어디 있든 안이 보인다. 각도가 돌 걱정이 없다.

### 5-2. ⚠️ 41°는 생각보다 위에서 내려다본다

레퍼런스 이미지는 거의 눈높이 아이소메트릭이라 안이 훤히 보이지만, 41.2°에서는 다르다.
**무엇이 무엇을 가리는지는 눈이 아니라 계산으로 판정한다:**

> 어떤 지점을 보려면, 가리는 물체의 앞 가장자리까지 **수평거리가 높이차의 1.14배**
> (`1/tan 41.2°`) 이상이어야 한다.

지붕안 네 가지를 세워 41.2°로 비교한 결과:

| 안 | 결과 |
|---|---|
| A 평지붕 전체 + 차양 (레퍼런스 그대로) | ❌ 지붕이 내부를 완전히 덮는다 |
| **B 앞 처마 물림 (지붕을 뒤 60%만)** | ✅ **채택** — 안이 보이면서 평지붕·파라펫이 남는다 |
| C 앞 상인방 제거 | ❌ A와 거의 같다. 막던 건 상인방이 아니라 **지붕**이었다 |
| D 지붕 없음 | 보이지만 레퍼런스의 모양이 아니다 |

### 5-3. ⚠️ 주인이 안 보였던 진짜 이유는 지붕이 아니었다

차양을 의심했지만 계산해 보니 아니었다 — 주인이 안쪽에 있으면 41.2° 시선이 차양보다 **위로**
지나간다. 진짜 원인은 **주인을 게임 주민보다 작게 만든 것**이었다.

| | 키 |
|---|---|
| 게임 주민 (`js/game.js:15378`) | 몸 R 0.50(y 0.55) · 머리 R 0.38(y 1.15) → **1.53** |
| 처음 만든 주인 | 몸 R 0.34(y 0.38) · 머리 R 0.26(y 0.80) → **1.06** |

카운터 상판이 정확히 `1.05` 였다. 주인 머리 꼭대기 `1.06` — **딱 가려졌다.**

→ **가게 안에 두는 NPC 는 게임 주민과 같은 크기로 만든다.** 새로 그리지 말고
`js/animal-faces.js` 의 `buildAnimalHead` 를 그대로 쓴다(복제하면 게임과 갈린다).

### 5-4. 배치 규칙

| 요소 | 규칙 |
|---|---|
| 정면 | 왼쪽 **문 베이**(주인 동선) + 오른쪽 **창**(카운터) |
| 차양 | **창 위에만.** 정면 전체에 두면 문 베이까지 덮어 그 아래 주인이 가린다 |
| 카운터 | 창 쪽으로 몰아 문 베이를 비운다 |
| 주인 배회 | **문 베이 안에서만**(`x −1.67 ~ −1.03`). 창 허리벽까지 넘어가면 몸통이 잘린다 |
| 간판 | **건물 옆으로 돌출.** 벽에 붙이면 지붕 안쪽과 겹쳐 뜨고, 앞으로 내면 문 베이에 묻힌다 |
| 문짝 | 높이 `2.05`(주민 키 1.53 기준). `2.6` 은 간판을 스친다 |

간판 글자는 **넣지 않는다.** 한글을 구우면 i18n 사전이 또 필요하고 영어판에서 어긋난다.
대신 판 위에 **모자 부조**를 얹어 무슨 가게인지 보인다. 문 베이 뒷벽의 **모자걸이**도 같은 역할이다.

### 5-5. 색은 새로 만들지 않는다

| 쓰임 | 값 | 출처 |
|---|---|---|
| 벽 | `0xf2e4cf` (휘도 0.900) | 카페 회벽 `0xfaf8f4`(0.973)에 노란기를 더해 따뜻하게 |
| 그늘면 | `0xddc9ac` | |
| 차양 분홍 | `0xe0b0b0` | `WALL_COLORS` 에 이미 있는 핑크 |

⚠️ 벽 휘도가 블룸 임계 `0.85`(`UnrealBloomPass(res, 0.55, 0.9, 0.85)`)를 넘지만,
이건 새 문제가 아니라 **카페가 이미 0.973 으로 서 있는** 게임의 기존 톤이다. 오히려 낮췄다.

**⚠️ 조명을 시뮬에서 임의로 주면 안 된다.** 시뮬 하늘을 파랗게(`0xdfefff`) 줬더니 크림색이
회색으로 죽었다. 게임은 하늘이 **순백**이다 — `HemisphereLight(0xffffff, 0xbfe8c9, 0.9)` ·
`DirectionalLight(0xffe9c4, 1.1)`([js/game.js:2961](../../../js/game.js)). 시뮬은 이 값을 그대로 쓴다.

### 5-6. 구현 시 주의

- **가게 안은 어둡다.** 지붕과 벽이 빛을 막는다. 전시실에서 이미 겪은 문제 —
  세기만 올리면 안 되고 **세기·색·광원 자리** 3종 세트를 같이 잡는다. 등불 하나를 두면 밤에도 산다
- **차양 줄무늬는 정점색 한 덩어리**로 굽는다. 조각마다 메시로 만들면 드로우콜이 튄다
  (카페가 재질별 병합 후 24)
- **창 안 작은 소품은 그림자를 끈다.** 저폴리에서 작은 소품 그림자는 지글거린다
- 주인은 기존 주민 구조(`home` + `wanderTimer`)를 그대로 쓰되 **배회 반경만 좁힌다**

### 5-7. 판매 UI 는 아직 미정

가게 건물은 정했지만 **누르면 뜨는 창**은 아직이다. 기존 상점(`#shop-menu`)은 글자 목록이라
꾸미기에는 모자란다 — 썸네일, **내 캐릭터에 입혀 보는 미리보기**, 보유/장착 상태, 슬롯 탭이 필요하다.
모바일에서 어떻게 접히는지가 특히 관건이다(3단 레이아웃 규칙).

**§15 열린 결정에 올린다.**

### 5-1. 왜 경계를 먼저 긋는가

[js/farm-worker.js](../../../js/farm-worker.js)의 일꾼은 이미 **동물**이고, 이미 **밭일을 한다**:

**갈라 놓는 축은 "자율 vs 지시"와 "오프라인 vs 접속 중"이다.**

### 5-2. 경계표

| | 🧑‍🌾 일꾼 (고용) | 🐾 펫 (동반자) |
|---|---|---|

| 오프라인 | **12시간 자동 정산**(`MAX_CATCHUP_H`) | 안 함 |
| 비용 | 초빙료 120🪙 + 일급 15~55🪙 | 한 번 구매, 무보수 |

| 브레이크 | 돈 | **쿨다운(지침)** |

접속을 끊고 12시간을 버는 건 여전히 일꾼만 할 수 있다. 일꾼 경제는 산다.

### 6-2. 낚시 보조도 같은 원칙

**잡아 주지 않는다.** 미니게임을 대신하면 재미를 파는 게 아니라 없애는 것이다.

- 입질을 한 박자 먼저 알려준다
- 놓친 물고기를 **하루 1회** 물어온다

### 6-3. 조작

펫은 기본적으로 따라다닌다. 밭 근처에 서면 프롬프트 줄에 `🐾 맡기기` 가 뜬다.
누르면 반경 내 칸의 잡일을 차례로 하고, 다 하면 다시 따라온다.

⚠️ **안내는 컨텍스트 슬롯이나 프롬프트 줄에만 넣는다.** 모바일 3단 레이아웃 규칙이다 —
월드 라벨로 띄우면 다른 라벨을 가린다.

### 6-4. 쿨다운이 브레이크다

일급이 없는 대신, 연속으로 시키면 지쳐 쉰다. 수치는 §15.

## 8. 펫 성장

### 7-1. 성장 축

일꾼과 같은 방식 — **누적 작업 횟수**(일꾼은 `GRADES[].need` = 0 / 120 / 400).
펫은 일을 덜 하므로 문턱이 더 낮아야 한다. 수치는 §15.

### 7-2. 성장하면 무엇이 바뀌는가

**외형만 바뀐다. 능력은 안 바뀐다.**

능력이 같이 자라면 "성장한 펫 = 강한 펫"이 되고, 그러면 §6의 경계가 다시 흐려진다.
성장은 **애착의 보상**이지 성능의 보상이 아니다.

### 7-3. 실루엣이 바뀌어야 한다

색만 바꾸면 성장이 안 읽힌다. 방향마다 **윤곽이 바뀌는 축**을 하나씩 못박는다 (§9-2).

## 9. 펫 조형 — 후보 4종 (**미확정**)

### 8-1. 왜 네발 동물을 안 쓰는가

화면에 이미 도는 동물이 많다:

- 플레이어 선택 7종: 🦊여우 🐶강아지 🐰토끼 🐱고양이 🐻곰 🐼판다 🐤병아리
- 일꾼 3종: 🦫두더지 🐹햄스터 🐿️다람쥐
- 주민(🦉올빼미 등) · 🐔닭장 · 텃밭 방문객 도감 · 밤손님 🐗🦝

**네발 포유류와 설치류 자리는 다 찼다.** 여기서 또 동물을 고르면 "저게 펫인가 일꾼인가 내 캐릭터인가"가
헷갈린다. 이 게임은 베타에서 이미 *"누가 누군지 모르겠다"* 를 맞았다.
그래서 후보는 전부 **지상 네발 실루엣을 피한 것**이다.

### 8-2. 후보와 성장 축

| 후보 | 성장 축 (1 → 2 → 3단계) | 강점 | 약점 |
|---|---|---|---|
| ✨ **정령** | 공전 파편 0 → 3 → 6 + 후광 | 로스터와 0 충돌. 색만 바꿔도 새 상품 | 쓰다듬을 형태가 없다 |
| 🐦 **새** | 꽁지깃 1 → 3 → 5장 + 볏 | 쓰다듬는 맛. 낚시 보조가 자연스럽다 | 🐤병아리·🦉올빼미와 거리 두기 필요 |
| 🫘 **흙꼬마** | 민둥돌 → 이끼 → 꽃·버섯 | 로스터와 100% 무충돌. **성장이 제일 잘 읽힌다** | 귀여움이 ①②에 밀릴 수 있다 |
| 🍃 **잎사귀 정령** | 잎 1 → 3 → 5장 + 겉껍질 망토 | 정령의 신비 + 만질 형태 | 조형이 제일 까다롭다 |

### 8-3. 시안 검수 상태

[sims/pet-sim.html](../../../sims/pet-sim.html) 에 4종 × 3단계 = 12개 조형을 세워 두었다.
방향 필터 · 회전 · 밤 조명 · **캐릭터 대비 실루엣**(플레이어 체형을 흐리게 세워 크기를 잰다)이 붙어 있다.

2차 수정까지 반영돼 있다 — 하늘 배경, 블룸 초과색(`shard`) 교정, 뒤집혀 있던 잎 각도,
허리를 감던 이끼 벨트, 떠 있던 팔, 얼굴을 덮던 겉껍질, 토성 고리 같던 후광,
눕혀서 안 보이던 꽁지깃.
**3차 캡처는 아직 안 했다.** 종 선택은 §15 열린 결정.

⚠️ **확정 뒤 반드시 할 일** — 팔레트와 조형 수치를 `js/pet/art.js` 로 옮기고 시뮬이 그걸 `import` 하게 바꾼다.
시안이 복제본으로 남으면 게임과 갈린다 (`tool-tier-sim`에서 낚싯대 0단계 값이 갈려 역이식된 사고가 있었다).

## 10. 조형 규칙

이 저장소에서 이미 비싸게 배운 것들이다. 꾸미기와 펫 **양쪽 모두**에 적용한다.

1. **블룸 임계 0.85** — 휘도가 이 값을 넘는 색을 넓은 면에 칠하면 후광이 형태를 삼킨다.
   `luma()` 는 [js/tool-tiers.js](../../../js/tool-tiers.js) 와 같은 식(Rec.709)을 쓰고,
   **팔레트 전 색을 부팅 시 검산해 콘솔에 남긴다.** (시뮬은 이미 그렇게 한다)
2. **부속을 꽂지 말고 형태로 승격한다** — 이끼는 붙이는 게 아니라 덮는다. 잎은 몸에서 자라 나온다.
3. **눈은 작고 어둡게.** 크고 흰 눈은 인형이 아니라 캐릭터가 된다.
4. **면이 겹치면 줄무늬가 인다.** 덮는 조각은 확실히 띄우거나 `depthWrite: false` 로 간다.
5. **촘촘한 반복은 환공포증으로 읽힌다** — 파편·깃털·꽃잎은 6을 넘기지 않는다.
6. **재질은 기존과 같은 결로** — `clay`(저폴리 각진 면) / `plush`(봉제인형 톤, 캐릭터와 같은 재질).

## 11. 파일 구조

game.js는 15,901줄이다. **새 코드를 여기 몰지 않는다.**
규칙은 모듈 + 테스트, 렌더는 기능 디렉터리.

```
js/cosmetics/
  catalog.js      순수 데이터 — 품목·슬롯·가격·earSafe.   테스트 있음
  equip.js        순수 규칙 — 장착/해제, 슬롯 검증, 보유 판정.  테스트 있음
  art.js          조형 — 앵커에 꽂을 메시를 만든다 (THREE 의존)
  trail.js        👣 발자국 풀 (THREE 의존)

js/pet/
  rules.js        순수 규칙 — 할 일 선택, 반경 판정, 쿨다운, 성장 단계.  테스트 있음
  art.js          조형 + 팔레트 — 시뮬과 공유하는 단일 소스 (THREE 의존)
  render.js       따라다니기·이동·연출 (THREE 의존)
```

**순수 모듈(`catalog` · `equip` · `rules`)에는 `npm test` 로 도는 테스트를 붙인다.**
`farm-worker.js` 가 그렇게 돼 있고, 밸런스 수치를 테스트에 못박아 두면 나중에 조용히 어긋나지 않는다.

`game.js` 가 하는 일은 **연결뿐**이다: `buildAnimalMesh` 가 앵커를 반환하게 고치고, 상점 UI를 띄우고,
프롬프트 줄에 `🐾 맡기기` 를 건다.

## 12. 세이브와 마이그레이션

### 11-1. 새 필드

```js
gameState.cosmetics = {
  owned: ['hat_flower', 'neck_scarf'],          // 산 것 (영구)
  equipped: { head: 'hat_flower', neck: null, back: null, trail: null },
};
gameState.pet = {
  kind: 'spirit',        // 종 — §15에서 확정
  name: '',              // 유저가 지은 이름(선택)
  works: 0,              // 누적 작업 횟수 → 성장 단계
  restUntil: 0,          // 쿨다운 종료 시각(epoch ms)
  owned: ['neck_bell'],  // 펫에게 채운 꾸미기 — 캐릭터와 같은 앵커를 쓴다
};
```

`pet`이 `null`이면 아직 안 샀다는 뜻이다.

### 11-2. ⚠️ 마이그레이션은 반드시 `js/save-migrate.js` 를 거친다

기존 세이브에는 이 필드가 없다. 없는 필드를 그대로 읽으면 `undefined` 가 퍼진다.
**읽기 실패를 "신규 유저"로 오인해 마을을 덮어쓴 사고가 있었다**([js/save-guard.js](../../../js/save-guard.js)).
없는 값은 기본값으로 채우되, **"필드가 없음"과 "읽기 실패"를 반드시 구분**한다.

### 11-3. 현금이 붙는 날 필요한 것 (이번엔 안 한다)

세이브는 지금 **클라이언트 권위**다 — [js/supabase-client.js](../../../js/supabase-client.js) 의
`writeSave()` 가 `gameState` 를 통째로 `upsert` 한다. 유료 상품이 붙는 순간, 웹에서 콘솔로
`cosmetics.owned` 에 아이템을 밀어 넣고 저장하면 끝이다.

그래서 **현금 결제를 여는 날, 구매 이력만은 별도 서버 원장(클라이언트가 못 쓰는 테이블)으로 가야 한다.**
지금은 코인 경로뿐이라 필요 없지만, 카탈로그 `id` 를 처음부터 안정적인 키로 잡아 두면 그날 옮기기 쉽다.

## 13. 트래킹

**새 기능은 트래킹을 구현과 같은 밀도로 만든다.** (`quest_id` 누락 사고의 교훈)

| 이벤트 | 파라미터 | 시점 |
|---|---|---|
| `shop_enter` | `from`(walk/minimap) | 🏪 가게에 들어섬 |
| `shop_open` | `tab`(cosmetics/pet) | 상점 창 열기 |
| `cosmetic_buy` | `item_id`, `slot`, `price_coins`, `coins_after` | 구매 성공 |
| `cosmetic_equip` | `item_id`, `slot`, `action`(on/off) | 장착·해제 |
| `pet_buy` | `pet_kind`, `price_coins` | 펫 구매 |
| `pet_command` | `pet_kind`, `stage`, `task`, `plots_done` | 맡기기 1회가 끝날 때 |
| `pet_stage_up` | `pet_kind`, `stage`, `works` | 성장 |

규칙:

- **축은 전부 키값**이다. `item_id`는 `'밀짚모자'` 가 아니라 `'hat_straw'`. 표시 이름은 i18n이 정한다
- **생명주기 전 구간**을 남긴다 — 열기 → 구매 → 장착까지. 구매만 남기면 "왜 안 샀는지"를 못 본다
- **다음 날 BigQuery에서 재검증**한다. 보내는 것과 쌓이는 것은 다를 수 있다

## 14. 드로우콜 예산

현재 마을이 567 근처다(1차 최적화 후). 이번에 늘어나는 것:

| 항목 | 증가 | 대책 |
|---|---|---|
| 꾸미기 장식 | 슬롯당 1~3 (최대 +9) | 장착한 것만 만든다. 해제하면 정리 |
| 👣 발자국 | **+12** (병합했을 때) | 아래 — 병합하지 않으면 **최대 +84** |
| 🐾 펫 | 3단계에서 최대 +12 | 파편·깃털을 6 이하로 (§10-5) |

### ⚠️ 발자국은 **자국 하나를 한 메시로 병합**해야 한다

처음엔 "동시 12개 상한이니 +12" 로 잡았는데 **틀렸다.** 자국 하나가 메시 여러 개다:

| 아이템 | 자국 1개당 메시 | × 12 |
|---|---|---|
| 💧 물방울 | 2 | 24 |
| 🐾 발바닥 | 5 (패드 + 발가락 4) | 60 |
| ⭐ 별 | 5 (삼각 2 + 떠오르는 별 3) | 60 |
| 🌸 꽃 | 6 (꽃잎 5 + 수술) | 72 |
| ✨ 반짝이 | 7 (바닥 원 + 알갱이 6) | **84** |

현재 마을이 567 근처인데 반짝이 하나로 **15% 가 늘어난다.** 받아들일 수 없다.

**자국 하나를 만들 때 조각들을 병합해 단일 메시로 굽는다**(`BufferGeometryUtils.mergeGeometries`).
그러면 아이템 종류와 무관하게 **12 드로우콜**로 고정된다.
색이 두 가지 이상이면(꽃잎 2색, 별 2색) **정점색**으로 처리한다 — 🦊여우 꼬리가 이미 그렇게 한다.

풀에서 재사용할 때도 병합된 지오메트리 하나를 복제해 쓰고, 투명도만 갱신한다.

⚠️ **공유 자원 `dispose` 규칙** — 장식이 공유 재질·지오메트리를 쓰면 해제할 때 `dispose` 하면 안 된다.
다른 곳에서 쓰던 것까지 검게 만든다. 공유 자원은 모듈이 만들어 들고 있고, 인스턴스만 버린다.

## 15. 열린 결정 (구현 전에 정해야 함)

1. **펫 종** — ✨정령 / 🐦새 / 🫘흙꼬마 / 🍃잎사귀 정령 중 하나.
   시안 3차 캡처 후 나란히 비교해서 고른다
2. **가격 수치** — §2-2 구간을 실제 숫자로. 기존 코인 싱크 표와 나란히 놓고 정한다
3. **펫 성장 문턱** — 누적 작업 몇 회에 2·3단계인가 (일꾼은 120 / 400)
4. **펫 반경과 쿨다운** — 몇 칸까지, 몇 칸 하고 얼마나 쉬는가
5. **🏪 판매 UI** — 가게를 누르면 뜨는 창(§5-7). 썸네일·미리보기·슬롯 탭·모바일 접힘
6. **UI 문구** — 버튼·라벨의 한국어 후보를 **먼저 검수받는다.** 만들고 나서 고치면 i18n 사전까지 두 번 고친다.
   모바일 실측 필수 (`🐾 맡기기` 가 프롬프트 줄에서 안 넘치는지)
