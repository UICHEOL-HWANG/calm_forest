# 🦋 설계형 수집 — 텃밭 방문객 도감

작성 2026-09-17 · 상태: 설계 확정, 구현 미착수(2026-09-18 시작 예정)

## 배경

지금 도감 12개 카테고리는 전부 **행동 트리거**다. `dexDiscover(cat, id)` 하나로 "잡거나 캐거나 거두면 등록"(`js/game.js:1191`). 수집 = 반복 노동이다.

포코피아는 **조건 트리거**다 — 서식지를 설계하면 포켓몬이 스스로 찾아온다. 다만 레시피 200개를 손으로 짜서 구현했고, 그 대가로 "체크리스트 같다"는 비판을 받았다.

이 설계는 조건 트리거를 가져오되 레시피를 짜지 않는다.

## 확정 전제 (재론 불필요)

1. **위치는 개인 텃밭 필드** (`FARM = (0,0,84)`). 마을 본체·신규 맵은 기각.
2. **레시피 방식 기각, 환경 점수 방식 채택.**
3. **신규 카테고리 `visitor` 한정.** 기존 12종은 행동 트리거 그대로 — 전환하지 않는다.
   행동형의 유일한 장점은 **보장**이다(반복하면 언젠가 얻는다). 조건형은 보장이 없고 실패 피드백이 침묵이다.
   입구이탈 59.4%인 게임에서 신규 유저 도감까지 조건형으로 바꾸면 이탈이 늘어난다.
4. **등록은 1회, 방문은 반복.** 조건이 유지되면 계속 온다.
   다 모은 뒤에도 정원 설계가 의미를 잃지 않게 하는 장치다. 관리 부담은 0(머물지 않고 떠난다).
5. **`fear`는 국소.** 밤손님 방어(반경 9)와 분리한다 — 작물을 잃는 강제 교환은 코지가 아니라 벌칙이다.
6. **신규 3D 에셋은 방문객 본체 4종만.**

## 환경 점수 모델

### 원칙 — 태그 소스는 세이브에 남는 것만

런타임 전용 상태(`watered`, `wetUntil`, `tree.hp`, `plot.digAt`)는 태그 소스가 될 수 없다.

`plot.wetUntil`은 `clock.elapsedTime` 기반이라 세션이 끊기면 사라지고, `WET_TIME = 9`라 물 준 흙은 **9초**만 촉촉하다(`js/game.js:138, 12470`). 방문객 스폰 지연이 6~14초이므로 물주기를 `damp` 소스로 쓰면 🐸는 뜨기도 전에 조건이 사라져 **영원히 오지 않는다.**

### 태그표

| 태그 | 소스 | 값 | 저장 위치 |
|---|---|---|---|
| `nectar` 🌷 꽃 | 꽃밭 | +2 | `gameState.outdoor` |
| `light` 🏮 빛 | 정원등 · 화로 · 정령 등불 | 각 +2 | `gameState.outdoor` |
| `shelter` 🧱 은신 | 돌담 +2 · 울타리 +1 | | `gameState.outdoor` |
| `damp` 💧 물기 | 💧우물(반경 5) +3 · 🌧️비 오는 날 밭 전체 +2 | | `gameState.outdoor` / `WEATHER` |
| `shade` 🌑 그늘 | 둘레 나무 | +2 | `farm.stage` 파생 (`perimeterTrees()`) |
| `food` 🌾 먹이 | 다 자란 작물 (`state === 'mature'`) | +2 | `gameState.plots` |
| `fear` 🎃 공포 | 허수아비 (반경 6) | +3 | `gameState.outdoor` |

미채택: `bare`(빈 흙), `stone`(디딤돌) — 쓰는 방문객이 없다. 필요해지면 그때 붙인다.

### 반경

`CELL = 2` (`js/farm-building.js:13`).

| | 반경(월드 유닛) | 의미 |
|---|---|---|
| 일반 태그 합산 | **3** | 정확히 3×3 밭칸 |
| `fear` | **6** | 환경 반경의 2배 — 피하려면 실제로 옮겨야 한다 |
| 밤손님 방어 (기존, 불변) | 9 | `js/game.js:11363` |

**이 세 숫자에서 설계의 핵심 장치가 나온다.** 1단계 텃밭 반경이 6이므로, 허수아비를 울타리 밖으로 두 발짝 물리면(중심에서 8) `fear`는 밭 중앙에 닿지 않고(8 > 6) 밤손님 방어는 그대로 걸린다(8 < 9). 희생은 없지만 "아무데나"도 안 되는 배치 문제가 된다. 플레이어는 미터를 보며 스스로 이걸 찾아낸다.

### 그늘이 가장자리에만 있다

`shade`가 둘레 나무에서만 나오므로 그늘은 밭 **가장자리에만** 존재한다. 🦔와 🐸가 자연스럽게 변두리로 유도된다 — 중앙은 농사, 가장자리는 생태. 공간이 의미를 갖는다. 의도된 결과이므로 `shade` 소스를 늘릴 때 이 성질이 깨지지 않는지 확인한다.

## 방문객 4종

```js
{ id:'butterfly', ico:'🦋', name:'호랑나비',  need:{ nectar:3 },          block:{ fear:1 }, when:'day'  }
{ id:'sparrow',   ico:'🐦', name:'참새',      need:{ food:2 },            block:{ fear:1 }, when:'day'  }
{ id:'hedgehog',  ico:'🦔', name:'고슴도치',  need:{ shelter:3, shade:2 },                  when:'night'}
{ id:'frog',      ico:'🐸', name:'청개구리',  need:{ damp:4, shade:1 },                     when:'rain' }
```

난이도 곡선:

| | 필요한 것 | 난이도 |
|---|---|---|
| 🦋 | 꽃밭 2개 | 아주 쉬움 |
| 🐦 | 작물 하나 다 키우기 | 쉬움 |
| 🦔 | 가장자리에 돌담 2개 · 밤 | 중간 |
| 🐸 | 💧우물(🪙100, 측량소 해금) + 밭 가장자리 + 비 오는 날 | 어려움 |

🐸만 하루 상수 `WEATHER`에 걸린다(약 20%의 날, `js/game.js:158` — 날짜 해시라 전 유저 동일). 이대로 둔다: 4종 중 하나는 깊어야 수집이 의미를 갖고, `FORECAST`(내일 예보)가 이미 공개돼 있어 **"내일 비 온대 → 오늘 우물 옆을 비워두자"** 가 기존 재방문 훅에 그대로 얹힌다.

## 외형

기존 캐릭터 톤(플러시 인형체)에 맞춘 로우폴리 소형. 4종 모두 **머리가 몸의 대부분**을 차지하는 비율로 통일한다.

### 🐸 청개구리 (2026-09-17 레퍼런스 확정)

사용자가 스타일 레퍼런스를 지정했다. **레퍼런스 이미지 자체는 워터마크가 박힌 스톡 에셋이므로 사용하지 않는다** — 아래 특징만 가져와 직접 만든다.

| 요소 | 사양 |
|---|---|
| 실루엣 | 몸통 없이 **둥근 머리 하나**. 가로로 약간 넓은 타원(대략 1 : 0.9) |
| 눈 | **머리 윤곽 위로 튀어나온** 큰 흰 구 2개 + 검은 동공. 개구리 인상의 핵심 |
| 동공 | 정면 고정, 흰자 대비 약 40% 크기. 하이라이트 없음 |
| 콧구멍 | 눈 사이 아래 작은 검은 점 2개 |
| 입 | 아래로 볼록한 **굵은 곡선 하나**. 두께가 있어야 인상이 산다 |
| 볼터치 | 연분홍 사선 2줄씩 양볼 |
| 색 | 연두 계열 단색. 아웃라인 없음 — 검정은 눈·코·입에만 |

**주의:** 정면 2D 도안이라 3D로 옮길 때 측면이 빈다. 눈은 별도 구체 2개로 붙이고, 입·콧구멍·볼터치는 텍스처나 얕은 디칼로 처리해 정면성이 유지되게 한다.

나머지 3종(🦋🐦🦔)의 외형 사양은 미정 — 구현 착수 전에 같은 형식으로 확정한다.

## 생명주기

```
조건 충족 지점 발생
   ↓  6~14초 랜덤 지연              ← 즉시 뜨면 싸구려가 된다
페이드인 · 동시 최대 2마리
   ↓  플레이어가 반경 2.5 안으로
dexDiscover('visitor', id)  — 미등록일 때만 · ✨반짝임 · 토스트
   ↓  등록 여부와 무관하게 25초 후
페이드아웃
```

- **텃밭 체류 중에만** 출현한다. 오프라인 방문·흔적 없음(서버 판정이 필요해져 복잡도가 급증한다).
- **재방문**: 조건이 유지되면 계속 온다. 등록만 1회.
- **재평가**: 장식 배치·이동, 물주기, 수확, 날짜 전환에 dirty 플래그 → **1초 스로틀**. 매 프레임 계산 없음. 최대 11×11 = 121칸이라 비용은 무시 가능.
- **렌더**: 방문객 메시는 `farmGroup` 자식으로 넣는다 — 텃밭을 나가면 같이 숨는다. 동시 2마리 × 1~2 메시라 드로우콜 영향 없음.

## 안내

### 도감 방문객 탭

미발견은 **실루엣 `???`**, 조건 비공개. 발견 후 조건 **전부 공개** — 재현 가능해야 정원 설계가 의미를 갖는다.

### 배치 미터 — 장식을 놓거나 옮기는 중에만

상시 HUD로 두면 시끄럽고 모바일 3단 레이아웃 규칙(안내는 컨텍스트 슬롯 또는 프롬프트 줄)에도 맞지 않는다. 정보가 필요한 순간은 정확히 배치할 때다.

```
🌿 이 자리
  🌷 꽃 ●●●●●●   💧 물기 ──
  🌑 그늘 ●●      🎃 공포 ●●●
```

**현재치는 정직하게 보여주되 목표치는 보여주지 않는다.** 은유로 쓰지 않는다 — "꽃향기가 진하다" 식은 유저가 못 알아듣는다.

포코피아가 "체크리스트 같다"고 비판받은 건 정보를 많이 줘서가 아니라 **정확한 조합을 강요해서**다. 환경 점수 방식은 이미 그걸 해결했다(대충 꽃밭이면 온다). 숫자를 숨기면 난이도가 아니라 불친절만 늘어난다.

### 근접 신호 — 침묵 방지

목표치를 안 보여주므로 "왜 안 오지"에 답할 장치가 필요하다.

미발견 방문객의 조건을 **70% 이상** 채우면 그 실루엣이 반응한다.

> `❓ 무언가 맴돌다 갔어요 — 무서워하는 것 같아요`

막는 요인을 **하나만** 집는다. 정답은 안 알려주고 방향은 알려준다.

## 연결 지점

### ⚠️ 함정 — 큐레이터가 🐸를 집으면 그날 의뢰가 막힌다

`js/museum.js:73`에 같은 이유의 방어가 이미 있다.

```js
// ⚠️ 집으면 안 되는 카테고리
//   · weather — "그 날씨인 날 접속" 이라 오늘 안에 맞출 수가 없다
```

🐸는 정확히 같은 문제다(비 오는 날 20%). 나머지 3종도 장식 구매·배치가 선행돼야 한다. **`DEX_NEVER`에 `'visitor'`를 추가한다.** 안 하면 `dex_one` 의뢰가 그날 통째로 막힌다.

### 박물관은 2층

`tests/museum.test.mjs`가 두 가지를 잠그고 있다.
- `MUSEUM_FLOORS.length === 4` → **새 층을 만들 수 없다**
- 모든 도감 카테고리가 어느 한 층에는 들어가야 한다 → **배정이 필수다**

🍄채집물 🌟반딧불이 🪏땅속 🐾흔적과 같은 자연 계열이므로 2층이 맞다. 3층 게이트(`need: 9`)가 이론상 느슨해지지만, 방문객은 장식 구매가 선행이라 그 시점엔 이미 지나 있다.

### 기존 유저 영향

`DEX_TOTAL` 33 → 37.

- `awardBadge()`는 **부여만 하고 회수하지 않는다**(`js/game.js:1263`) → 기존 `dex_master` 배지 유지
- 완성 보상 재지급은 `!gameState.badges.dex_master`가 막는다(`:1201`)
- 유일한 변화는 카운터가 `33/37`로 보이는 것 → **📮소식함 공지 1건**으로 안내

`collect_dex` 퀘스트는 `dexCount()`를 읽는 상태형이라 **코드 변경 0**으로 자동 반영된다(`js/game.js:14333`).

### 저장

**새로 저장하는 것은 `dex.visitor` 하나뿐이다.**

환경 점수는 `gameState.outdoor` + `plots` + `farm.stage`에서 매번 파생한다. 박물관이 해금 상태를 저장하지 않고 계산하는 것과 같은 원칙이다(`js/museum.js:9`) — 저장하면 어긋날 수 있고, 계산하면 언제나 일치한다.

재접속 시: 꽃밭 위치가 복원됨 → `envAt()`이 다시 합산 → 같은 값. 점수를 저장하면 오히려 "꽃밭을 옮겼는데 점수는 옛날 값"이 생긴다.

## 트래킹

새 기능은 구현과 같은 디테일로 계측한다. **축은 키값이다.**

```
habitat_meter    { farm_stage, tags }          미터를 봤다
visitor_nearmiss { visitor, blocker }          70% 왔는데 막혔다
visitor_spawn    { visitor, farm_stage }       실제로 왔다
dex_discover     { category:'visitor', entry } 등록 — 기존 함수가 이미 발사
```

`blocker`가 튜닝의 핵심이다. "🐸에서 다들 `damp`에 막힌다"가 보이면 물 태그 값을 올린다.

퍼널 4단계: 미터 노출 → 근접 → 출현 → 등록.

- **i18n**: 새 문구는 한국어 원문 키 + `js/i18n-en.js` 동시 추가. `" · "` 글루와 `{0#}` 조합 프롬프트 함정 주의
- **외형 사양**: 🐸는 확정(위). 🦋🐦🦔 3종은 구현 착수 전에 같은 형식으로 확정
