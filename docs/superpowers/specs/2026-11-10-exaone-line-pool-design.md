# EXAONE 문구 풀 (저녁 경매 문구 · 포구 반복 의뢰)

작성 2026-11-10 · 상태: 설계 승인(2026-11-10 사용자) · 구현·커밋 전

관련 스펙

- 포구 섬: `docs/superpowers/specs/2026-10-31-restaurant-quest-design.md` 5절, 1단계 계획 `docs/superpowers/plans/2026-11-10-port-island-stage1.md`

## 0. 왜 만드나

| 근거 | 내용 |
|---|---|
| 경매품이 사흘마다 돌아온다 | 경매 풀은 3점(달빛 그네·등불 아치·별 풍향계), 하루 1점. 물건 소개와 경매인 말이 매일 달라야 같은 물건이 돌아와도 덜 지루하다 |
| 포구 의뢰는 4개로 끝난다 | 1단계 의뢰는 고정 4개. 기획서 5.4 에 "의뢰는 하루 한 번 날짜 시드로 바뀜"이 이미 적혀 있다 |
| EXAONE 은 실시간에 못 쓴다 | 초당 1건 제한, 응답 9~40초. 대신 지금은 무료이고 한국어가 강하다 |
| 무료 기한이 불확실하다 | 2026-11-09 출시 기준 무료, 기한은 공식 문서에 없다(기사마다 다름) |

목표: 무료일 때 문구 풀을 넉넉히 쌓아 두고, 게임은 날짜로 그날 문구를 고른다. 게임 실행 중 EXAONE 호출은 0.

## 1. 확정된 것

| 항목 | 결정 |
|---|---|
| 방식 | 문구 풀 + 날짜 시드(주민 잡담 `npc_dialogues` 와 같은 구조). 매일 밤 생성(ai-pregen 방식)은 기각 |
| EXAONE 의 역할 | **대사만 쓴다.** 누가 무엇을 몇 개, 보상 얼마인지는 코드의 날짜 시드와 규칙표가 정한다 |
| 값 표기 | 수량·물건 이름·주민 이름은 자리표시 `{n}` `{item}` `{who}`. 가격·남은 초는 HUD 숫자 칸이 따로 보여 준다 |
| 언어 | 한국어·영어 둘 다 |
| 사용처 | ① 저녁 경매 HUD 문구 ② 포구 반복 의뢰 대사. 포구 고정 의뢰 4개는 확정 문구 그대로 |
| 포구 새 물건 | 주민당 2종, 8종 추가(조형은 시안 비교 후 확정) |
| A/B 실험 | 하지 않는다(표본 부족). 기술 통계로 보고 나쁜 문구는 숨긴다 |
| 순서 | 공통 계층 + 경매 먼저. 포구 반복 의뢰는 포구 섬 1단계가 main 에 들어간 뒤 |

## 2. 공통 생성 계층

### 2-1. 저장소 `line_pool` (Supabase)

| 열 | 내용 |
|---|---|
| `id` | bigint, 기본키 |
| `kind` | `auction` · `port` |
| `key` | 경매품 id, `_any`(경매 공통), `<주민>_<물건>`(포구) |
| `slot` | 대사 자리(3·4절 표) |
| `lang` | `ko` · `en` |
| `text` | 문구 한 줄(자리표시 포함) |
| `hidden` | boolean, 기본 false. true 면 고르지 않고 크론이 빈자리를 채운다 |
| `created_at` | timestamptz |

- 칸 = (kind, key, slot, lang). 칸당 상한 `POOL_CAP = 30`(hidden 제외하고 센다).
- RLS 켜고 정책 없음. service_role 로만 읽고 쓴다(게임 화면에 그대로 뜨는 문장이라 anon 쓰기 금지, `npc_dialogues` 와 같은 규칙).
- 고르기는 RPC `line_pick_many(p_kind, p_keys[], p_lang, p_seed, p_n)`: `hidden=false` 중에서 칸마다 `md5(seed/key/id)` 순으로 n줄. 칸 수 세기는 RPC `line_pool_counts()`. 둘 다 service_role 에만 연다.
- `line_picks`(date, kind, key, slot, lang, line_id): `/api/lines` 가 그날 고른 줄을 남긴다. 7절 트래킹용.
- `line_pool_runs`: 크론·시드 실행 기록(성공도 남김). 요청·적재·실패·429 여부·소요 시간.
- 마이그레이션: `sql/migrations/migrate_line_pool.sql`.

### 2-2. 채우기

- `functions/api/_exaone.js` (새): `aura-cron.js` 의 EXAONE 호출부를 떼어 낸다. URL·모델(`k-exaone_v2.5`)·호출 간격 1100ms·동시 6건·429/401/403 분류를 한곳에서. 빛 공방과 문구 풀이 같이 쓴다.
- `functions/api/_line-gen.js` (새): 프롬프트 생성, 응답 파싱, `validateLines`, 채울 칸 계획(`planLineWork`). 크론과 시드 스크립트가 공유하는 단일 출처.
- `tools/seed-line-pool.mjs` (새, 수동): 처음 한 번 풀을 상한까지 채운다. 호출 1번에 10줄. `--kind`, `--sample 10`(DB 쓰기 없이 칸마다 10줄을 뽑아 검수 표 출력).
- `functions/line-pool-cron.js` (새, 주 1회): 상한에 못 미친 칸과 `hidden` 으로 빠진 자리만 채운다. 무료가 끝나면 이 크론만 끈다.
- 크론 트리거: 슬롯이 이미 5/5(`worker/index.js` scheduled 주석). 새 트리거를 만들지 않고 빛 공방 틱 `0,30 18-21 * * *` 중 **UTC 일요일 21:30(KST 월요일 06:30) 한 번**을 문구 풀 보충에 쓴다(푸시가 ai-pregen 트리거를 분으로 가른 것과 같은 방식). 실행이 따로라 서브리퀘스트 50 예산도 따로이고, 빛 공방은 06:00 틱과 07:00 마감이 그대로 남는다.

### 2-3. 읽기 `/api/lines`

- 요청: `GET /api/lines?kind=auction&key=moonswing&lang=ko`. `key` 는 쉼표로 여러 개(최대 4) 받을 수 있다.
- 서버가 시드 `<KST 날짜>:<kind>:<key>` 로 slot마다 필요한 수만큼 고른다(slot별 수는 3·4절 표).
- 응답: `{ date, src: 'pool'|'partial'|'fallback', lines: { <key>: { <slot>: [{ id, text }] } } }`
- 엣지 캐시 키 (날짜 × kind × key × lang). 캐시를 채울 때 `line_picks` 에 기록.
- 라우트는 `worker/index.js` 에 등록(메모리 api-route-wiring).
- 클라이언트 기본 문구: `js/lines/fallback.js` 에 slot마다 손으로 쓴 문구. 응답 실패·3초 초과·빈 칸·자리표시 미치환이면 그 slot 만 기본 문구.
- 클라이언트 모듈 `js/lines/client.js`: 받기·캐시·자리표시 채우기(`fillLine(text, vars)`).

## 3. 저녁 경매 문구

모두 HUD 창에만 뜬다. 무대 위는 지금처럼 이모지만.

| slot | 언제 | key | ko 상한 | 하루 수 | 자리표시 |
|---|---|---|---|---|---|
| `intro` | 창을 열 때, 감정가 옆 물건 소개 | 경매품별 | 60자 | 1 | 없음 |
| `open` | 시작 종이 울릴 때 방랑 상인 첫마디 | 경매품별 | 30자 | 1 | 없음 |
| `raise_npc` | 주민이 부를 때 상인의 반응 | `_any` | 24자 | 4(돌려 씀) | `{who}` |
| `raise_me` | 플레이어가 부를 때 상인의 반응 | `_any` | 24자 | 4(돌려 씀) | 없음 |
| `last` | 마지막 3초, 망치를 들 때 | `_any` | 20자 | 1 | 없음 |
| `sold_me` | 플레이어 낙찰 | `_any` | 30자 | 1 | 없음 |
| `sold_npc` | 주민 낙찰 | `_any` | 30자 | 1 | `{who}` |

- 칸 수: 경매품별 3 × 2 slot × 2 언어 = 12, 공통 5 slot × 2 언어 = 10, 합 22칸. 풀 660줄, 약 66회 호출.
- `/api/lines?kind=auction&key=<그날 경매품>` 한 번이 경매품별 slot 과 `_any` slot 을 함께 돌려준다.
- 프롬프트: 방랑 상인 말투는 주민 잡담과 같은 단일 출처 `functions/api/_npc-gen.js` 의 `NPC_SHEET.merchant`(하오체), 경매품 설명(구현된 C 무대 세트: 큰 초승달 그네·빨간 지붕 등불 문·금별 풍향계), slot 설명과 상한, "숫자 쓰지 말 것", 자리표시 규칙.
- 구경 모드는 같은 문구에서 `raise_me`·`sold_me` 만 빠진다.
- `{who}` 는 코드가 큐레이터 · 별 보는 아이 · 목수 아저씨 표시 이름으로 채운다.
- 받는 시점: 경매 시간대에 광장에 들어올 때 미리 받는다. 창 여는 흐름을 막지 않는다.

## 4. 포구 반복 의뢰

### 4-1. 규칙 (`js/port/daily.js`, 순수 모듈)

- 열림: 고정 의뢰 4개를 모두 끝낸 다음 KST 날짜부터.
- 하루 4개: 날짜와 주민을 시드로 주민마다 1개. 부엉이 의뢰는 지금처럼 밤에만 받는다.
- 물건: 그 주민의 3종(기존 1 + 새 2) 중 하나.
- 수량: 물건별 `[min, max]` 범위 안에서 시드로.
- 보상: 주민별 식재료(고정 의뢰와 같은 종류), 양 = 물건별 단가 × 수량을 올림. 포장마차 구매(코인 30 → 쌀 2·채소 2)보다 넉넉하게.
- 자리: 물건마다 자기 구역 안 후보 자리 4~5곳, 그날 수량만큼 시드로 골라 놓는다. 수락할 때만 생긴다(1단계 `spawnItems` 와 같은 흐름).
- 저장: `gameState.port.daily = { date, quests: { <npc>: { item, n, got, state } } }`. `sanitizePort` 에 정규화 추가. 날짜가 바뀌면 새로 뽑는다.
- quest id: `r_<npc>_<item>`.
- 단가·범위 수치는 구현 계획에서 시뮬(왕복 시간 대비 식재료량)로 정한다.

### 4-2. 새 물건 8종 (후보)

| 주민 | 구역 | 기존 | 새 2종 |
|---|---|---|---|
| 🦦 수달 어부 | 🏖️ 해변 | 부표 | 떠내려온 유리병 · 그물 조각 |
| 🦝 포장마차 너구리 | 🪨 갯바위 | 조개 | 소라 · 미역 |
| 🐐 밭 할머니 염소 | 🌱 밭 | 배추 | 무 · 호박 |
| 🦉 등대지기 부엉이 | 🗼 등대·밤 해변 | 기름통 | 불가사리 · 빛나는 바다유리 |

- 조형·아이콘은 시안 3개 이상을 PC·모바일로 나란히 비교한 뒤 확정(메모리 design-compare-before-ship). 저폴리 소품 그림자 규칙과 블룸 임계 0.85 를 지킨다.
- 이름 문구(한·영)는 후보 표로 먼저 검수.

### 4-3. 대사

| slot | 언제 | key | ko 상한 | 하루 수 | 자리표시 |
|---|---|---|---|---|---|
| `ask` | 말을 걸어 부탁할 때 | `<주민>_<물건>` | 70자 | 1 | `{item}` `{n}` |
| `thanks` | 다 모아 돌려줄 때 | `<주민>_<물건>` | 50자 | 1 | `{item}` |

- 칸 수: 주민×물건 12 × 2 slot × 2 언어 = 48칸. 풀 약 1,440줄, 약 144회 호출.
- 섬에 내릴 때 그날 의뢰 4개 key 를 한 번에 받는다(`/api/lines?kind=port&key=a,b,c,d`).
- 재촉 대사는 1단계 고정 문구(`PORT_COPY.nag`) 그대로.
- 대사 박스는 1단계와 같은 `js/mirror/talk-box.js`, 문장 끝 나누기 `splitLines`.
- 프롬프트: 주민 4명의 캐릭터(수달 어부 노란 우비, 너구리 머리띠 앞치마, 염소 뿔 안경, 부엉이 귀깃 선장모)와 말투, 물건이 있는 구역.

## 5. 생성 문구 검증 (`validateLines`)

| 검사 | 버리는 것 |
|---|---|
| 자리표시 | 필수 자리표시가 빠졌거나 모르는 `{x}` 가 있음 |
| 숫자 | 아라비아 숫자가 들어간 줄 |
| 금지어 | 엠대시(—), "놀다·놀아요" 활용형 |
| 길이 | slot 상한 초과(영어는 한국어 상한 × 1.8) |
| 언어 | `en` 줄에 한글, `ko` 줄에 한글 없음 |
| 중복 | 같은 칸 안 또는 기존 풀과 같은 줄 |
| 조사 | 자리표시 바로 뒤의 받침 갈리는 조사(이·가·을·를·은·는·와·과·으로·로). 이름·물건마다 받침이 달라 틀린다 |

- 응답 파싱: `response_format` 이 문서에 없으므로 스키마를 시스템 프롬프트에 넣고 느슨하게 파싱(빛 공방과 같음). 필드가 빠지면 그 칸만 다시 시도.
- 말투(존댓말 등)는 자동 검사하지 않고 샘플 검수에서 사람이 본다.

## 6. 실패 처리

| 상황 | 처리 |
|---|---|
| EXAONE 429 | 그 회차 중단, 다음 회차가 이어서 채움 |
| EXAONE 401·403 | 중단 + 메일 |
| 시간 초과·형식 오류 | 그 칸만 2번까지 재시도 후 건너뜀 |
| 검증 후 0줄 | 실패로 세고 다음 칸으로 |
| 크론 성공 | `line_pool_runs` 에 기록(안 떴는지 잡기 위해) |
| `/api/lines` 실패·3초 초과 | 클라이언트 기본 문구 |
| 칸 하나가 빔 | 그 slot 만 기본 문구, `src='partial'` |
| 고른 줄에 자리표시가 남음 | 그 줄 버리고 기본 문구 |
| 문제 문구 발견 | `hidden=true`, 다음 크론이 빈자리를 채움. 캐시는 그날까지만 유지 |

## 7. 트래킹

| 질문 | 방법 | GA4 추가 |
|---|---|---|
| 풀 문구가 나갔나, 기본 문구로 떨어졌나 | `auction_open` · `port_quest`(act=accept)에 `line_src`(pool/partial/fallback) | 키 1개. 기존에 같은 뜻의 키가 있으면 재사용 |
| 그날 누가 어떤 문구를 봤나 | `line_picks`(서버). GA4 의 날짜·`item_id`·`quest_id` 와 이어 붙임 | 없음 |
| 반복 의뢰가 돌아올 이유가 되나 | `port_quest` 의 `quest_id=r_<npc>_<item>`, `act`=accept/done | 없음 |
| 크론이 제대로 도나 | `line_pool_runs`, 실패 메일 | 없음 |

- 판정 지표(반복 의뢰 배포 2주 뒤): 반복 의뢰가 열린 사람의 D1·D7, 1인 하루 완료 수, 문구별 수락·완료(기술 통계).
- 이벤트 파라미터 5개 이하 유지, `docs/analysis/event-taxonomy.csv` 행 추가, 배포 다음 날 BQ 재검증(메모리 feature-tracking-checklist).

## 8. 테스트

- 단위(`node:test`): `validateLines` 규칙별, `planLineWork`(상한·hidden 보충), 날짜 시드 선택(같은 날 같은 줄, 날마다 고르게), `fillLine`, `js/port/daily.js`(결정성·수량 범위·부엉이 밤·고정 4개 뒤 열림), `sanitizePort` 의 `daily`.
- 프롬프트 언어: `en` 프롬프트에 한글이 없다.
- 크론·API: fetch·notify 주입(ai-pregen 테스트 방식)으로 429·401·폴백·성공 기록.
- 실호출: `seed-line-pool.mjs --sample 10` 검수 표를 사용자에게 → 승인 뒤 본 채우기.
- 브라우저: 가장 긴 문구로 경매 HUD·포구 대사 박스를 PC 와 가로 폰(844×390)에서 확인.
- 코드 리뷰 에이전트.

## 9. 안 하는 것

- 게임 실행 중 EXAONE 호출, 플레이어 입력에 반응하는 생성.
- 날씨·계절별 문구(필요하면 주민 잡담 첫인사처럼 나중에 slot 추가).
- 포구 고정 의뢰 4개 문구 교체.
- 기존 Gemini 사전 생성 5곳의 EXAONE 이관.
- 문구 A/B 실험.

## 10. 지켜야 할 기존 규칙

- 새 코드·CSS·테스트에 주석 없음. 클라이언트 코드는 `js/lines/`, `js/port/`, `js/auction/` 아래.
- 월드 말풍선은 이모지만, 글자는 HUD·대사 박스.
- 새 UI 문구(기본 문구·물건 이름)는 코드 전에 후보 표로 검수, 모바일 실측.
- 새 `functions/api` 파일은 `worker/index.js` 라우트 등록.
- 키 `EXAONE_API_KEY` 는 키체인·Worker 시크릿·루트 `.env` 에만. 공개 저장소이므로 푸시 전 키 스캔.
- 배포는 웹·토스·Play·iOS·itch 5곳 동시.
