# 🎃 할로윈 프리미엄 한정 판매

**작성** 2026-10-06 · **상태** 설계(미구현) · 선행 스펙 [premium-trails](./2026-10-01-premium-trails-design.md) · [premium-skins](./2026-10-01-premium-skins-design.md) · [seasons](./2026-10-01-seasons-design.md) · [paddle-checkout](./2026-09-30-paddle-checkout-design.md)

## 1. 목적과 비목표

할로윈(10/31) 시즌 한정 프리미엄 상품을 **기간 한정으로** 판다. 매년 같은 상품을 날짜만 바꿔 재판매할 수 있게 만든다(1인 운영 부담 고정).

**비목표**
- 확률형·뽑기 금지(premium-cosmetics 확정 사항).
- 압박성 문구("놓치면 영영 못 사요") 금지 — 내년에 다시 팔기 때문에 "시즌 한정"으로만 안내.
- 세트 할인, 첫 구매 팩, 토스·Play 결제 — 이번 범위 밖.
- 계절 순환(`js/season.js`) 변경 — 할로윈은 계절과 별개의 날짜 창이다.

## 2. 확정 사항 (사용자, 2026-10-06)

| 항목 | 결정 |
|---|---|
| Paddle 승인 지연 | 준비만 해 두고 **승인 후 오픈**. 판매 시작일은 승인일 기준으로 유동 |
| 상품 종류 | 걷는 자국 · 전신 스킨 · 도구 스킨 · 펫 코스튬/망토 (4종 전부) |

| 한정 방식 | A안 — 아이템에 판매 기간 필드 + 종료일 Paddle Price 보관(Archive) 이중 방어 |

## 3. 현황과 제약 (코드 확인, 2026-10-06)

- 프리미엄 상품은 `js/cosmetics/catalog.js` 의 `RAW` 에 `{ id, slot, ico, name, won, tier:'프리미엄' }` 로 정의. `won` 이 있으면 현금 전용.
- 행을 어떻게 그릴지는 `js/shop/premium-row.js` 의 `premiumRowMode(item, ctx)` (순수 함수): `owned` → 웹 아님이면 `hidden` → 토큰·상점·가격 없으면 `unavailable` → 게스트 `login` → 오프라인 `unavailable` → `buy`.
- Paddle priceId 는 `js/shop/price-ids.js` 가 유일한 입력처. 값이 `null` 이면 현금 버튼이 없다. 라벨(₩)은 `js/shop/cash.js` 가 `won` 으로 만든다.
- 가격 등록은 `scripts/paddle-seed.mjs` (`custom_data.item_id` 로 멱등, 새 아이템은 `id: null` 로 넣고 재실행).
- **⚠️ 정정:** `js/config.js` 는 10/2 이후 **라이브 토큰·`storeOpen: true`** 이고 라이브 priceId 7개가 들어 있다. 클라이언트 상점은 이미 열려 있고, 막힌 건 **Paddle 도메인 승인(Pending)** 이다. 승인 전에 priceId 가 있는 새 상품을 배포하면 로그인한 웹 유저에게 결제 버튼이 보이는데 결제창이 안 열릴 수 있다 → §4-2 로 막는다.
- 결제는 **웹 전용**. 토스·Android·itch 는 안 산 프리미엄 행을 숨긴다(정책). 웹에서 산 건 옷장에서 모든 플랫폼이 장착한다.
- 계절 규칙상 가을은 10/9~10/22, **10/23 부터 겨울** 이라 할로윈(10/31)은 겨울 기간에 걸린다. 수확제 광장도 10/9~10/22. → 판매 창은 계절과 분리.

## 4. 설계

### 4-1. 판매 기간 규칙 — `js/shop/sale-window.js` (신규, 순수 모듈)

```js
export const SALE_WINDOWS = Object.freeze({
  halloween: { from: '2026-10-24', to: '2026-11-02' },   // KST 날짜, 양끝 포함. 승인일에 맞춰 이 한 곳만 고친다
});
export function saleOpen(item, now = Date.now()) { /* item.sale 없으면 true */ }
```

- 카탈로그 항목은 `sale: 'halloween'` 키만 가진다. 날짜는 위 표 한 곳이라 내년엔 이 표만 바꾼다.
- 날짜 해석은 KST 자정 기준(서버·클라 동일 식). `js/season.js` 와 같은 방식으로 날짜만 본다.
- `to` 다음 날부터 닫힌다. 날짜 문자열 → 에포크 변환은 이 모듈에서만 한다.

### 4-2. `premiumRowMode` 변경

순서: `owned` → 웹 아님 `hidden` → **`item.sale` 이 있고 기간 밖이면 `hidden`** → 나머지 기존 규칙.

- 산 사람은 기간과 무관하게 `owned`(옷장·가게에서 계속 보임).
- 기간 전에는 아무 행도 안 보이므로 **승인 전 배포가 안전**하다(버튼이 안 보임). 승인 후 `SALE_WINDOWS` 날짜만 맞춰 배포하면 오픈.
- 시계 주입을 위해 `ctx.now` 를 옵션으로 받는다(테스트용, 기본은 `Date.now()`).

### 4-3. 결제 이후 규칙 (돈 받고 안 주는 사고 방지)

- 웹훅은 판매 기간을 **검사하지 않는다.** 결제가 완료된 건 기간 밖이어도 무조건 지급한다(결제창을 열어 둔 채 자정을 넘긴 경우 포함).
- 클라이언트 시계는 표시용일 뿐 신뢰하지 않는다. 최종 차단은 종료일에 **Paddle Price 를 Archive** 하는 것(사용자 대시보드 작업, §7 체크리스트).

### 4-4a. 확정 시안과 가격 (사용자, 2026-10-06 — 최종 선택으로 교체)

시안 18안(`dev/active/halloween-premium/look/compare.html`, 라이브 `sims/halloween-{trail,skin,tools}-sim.html`) 중 사용자가 고른 **10개 상품**:

| 종류 | 확정 안 | 시안 수치 |
|---|---|---|
| 🎃 호박불(자국) | A 꼬마 호박등 | 호박 메시 8 + 입자 28, 드로우콜 최대 **9** ⚠️ |
| 🦇 박쥐(자국) | B 박쥐 회오리 | 입자 28, 드로우콜 1 |
| 👻 유령(스킨) | B 나이트캡 유령 | 메시 9→4 |
| ☁️ 유령(스킨) | C 구름 유령 (추가) | 메시 23→2, 반투명 |
| 🧙 마녀(스킨) | A 클래식 고깔 | 메시 8→5 |
| 🧙 마녀(스킨) | C 별밤 견습 마녀 | 메시 18→9, 별 발광 |
| 🌙 도구 세트 | B 달밤 보라 | 평균 3.4콜(최대 **5**) ⚠️ |
| 🌽 도구 세트 | C 수확제 | 평균 1.4콜(최대 3) |
| 🦇 망토 | A 펼친 박쥐 날개 | 메시 12 · 2콜 |
| 🦇 망토 | C 일반 + 꼬마 박쥐 | 메시 29 · 3콜 |

⚠️ 표시는 모바일 드로우콜 상한을 시험할 항목(구현 후 실측, §6).

**가격(확정, 2026-10-06): 전 상품 ₩4,000대**

| 종류 | 금액 |
|---|---|
| 걷는 자국 2종 | ₩4,000 |
| 도구 세트 2종 · 망토 2종 | ₩4,500 |
| 전신 스킨 4종 | ₩4,900 |

기존 프리미엄(₩3,000~10,000)보다 낮춘 가격이다. §4-4 표의 가격대 근거 열은 이 결정으로 대체된다. 금액은 `won` 필드 하나라 나중에 바꾸기 쉽다(Paddle 가격은 대시보드에서 별도 등록).

**구매 연출(확정): 기존 슬롯 기준 그대로.** `js/shop/reveal-pose.js` 의 `revealModeOf` 가 이미 슬롯으로 정한다 — `skin`·`tools` → 상자 폭발(boxburst), 그 외(`trail`·`back`) → 스포트라이트(spot). 가격과 무관하므로 가격을 낮춰도 연출은 변하지 않는다. 새 규칙은 필요 없고, 상품마다 `REVEAL_COPY[itemId]`(이름·설명 카드 문구)만 추가한다. 망토(`back`)는 스포트라이트(`spot`)가 자국 전용이라 **상자 폭발(`boxburst`)** 로 보낸다(캐릭터가 입은 모습, 전용 카드 "PREMIUM · 등 꾸미기"). `revealModeOf` 가 `back` 도 `boxburst` 로 바뀐다 — 구현 계획 Task 5.

(아래 원래 가격 문구는 §4-4a 로 대체됨) 가격은 새로 정하지 않고 기존 가격대 표를 따른다. 구매 직후 연출은 가격대별 기존 연출(A 스포트라이트·B 터지는 빛·C 상자 폭발)을 그대로 쓴다.

### 4-5. 화면·문구

- 한정 상품 행에 시즌 태그 "🎃 할로윈 한정 · ~11/2" 표시(안 산 사람에게만). 문구는 **구현 전에 한국어 후보를 먼저 검수받는다**(ui-copy-review-first). 영어는 i18n 사전 키 추가(한국어 원문 키 방식).

- 기존 `premium_row_view`, `cosmetic_tryon`, `cash_checkout_*`, `paddle_step`, 웹훅 `checkout_events` 가 자동으로 잡는다 → 상품 단위 퍼널은 새로 만들 게 없다.
- 추가: `premium_row_view` 에 `sale: 'halloween'` 파라미터. 한정 상품끼리 노출 대비 전환을 비교하려는 것.
- 규칙(feature-tracking-checklist): 이벤트 변경 전에 필요한 값을 먼저 확정, 배포 다음 날 BigQuery 로 재검증.

## 5. 작업 순서

1. **시안** — 상품 종류별 3안 이상을 PC·모바일로 나란히(`sims/halloween-look-sim.html`). 승인 전 구현 금지(design-compare-before-ship).
2. **규칙** — `sale-window.js` + `premiumRowMode` 변경 + 테스트(TDD).
3. **상품 구현** — 상품별: 카탈로그 항목 → 외형(이펙트/스킨/도구/망토) → 샌드박스 가격 등록(`paddle-seed.mjs`, `PADDLE_ENV=sandbox`) → `price-ids.js`.
4. **부수** — 영어 문구, 소식함 공지(notices_admin.html), 입어보기 확인.
5. **검증** — `npm test`, 모바일 실측(드로우콜·성능, 도구 쥐기·스윙 모션 불변), 코드 리뷰, 샌드박스 결제·환불 1회.
6. **승인 후** — 라이브 가격 등록(`PADDLE_ENV=production`) → `price-ids.js` 교체 → `SALE_WINDOWS` 날짜 확정 → 배포(웹만) → 공지.

## 6. 테스트

- `sale-window`: 기간 전·첫날·마지막날·다음날 경계, KST 자정, `sale` 없는 상품은 항상 열림.
- `premiumRowMode`: 한정 상품이 기간 밖이면 `hidden`, 산 사람은 기간 밖에서도 `owned`, 웹 아님은 `hidden` 유지.
- 카탈로그: 새 상품의 `won`·`sale`·`slot` 유효성, `price-ids.js` 유일성(`tests/cash.test.mjs`), `paddle-seed` 가 새 항목을 인식(`tests/paddle-seed.test.mjs`).
- 기존 유저 무영향: 기존 7개 프리미엄·코인 상품의 행 모드가 변하지 않음.

## 7. 사용자 체크리스트 (승인 후)

1. Paddle 라이브에서 상품·가격 등록 확인(`paddle-seed.mjs` 로 만든 뒤 대시보드에서 확인).
2. 판매 시작일: `SALE_WINDOWS.halloween.from` 을 오픈일로 확정.
3. **종료일에 Paddle Price 를 Archive**(대시보드) — 클라이언트 시계가 틀려도 결제를 막는 최종 방어.
4. 환불·약관 문구가 한정 상품에 맞는지 확인(refund.html "미사용 14일" 조건은 자동 장착과 모순되어 손질 필요하다고 기록돼 있음).
