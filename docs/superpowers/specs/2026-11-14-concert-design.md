# 마을 음악회 설계

작성 2026-11-14. 상태: 사용자 승인 대기.

## 무엇을, 왜

호수 옆 공원 무대에서 혼자서도 끝까지 즐기는 박자 맞추기 공연을 넣는다. 공연하면 음표를 받고, 음표로 악기와 꾸미기를 바꾼다.

- 항상 열려 있다. 하루 이용자가 적어 기간을 정하면 볼 기회만 줄어든다(사용자 결정).
- 여럿이 같은 시각에 모이는 방식이 아니다. 최근 2주 활동 로그인 계정이 46명 안팎이라 대부분 혼자 보게 된다.
- 다시 들어올 이유는 "하루 첫 3번 공연 보상"과 "악기·꾸미기 수집"이다.

## 확정된 결정

| 항목 | 결정 |
|---|---|
| 열리는 때 | 항상 |
| 박자 방식 | 두 줄 리듬 레인 |
| 장소 | 호수 옆 공원의 야외 무대. 누르면 카메라가 무대 정면으로 고정되는 공연 화면 |
| 곡 | 6곡, 난이도마다 2곡 |
| 보상 | 음표. 악기 4종 + 꾸미기 6종과 교환 |
| 게스트 | 음표는 모두, 교환은 로그인 |
| 기본 악기 | 작은북 + 북채 |
| 바꾸는 악기 | 큰 통기타(시안 ②), 큰북, 핸드벨, 마라카스 |
| 만드는 방식 | 악보 데이터 + 코드로 내는 소리, 소리 시계 기준 판정 |

## 플레이 흐름

1. 무대에 다가가면 "음악회 열기" 프롬프트가 뜬다. 누르면 곡 고르기 창이 열린다.
2. 창에는 곡 3개(최고 별 표시), 내 악기 고르기, 음표 교환, 가진 음표 수가 있다.
3. 곡을 고르면 카메라가 무대 정면으로 고정되고 캐릭터가 악기를 들고 무대 가운데에 선다.
4. 첫 공연이면 연습 4박을 먼저 한다. 안내 문구: 왼쪽 줄은 왼쪽을, 오른쪽 줄은 오른쪽을 누른다.
5. 곡이 끝나면 결과 창이 뜬다. 별, 받은 음표, 오늘 남은 보상 횟수, 다시 하기, 나가기.
6. 중간에 나가기를 누르거나 탭이 가려지면 공연이 끝난다. 보상은 없고 오늘 횟수도 줄지 않는다.

## 규칙

### 조작

- 모바일: 화면 왼쪽 절반 = 왼쪽 줄, 오른쪽 절반 = 오른쪽 줄.
- PC: F 또는 ← = 왼쪽 줄, J 또는 → = 오른쪽 줄.

### 판정

- 기준 시각은 `AudioContext.currentTime`이다. 입력 시각을 소리 시계로 바꿔 가장 가까운 음표와 비교한다.
- 딱 맞음: ±70ms, 2점. 좋아요: ±140ms, 1점. 그 밖은 놓침, 0점.
- 한 입력은 음표 하나에만 쓰인다. 창 밖 입력은 무시하고 벌점은 없다.
- 기기 출력 지연 보정은 상수 하나로 둔다. 보정 화면은 만들지 않는다.

### 난이도 자동 조절 (DDA)

기존 미니게임 난이도 모듈(`js/difficulty.js`, `js/tuning.js`의 `DIFFICULTY`)에 `concert`를 추가한다. 별 잇기(`star`)와 같은 방식이다.

- 판마다 `rollDifficulty('concert')`로 계수 `ease`를 뽑는다. `ease`는 유저별 보정(`dda`)에 측정용 팔(`arm`)을 곱한 값이고, 클수록 쉽다.
- `ease`는 판정 창에만 곱한다. 딱 맞음 = 70ms × ease, 좋아요 = 140ms × ease. 곡 빠르기와 음표 수는 바꾸지 않는다(음악이 달라지면 안 된다).
- 좋아요 창은 그 곡의 같은 줄 최소 음표 간격의 45%를 넘지 않는다. 창이 겹쳐 한 입력이 두 음표에 걸리는 일을 막는다.
- 표 값: `concert: { arms: [0.85, 1.0, 1.2], target: 0.75, ddaOn: true }`. 목표 달성률 75%는 표본이 없는 잠정치다.
- 판이 끝나면 `settleDifficulty('concert', 달성률)`을 부른다. 한 판에 움직이는 양과 범위는 기존 상수(`DIFF_K` 0.10, 범위 0.7~1.5)를 그대로 쓴다.
- 중간에 나간 판은 DDA를 움직이지 않고 `minigame_abandon`만 남긴다(기존 규칙과 같다).
- 연습 4박은 난이도를 뽑지 않는다.
- 곡 3개가 DDA 상태 하나를 같이 쓴다. 곡별로 나누면 표본이 더 모자란다. 분석할 때는 이벤트의 곡 항목으로 나눈다.
- 별 기준은 달성률 그대로다. 창이 넓어지면 별도 쉽게 받는다.

### 별과 음표

- 달성률 = 얻은 점수 ÷ (음표 수 × 2).
- 별 1개 30% 이상, 2개 60% 이상, 3개 85% 이상. 어려운 곡만 3개 기준이 80%다.
- 받는 음표 = 1 + 별 수. 한 번에 1~4개.
- 하루 첫 3번 완주까지만 음표를 받는다. 하루 최대 12개. 날짜 경계는 기존 KST 날짜 함수를 쓴다.
- 4번째부터는 음표 없이 연습과 최고 점수 갱신만 된다.

### 곡

| 곡 | 난이도 | 빠르기 | 박자 | 길이 | 음표 수 |
|---|---|---|---|---|---|
| 숲의 아침 | 쉬움 | 92 | 4/4 | 약 60초 | 약 70 |
| 장터 행진 | 보통 | 112 | 4/4 | 약 65초 | 약 110 |
| 별빛 왈츠 | 어려움 | 132 | 3/4 | 약 70초 | 약 150 |
| 호숫가 자장가 | 쉬움 | 84 | 3/4 | 약 62초 | 약 65 |
| 수확제 폴카 | 보통 | 120 | 4/4 | 약 60초 | 약 121 |
| 반딧불 춤 | 어려움 | 142 | 4/4 | 약 64초 | 약 171 |

쉬운 곡은 한 줄씩 번갈아 나오는 음표만 쓴다. 보통은 같은 줄 연타, 어려움은 두 줄 동시 음표를 더한다.

### 교환

| 품목 | 종류 | 값 |
|---|---|---|
| 마라카스 | 악기 | 20 |
| 핸드벨 | 악기 | 25 |
| 큰북 | 악기 | 35 |
| 큰 통기타 | 악기 | 40 |
| 꾸미기 6종 (실내 3, 야외 3) | 꾸미기 | 10, 15, 20, 25, 30, 30 |

합계 250. 매일 최대로 받으면 3주, 가끔 하면 두 달쯤이다. 꾸미기 6종의 이름과 조형은 시안 게이트에서 정한다. 후보: 보면대, 메트로놈, 오르골(실내), 작은 풍금, 나팔 기둥, 음표 깃발 줄(야외).

- 교환은 로그인 계정만 된다. 게스트가 누르면 기존 로그인 안내를 띄운다.
- 이미 가진 품목은 "보유 중"으로 표시하고 다시 살 수 없다.
- 조형이 없는 품목은 팔지 않는다(장터의 `hasItemArt`와 같은 막음).

## 악기

시안: `sims/concert-instrument-v2.html`(메인 폴더, 커밋하지 않음).

설계 제약: 이 캐릭터들은 배가 앞발이 닿는 거리보다 앞으로 나와 있다. 배 앞의 악기를 앞발로 직접 만지는 자세는 성립하지 않는다. 그래서 다음 세 가지 방법만 쓴다.

1. 채를 쥔다. 채 길이만큼 배 앞까지 닿는다. 작은북, 큰북.
2. 멜빵으로 메고 양발이 닿는 가슴 높이로 올린다. 큰 통기타.
3. 양발에 하나씩 들고 옆에서 흔든다. 핸드벨, 마라카스.

| 악기 | 왼쪽 줄 | 오른쪽 줄 | 소리 |
|---|---|---|---|
| 작은북 + 북채 | 왼채 | 오른채 | 둥, 탁 |
| 큰 통기타 | 올려 튕기기 | 내려 튕기기 | 튕기는 화음 |
| 큰북 | 왼 방망이 | 오른 방망이 | 낮은 쿵 |
| 핸드벨 | 파랑 종 | 빨강 종 | 높은 종소리 |
| 마라카스 | 초록 | 빨강 | 찰찰 |

- 맞게 친 입력에만 그 발이 움직이고 소리가 난다. 놓치면 동작도 소리도 없다.
- 팔 조형과 도구 휘두르는 모션은 건드리지 않는다. 공연 중에만 팔 방향을 따로 잡는다.
- 병아리는 날개가 짧아 기타 목을 쥐지 못하고 뒤에서 받친다(시안에서 확인).
- 캐릭터 7종 전부에 입혀 확인한다. 시안은 곰, 토끼, 고양이, 병아리 4종만 봤다.

## 무대와 연출

- 자리: 호수 서쪽 공원 잔디. 기존 공원 벤치를 객석으로 쓴다. 정확한 좌표는 무대 시안과 함께 걷기·충돌·주변 시설 간격을 확인해 정한다.
- 조형: 나무 단, 뒤쪽 조개 모양 가림막, 등불 줄. 밤에는 `night` 값에 따라 등불이 밝아진다(장터 수레와 같은 방식).
- 반주 악단: 해금된 주민 2~3명이 뒤에 서서 연주 동작만 한다. 판정과 무관하다.
- 객석: 벤치의 주민이 딱 맞음이 이어지면 박수 이모지를 띄운다. 월드 말풍선에는 글자를 쓰지 않는다.
- 첫 방문 안내: 장터와 같은 화살표 안내를 한 번 쓴다. 다른 안내가 진행 중이면 양보한다.

## 화면

- 세로 폰·PC: 화면 아래 3분의 1에 두 줄. 위쪽은 무대가 보인다.
- 가로 폰: 줄을 화면 양옆 세로 띠로 옮긴다.
- 줄 색은 고른 악기의 두 색을 따른다.
- 소리가 꺼져 있어도 칠 수 있게 박자선을 그린다.
- 창은 무대 분위기에 맞춘 시안 3개를 비교해 정한다.

## 소리

- 반주와 악기 소리 모두 `js/sound.js`와 같은 방식으로 Web Audio로 만든다. 음원 파일은 없다.
- 공연 중에는 마을 배경음악을 멈추고, 끝나면 되돌린다.
- 음표와 반주는 소리 시계로 미리 예약한다. 화면은 같은 시계를 읽어 그린다.

## 저장

`gameState.concert`를 추가한다.

```js
{
  notes: 0,
  owned: ['drum'],
  equipped: 'drum',
  best: { morning: 0, march: 0, waltz: 0 },
  day: '2026-11-14',
  paid: 0,
  tutorial: false
}
```

- 저장 요청은 공연 완주, 교환, 악기 바꾸기, 연습 완료 때만 한다.
- 초기화와 매 프레임 갱신은 상태만 바꾸고 저장을 요청하지 않는다(장터에서 세이브 덮어쓰기 위험이 실제로 났다).
- 불러올 때 모르는 악기 id는 버리고, `equipped`가 `owned`에 없으면 `drum`으로 되돌린다.

## 코드 구조

```
js/concert/
  rules.js      판정 창, 별, 음표, 하루 제한, 교환 가능 여부 (THREE·DOM 없음)
  songs.js      곡 3개의 빠르기·반주·악보 데이터
  judge.js      입력 시각과 악보를 받아 판정을 내는 순수 함수
  audio.js      반주와 악기 소리 예약
  lanes.js      두 줄 화면
  ui.js         곡 고르기·결과·교환 창
  copy.js       문구
  track.js      이벤트 5종
  index.js      초기화, 프롬프트, 공연 시작과 끝
  items.js      교환 꾸미기 6종 조형
js/spaces/concert-stage-art.js   무대 조형과 충돌
```

- `game.js`에는 연결 줄만 넣고 줄 수 상한을 테스트로 고정한다.
- 꾸미기는 장터에서 넣은 카탈로그 필드(`keep`, `box`, `posts`)를 그대로 쓴다.
- 새 코드에 주석을 쓰지 않는다. 설명은 커밋과 dev docs에 적는다.

## 측정

GA4 이벤트 5종, 이벤트당 기능 항목 5개 이하. 공연 시작과 끝에는 기존 난이도 키 4개(`ease`, `dda`, `arm`, `probe_v`)를 더 싣는다. 합쳐도 9개라 한도 23개 안이다.

| 이벤트 | 항목 |
|---|---|
| `concert_open` | 가진 음표, 게스트 여부 |
| `concert_start` | 곡, 악기, 오늘 몇 번째 + 난이도 키 |
| `concert_end` | 곡, 별, 달성률, 받은 음표, 딱 맞음 수 + 난이도 키 |
| `concert_exchange` | 품목, 값, 남은 음표 |
| `concert_login_prompt` | 가진 음표 |

중간에 나간 판은 `concert_end`가 아니라 기존 `minigame_abandon{game:'concert', stage:'play', song}`으로 남긴다.

배포 다음 날 BigQuery에서 적재를 확인한다. `docs/analysis/event-taxonomy.csv`에 함께 적는다.

## 테스트

- 난이도: `ease`에 따른 판정 창, 최소 간격 45% 상한, 달성률이 DDA를 움직이는지, 나간 판은 안 움직이는지.
- 단위: 판정 창 경계, 한 입력이 음표 하나에만 쓰이는지, 별 기준, 음표 계산, 하루 3번 제한과 날짜 넘김, 교환(게스트·부족·보유 중·조형 없음), 세이브 복구.
- 악보: 곡마다 음표가 시간순인지, 같은 줄 음표 간격이 판정 창의 두 배보다 넓은지, 쉬운 곡에 동시 음표가 없는지.
- 무대: 충돌이 돌길과 주변 시설을 막지 않는지.
- 브라우저: PC, 세로 폰, 가로 폰에서 한 곡 완주, 교환, 악기 바꿔 다시 연주, 밤 화면.

## 확인받을 시안 (구현 중 게이트)

1. 무대 조형과 자리: 3안, PC와 모바일 나란히.
2. 두 줄 화면과 창: 3안, 세로 폰·가로 폰·PC.
3. 문구: 버튼과 안내 후보를 먼저 검수. 엠대시와 "놀다"를 쓰지 않는다.
4. 꾸미기 6종: 품목마다 3안.
5. 곡: 3곡을 들어 보고 확정.
6. 악기: 나머지 캐릭터 3종에 입힌 모습.
