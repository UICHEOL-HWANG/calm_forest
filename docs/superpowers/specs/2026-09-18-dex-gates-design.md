# 📖 도감 희귀종 해금 게이트

작성 2026-09-18 · 상태: 설계 확정, 구현 미착수

## 배경

🦋텃밭 방문객(`2026-09-17-habitat-design.md`)으로 **조건형 수집**을 처음 넣었다. 그 다음 질문이 나왔다 — 나머지 66종은 어떤가.

조사해 보니 문제는 "조건이 없다"가 아니라 **조건이 대부분 확률**이라는 것이다.

| 카테고리 | 지금 걸린 것 | 성격 |
|---|---|---|
| 🐟 물고기 3 | 7% / 28% / 65% · 비·미끼·버프로 확률↑ | 확률 |
| ⛏️ 광물 3 | 보석 10%, 🌫️안개 20% | 확률(+날씨 보정) |
| 🌟 반딧불이 4 | 무지개 6% · 밤에만 | 확률(+시간) |
| 🍄 채집 4 | 약초 12% ~ 버섯 100% | 확률 |
| 🪏 땅속 3 | 지렁이 10% · 사금파리 5% · 옛 동전 2% | 확률 |
| 🌾 작물 7 | 씨앗 종류 — 고급 3종은 지지대 선행 | 조건 일부 |
| 🍳 요리 | 재료 보유 | 조건(재료) |
| 🧑 주민·손님 | 만나기 / 대접 | 진행 |
| 🌦️ 날씨 4 | 그 날씨인 날 접속 | 조건 |
| 🛶 강 · 🌫️ 정령 | 맵 해금 | 조건 |
| 🐾 흔적 3 | 밤손님이 와야 | 조건(수동) |

즉 희귀종은 **설계해서 얻는 것이 아니라 반복하면 언젠가 나오는 것**이다. 🌈무지개 물고기 7%, 🌈무지개반디 6%, 💎보석 10% — 많이 하면 나온다.

## 확정 전제 (재론 불필요)

1. **확률을 없애지 않는다.** 확률은 유지하고 **상황 조건을 더한다**(후보가 나올 수 있는 날을 제한).
2. **하드 게이트.** 조건이 아니면 확률 0 — 아예 안 나온다. 가중치 방식은 기각.
3. **기존 유저 무영향.** 이미 등록한 종은 절대 잃지 않는다.
4. **안내 문구는 그대로.** 종 이름을 밝히지 않는다 — 유저가 알아내는 게 수집의 핵심.
5. **희귀종만.** 흔한 종(피라미 65% · 버섯 100%)은 튜토리얼 역할이라 건드리지 않는다.
6. **🏅배지가 어려워지는 것을 받아들인다.** `night_owl`(반딧불이 4종)·`forager`(채집 4종)는 "많이 하면 받는 것"에서 "때를 맞춰야 받는 것"으로 바뀐다. 이미 받은 사람은 영향 없다.

## 게이트 표

**게임이 이미 약속하고 있는 것만 게이트로 승격한다.**

```
WEATHER_MSG (js/game.js:192)
  rain: '밭이 저절로 자라고 물고기가 잘 물어요'
  snow: '나뭇가지가 잘 부러져 목재가 더 나와요'
  fog:  '동굴에서 보석이 더 자주 반짝여요'
```

날씨↔수집의 연결이 이미 문구로 존재한다. 이걸 하드 게이트로 만드는 건 새 규칙을 만드는 게 아니라 **있던 약속을 지키는** 것이다. 그래서 별도 안내 UI가 필요 없다.

| 종 | 지금 | 게이트 | 게이트 안 확률 | 근거 |
|---|---|---|---|---|
| 🌈 무지개 물고기 (`fish.rare`) | 7% 상시 | 🌧️ 비 오는 날만 | 7% → **22%** | "비 오는 날 물고기가 잘 물어요" |
| 💎 보석 (`ore.gem`) | 10%(안개 20%) | 🌫️ 안개 낀 날만 | → **28%** | "안개 낀 날 보석이 반짝여요" |
| 🌈 무지개반디 (`bug.rainbow`) | 6% 상시 | ☀️ 맑은 날 **밤**만 | 6% → **18%** | 흐린 밤엔 안 보인다 |
| 🌿 숲 약초 (`forage.herb`) | 12% 상시 | 🌧️ 비 오는 날만 | → **30%** | 비 온 뒤 약초가 돋는다 |

### 확률을 같이 올리는 게 핵심이다

🌈무지개 물고기는 지금 평균 14번 낚아야 나온다. 바뀐 뒤엔 **비 오는 날 5번**이면 나온다.
조건을 알면 **더 빨라진다** — 기다리는 대가로 확실해진다. 그냥 어렵게만 만들면 벌칙이 된다.

비 오는 날이 두 종을 담당하는 건 의도다. 예보에 비가 뜨면 "오늘은 낚시하고 채집하는 날"이 되고,
이미 있는 `FORECAST` 재방문 훅이 세진다.

### 게이트를 걸지 않는 것

- 🪙 옛 동전(2%) · 🏺 사금파리(5%) — 이미 깊다. 삽질에 억지 날씨를 붙일 근거가 없다
- 🌾 작물 · 🍳 요리 · 🧑 주민 — 이미 조건형(씨앗·재료·진행)
- 🌦️ 날씨 · 🛶 강 · 🌫️ 정령 · 🐾 흔적 — 이미 조건형
- 흔한 종 전부 — 튜토리얼 역할

## 아키텍처

### `js/dex-gates.js` (신규, 순수 모듈)

획득 판정(`js/game.js`)과 의뢰 선택(`js/museum.js`)이 **같은 표**를 봐야 어긋나지 않는다.
🦋방문객의 `js/habitat.js`와 같은 구조다.

```js
export const DEX_GATES = {
  fish:   { rare:    { weather: 'rain',  p: 0.22 } },
  ore:    { gem:     { weather: 'fog',   p: 0.28 } },
  bug:    { rainbow: { weather: 'clear', night: true, p: 0.18 } },
  forage: { herb:    { weather: 'rain',  p: 0.30 } },
};

gateOf(cat, id) -> gate|null
gateOpen(gate, situation) -> boolean          // situation = { weather, night }
rollKind(kinds, cat, situation, rnd) -> kind
```

`situation`은 호출부가 만든다 — `{ weather: WEATHER, night: isNight() }`.

### `rollKind` — 네 갈래 굴림을 하나로 모은다

지금 네 카테고리가 각자 다른 방식으로 굴린다.

- `fish` · `bug` · `forage` — 누적 확률(`p`가 누적값)
- `ore` — `weightedOre()` 안에 분기가 하드코딩

`rollKind`는 누적 목록을 받아 **개별 가중치로 풀고 → 닫힌 종을 빼고 → 열린 종은 표의 `p`로 갈아끼우고 → 다시 정규화해서** 굴린다.

```
FISH_KINDS = [rare 0.07, uncommon 0.28, common 1.00]   (누적)
  ↓ 개별 가중치
  rare .07 · uncommon .21 · common .72
  ↓ 맑은 날(게이트 닫힘) → rare 제외, 나머지 정규화
  uncommon .226 · common .774
  ↓ 비 오는 날(게이트 열림) → rare 를 .22 로 갈아끼우고 나머지를 .78 로 정규화
  rare .22 · uncommon .177 · common .603
```

⚠️ `ore`도 이 함수를 쓰려면 `ORES`를 가중치 목록으로 표현해야 한다. `weightedOre()`의 하드코딩 분기를 없애는 게 이 작업에 포함된다.

### 큐레이터 의뢰 (`js/museum.js`)

`pickMissingDex`가 맑은 날에 🌈무지개 물고기를 집으면 **그날 의뢰가 불가능**해진다.
🦋방문객을 `DEX_NEVER`로 막은 것과 같은 함정이지만, 이번엔 종별로 날씨가 달라 더 까다롭다.

`DEX_NEVER`로 전부 막는 건 손해다 — 제일 재미있는 종을 큐레이터가 영영 못 집는다.
대신 **오늘 게이트가 열린 종만** 후보에 넣는다. `pickMissingDex`는 이미 `ctx.locked`로
잠긴 맵을 걸러내므로, **같은 자리에 `ctx.situation` 필터를 더한다.**

```
비 오는 날  → 🌈무지개 물고기 · 🌿숲 약초를 집을 수 있다
안개 낀 날  → 💎보석
맑은 날 밤  → 🌈무지개반디
맑은 날 낮  → 게이트 있는 종은 후보에서 빠진다
```

의뢰가 그날 날씨와 맞물린다 — 부작용을 고치는 게 아니라 **기회로 바꾼다.**

## 기존 유저 보호

| 보호 | 근거 | 검증 |
|---|---|---|
| 이미 등록한 종은 그대로 | `dexDiscover`는 추가만 한다(`gameState.dex[cat][id] = Date.now()`). 삭제 경로 없음 | 테스트 |
| 배지 후퇴 없음 | `awardBadge`는 부여만 한다(`js/game.js:1263`) | 기존 테스트가 잠금 |
| 박물관 층 후퇴 없음 | 층 판정은 `have`(보유 수) 기준 — 게이트는 보유 수를 줄이지 않는다 | 기존 테스트가 잠금 |
| 진행 중 의뢰가 막히지 않음 | `pickMissingDex`가 오늘 열린 종만 집는다 | 테스트 |
| 도감 총계 불변 | 종을 추가하지 않는다 — `DEX_TOTAL` 그대로 | — |

**소식함 공지가 필요 없다.** 종이 늘지 않아 카운터가 바뀌지 않고, 이미 모은 것도 그대로다.
새로 모으는 사람만 "언제 해야 하는가"를 알게 된다.

## 트래킹

새 기능은 구현과 같은 디테일로 계측한다. **축은 키값이다.**

```
dex_gate_blocked  { category, entry, weather, night }   게이트가 닫혀 후보에서 빠졌다
dex_discover      { category, entry, total }            기존 이벤트 — 게이트 종의 실제 획득일
quest_dex_one     { category, entry }                   큐레이터가 집은 종(게이트 열린 날만)
```

`dex_gate_blocked`의 빈도가 획득률과 함께 보이면 **게이트가 너무 조이는지** 알 수 있다.
예: 🌈무지개 물고기가 한 달 뒤에도 획득률이 안 오르면 확률 22%를 더 올린다.

## 비범위

- 흔한·중간 종에 게이트 걸기
- 도감 카드에 조건 표시(안내는 기존 날씨 문구로 충분)
- 🪙옛 동전·🏺사금파리 게이트
- 도구 등급 전제(별도 작업)
- 이미 조건형인 카테고리 재설계

## 열린 항목

- **확률 수치 튜닝**: 22% / 28% / 18% / 30%은 "기다린 만큼 확실해진다"를 목표로 잡은 초안이다.
  배포 뒤 `dex_gate_blocked` 대비 획득률을 보고 조정한다
- **🌈무지개반디 `weather: 'clear'`**: 밤에 안개·비가 겹치면 못 잡는다. 맑은 밤은 약 55%의 날이라
  실질 제약이 크지 않다고 판단했으나, 실측으로 확인이 필요하다
