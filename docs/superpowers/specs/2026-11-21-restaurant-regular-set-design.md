# 🍽️ 식당 단골 세트 주문 기획

## 1. 목적

단골이 된 뒤에도 그 이웃과 식당에서 할 일이 남게 한다. 단골이 가끔 두 접시 세트를 시키고, 다 내면 코인 보너스와 호감도를 더 준다.

## 2. 사용자 결정 (2026-11-21)

| 항목 | 결정 |
|---|---|
| 방식 | 한 주문표에 두 접시. 두 접시를 다 내야 먹기 시작 |
| 보상 | 코인 보너스 + 그 이웃 호감도 추가 |
| 주문표 모양 | 시안 3개 이상 PC·모바일 비교 후 결정 |

## 3. 언제 나오나

- 단골(`restaurant.regulars[npc].done`)인 이웃이 손님으로 올 때 `SET_ODDS = 0.25` 확률.
- 한 영업에서 같은 이웃은 세트를 한 번만 시킨다.
- 세트 = 그 이웃이 좋아하는 메뉴 + 지금 별에서 열린 다른 메뉴 하나(무작위). 두 메뉴 재료가 모두 남아 있을 때만(같은 재료면 2개 필요). 아니면 보통 주문.
- 연습판(첫 영업)에는 없다.

## 4. 주문과 대접

- 주문표 하나에 메뉴 두 개. 각 접시는 지금처럼 주문표 메뉴와 같은 요리를 내면 받는다. 직원 자동 대접도 같다.
- 기다리는 시간 한도는 보통의 `SET_PATIENCE = 1.5`배.
- 두 접시를 다 받아야 먹기 시작한다.
- 별점: 접시마다 지금처럼 매긴다. 세트 별점 = 두 접시 평균(반올림).

## 5. 보상

- 코인: 두 접시 코인 합 × `SET_COIN_MUL = 1.5`(반올림). 특선 두 배는 접시마다 먼저 적용.
- 호감도: 세트 별점이 4 이상이면 접시별 호감도에 더해 `SET_LOVE = 2`. 하루 선물 상한(`giftGain`)을 그대로 따른다.
- 단골 기록(`recordRegular`)은 좋아하는 메뉴 접시에 지금처럼 센다.

## 6. 화면 (시안 필수)

- 주문표: 세트임이 보이고 두 메뉴 중 이미 낸 것이 구분돼야 한다. 시안 3개를 실제 영업 화면에 넣어 PC·모바일로 비교한다.
- 세트를 다 냈을 때 손님 위 떠오르는 표시는 이모지만(월드 말풍선 규칙).
- 새 UI 문구는 후보 검수 후.

## 7. 트래킹

- 새 이벤트 `restaurant_set`(파라미터 `npc`, `stars`, `coins`) 하나. 세트를 다 냈을 때만.
- `restaurant_service` 파라미터는 늘리지 않는다(상한 5개).

## 8. 테스트

- 세트 확률·조건(단골만, 영업당 이웃 1회, 재고 2개, 연습판 없음).
- 두 접시 다 받기 전에는 먹지 않음, 접시 순서 상관없음, 직원 대접.
- 코인·별점·호감도 계산, 특선과 겹칠 때.
- 저장: 세트는 영업 안에서만 존재하므로 세이브 변경 없음.

## 9. 범위 밖

이웃별 꾸미기 보상, 세트 감사 편지, 세 접시 이상 세트.
