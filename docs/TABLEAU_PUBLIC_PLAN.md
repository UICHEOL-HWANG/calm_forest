## 4. 시트별 스펙

모든 시트: 격자선 없음, 축 0 기준선만 `#D8CDB9`, 툴팁에 "기기(브라우저) 기준" 문구 포함.

### KPI 4장 (ER 레퍼런스 패턴 이식)
각 KPI = **텍스트 시트 + 스파크라인 시트 2장 쌍**을 가로 컨테이너에 넣는다.
스파크라인이 없는 지표는 텍스트 시트만.

| # | 지표 | 값 | 소스 | 색 |
|---|---|---|---|---|
| 1 | 방문 기기 | 237 | t1 | 잉크 `#3A3226` |
| 2 | 아무것도 안 한 기기 | **59.4%** | t7 `activity_kinds=0` | **`#C4574A`** |
| 3 | 재방문 기기 | t1 `returning_devices` 합 | t1 | `#0E9078` |
| 4 | 코인 유출 / 유입 | 80 / 6,894 | t4 | `#B5851F` (직접 라벨) |

스파크라인: t1 `date` × `devices`, 라인 1.5px, 마크 없음, 축 숨김, 높이 60px.

### 섹션 1 — 입구 이탈 (t7_activity_breadth)
- 마크: 세로 막대. 열 `activity_kinds`(불연속), 행 `devices`.
- 색: `activity_kinds = 0` → `#C4574A`, 그 외 → `#8A8178`.
  (계산식: `IF [activity_kinds] = 0 THEN "아무것도 안 함" ELSE "1종 이상" END`)
- 라벨: 막대 끝에 `devices` + `pct_of_all`%. 0 막대만 굵게.
- 주석: 0 막대 위에 텍스트 주석 1개(문구는 §5에서 검수).

### 섹션 2 — 활동별 도달 (t6_activity_funnel)
- 마크: **가로 막대**, `devices` 내림차순 정렬(step 순서 아님 — 퍼널이 아니므로).
- 색: **전부 단색 `#946B3B`**(곰 갈색 램프 중간).
  ~~상위 3개만 `#C4574A`~~ — 기각(2026-09-02). 섹션 1에서 `#C4574A`가 "아무것도 안 함 = 문제"를
  뜻하게 됐으므로, 같은 색을 "가장 많이 한 활동"에 쓰면 의미가 정반대로 충돌한다.
  **벽돌색은 이탈 전용으로 예약.** 대비는 237 참조선이 만든다.
- 라벨: 막대 끝 `devices` + `pct_of_all`%.
- 기준선: 237(전체 기기) 위치에 회색 참조선 + "전체 기기 237" 라벨 → 도달 폭이 얼마나 좁은지 한눈에.

### 섹션 3 — 시작하면 끝낸다 (t2_event_frequency)
- 3쌍을 **덤벨/슬로프 차트**로:
  - `fishing_cast` 28 → `fishing_catch` 26 (93%)
  - `water_crop` 25 → `harvest_crop` 23 (92%)
  - `plant_seed` 30 → `water_crop` 25 (83%)
- 필터: 위 event_name 집합만.
- 색: 시작 `#8A8178`, 완료 `#0E9078`. 연결선 1px `#D8CDB9`.
- 라벨: 완료율 % 직접 표기.

### 섹션 4 — 튜토리얼 순차 퍼널 (t3_tutorial_funnel)
- 마크: 가로 막대, `step` 오름차순(**여기는 진짜 퍼널이라 순서 유지**).
- 축 라벨: `step` + `step_key` 병기(`2 chop`, `3 chop`처럼 중복 키가 있으므로 step 필수).
- 색: 곰 갈색 램프 `Calm Forest Bear Brown`, `devices` 기준.
- 별도 텍스트 카드: `tutorial_skip` 76대 / `tutorial_step` 1단계 26대 대비 — 이게 진짜 이야기.

### 섹션 5 — 경제 (t4_economy_flow)
- 좌: 소스별 **유입** 가로 막대(`daily_bonus` 2,335 → `sea_catch` 48), 단색 `#0E9078`.
- 우: **유출** 같은 축 스케일로 단 하나의 막대(`boat_upgrade` 80), `#C4574A`.
  같은 축을 공유해야 격차가 보인다 — 축을 따로 잡으면 메시지가 죽는다.
- 주석: "`shop_buy` 0건" 을 유출 쪽 빈 공간에 직접 표기.

소스별 유입 실측: `daily_bonus` 2,335 · `badge` 1,320 · `quest_reward` 903 · `story` 740 ·
`cafe_serve` 680 · `shop_sell` 406 · `cafe_bonus` 225 · `carve_reward` 136 · `lucky_box` 101 · `sea_catch` 48.

### 섹션 6 — 어디서 노나 (t5_move_heatmap)
- **씬별 소형 다중(small multiples)** — 한 캔버스에 합치면 안 됨(씬마다 월드 원점이 달라 마을이 점으로 뭉갬).
- 마크: 사각형. 열 `gx`, 행 `gz`, 색 `hits`, 패널 `scene`.
- **필터 2개 필수**:
  1. `devices >= 2` (1기기 셀 노출 방지)
  2. village 패널에서 `gx=0 AND gz=0` 제외 (스폰 고정점 907행이 램프를 독점)
- 색: `Calm Forest Bear Brown`.
- 제외: `city`는 셀 1개(좌표 고정) → 히트맵 불가. **방문 수 텍스트로만** 표기.
  `kitchen`·`workshop`은 0행 — 클로즈업 무대라 이동이 없음(누락 아님, 주석으로 명시).
- 씬 규모(필터 전): village 772셀/56,257 · river 673/6,342 · cafe 68/2,493 · sea 14/2,322 ·
  mine 97/2,249 · city 1/1,064.

  밝은 끝을 회색에 앵커하면 서피스와 자연스럽게 이어짐 → 우리 갈색 램프도 같은 처리 검토 가치.
- 파라미터 `Metric Selection`·`Period`로 메인 차트를 스왑, `Action (Weekday)` 필터 액션으로 교차 필터.
- LOD는 2개뿐이고 단순함(`{MAX({FIXED [Hour]: ...})}` — 막대 배경 스케일링용).
  → 우리 데이터는 시트에서 이미 집계돼 있어 LOD가 거의 불필요.

**`x_heatmap` 강(river) 처리 (2026-09-02 저녁)** — 강 씬은 gz 범위가 −626~162(789칸)로 마을(125칸)의 6배라
한 축에 놓으면 다른 씬을 납작하게 누른다. 실측 분포: 강 본체 gz −308~19 + 마을→강 통로 140~179(전체 hits의 22%),
그 사이 120칸은 빈 구간, −308 아래는 2.5%짜리 희미한 꼬리. 처리: **꼬리 절단(gz<−308 제거) → 빈 구간 접기(140+ → −120)
→ 세로 3칸 묶기(hits 합, devices 최댓값)** → 높이 117. 씬별 gz 최솟값을 0으로 바닥 정렬. 결과 1,379칸(원 1,623).
강의 세로 비율은 실제와 다르다 — 툴팁·주석에 "강은 3칸 단위로 묶음"을 남길 것.
