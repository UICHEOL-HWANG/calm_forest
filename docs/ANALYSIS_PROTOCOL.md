# 📐 분석·모델링 진행 지침

**작성** 2026-09-03

분석이 실패하는 방식은 정해져 있다. 한 번에 EDA부터 모델까지 달려가서, 읽을 수 없는 결과 덩어리를 남긴다.
**분석이 틀려서가 아니라 전달되지 않아서** 실패한다. 이 문서는 그걸 막는 절차다.

자동 적용판은 스킬 둘이다. 바깥 틀이 `gated-analysis`(게이트 구조), 안쪽 루프가
`analysis-step`(질문 하나를 쿼리→결과→차트→한계→멈춤으로 처리). 진행 상태는 `docs/ANALYSIS_GATES.md`.

---

## 왜 게이트인가

스킬은 이미 갖춰져 있었다. 입구에 `eda-analyst`(SRK 7단계), 출구에 `plain-analysis-report`.
없던 것은 **단계 사이에서 멈추는 장치**다. 멈추지 않으면 아무리 좋은 스킬도 한 턴에 소비된다.

그래서 분석을 7개 게이트로 끊고, **각 게이트 끝에서 반드시 멈춘다.**

---

## 절대 규칙 4개

### 0. 가설은 혼자 쓰지 않는다

Claude 는 근거와 반증 조건을 붙인 **후보**를 낼 뿐이다. 채택·기각·문구 수정은 대화로 정한다.

- **후보는 한 번에 하나씩.** 7개를 표로 던지고 "고르세요"도 위반이다 — 그것 자체가
  읽기 어려운 덩어리를 넘기는 행동이기 때문이다.
- 합의된 것만 가설표에 올린다.
- 합의 전에 가설을 전제로 다음 게이트를 시작하지 않는다.

### 1. 한 턴에 게이트 하나

승인 없이 다음 게이트를 시작하지 않는다. **"이어서 G3도 해봤습니다"는 위반이다.**
게이트가 빨리 끝났어도 멈춘다. 남는 시간엔 다음 게이트가 아니라 이번 전달을 다듬는다.

### 2. 통과/기각 기준은 게이트를 시작하기 전에 적는다

결과를 보고 기준을 만들면 p-hacking 이다. **기각도 정상적인 결과다.**
`CHURN_ANALYSIS_PLAN.md` §5 의 사전 기준은 결과가 나빠도 고치지 않는다.

### 3. 산출물 구조는 고정

```
한 줄 답                     ← 물은 것에 먼저 답한다
(차트 + 쉬운 말 설명 + 그 숫자를 만든 코드) × 논점 수
그래서 크기가 얼마나 되나      ← 원래 단위 · 양 끝 비교 · 설명력
이 숫자로 말할 수 없는 것      ← 비우지 않는다
다음에 확인할 것
```

마지막 두 절을 비우면 미완성이다. 차트는 **논점 하나에 한 장**, 한 장에 여러 패널을 합치지 않는다.

## 게이트 7개

| | 게이트 | 하는 일 | 끝났다는 뜻 |
|---|---|---|---|
| **G0** | 가설 확정 | 후보를 하나씩 대화로 채택/기각/수정. 표본 수치 갱신·재동결 | 사용자가 가설표에 서명 |
| **G1** | 데이터 신뢰성 | 분석 전에 데이터를 의심한다. 아래 함정 점검 | 전부 초록 또는 한계로 문서화 |
| **G2** | EDA | `eda-analyst` 7단계. 분포·이탈/잔존 단변량 비교 | **모델이 학습돼 있으면 실패** |
| **G3** | 피처·라벨 파이프라인 | 재현 가능한 추출. 누수 블랙리스트를 테스트로 강제 | 재실행 시 동일 표본 |
| **G4** | 베이스라인 | ① 다수 클래스 ② 단일 피처 로지스틱 | 두 개 다 산출 |
| **G5** | 모델·검증 | L2 로지스틱, GroupKFold(client_id), 부트스트랩 CI | 사전 기준으로 채택/보류/기각 |
| **G6** | 적용 | 모델을 실제로 태움 | 별도 기획 |

### 게이트마다 하는 일

1. 시작 전에 이번 게이트의 통과/기각 기준을 적는다
2. 작업 — G2는 `eda-analyst`, 산출물은 `plain-analysis-report` + `dataviz`, 페이지는 `artifact-design`
3. **W&B 런 1개** — `start_run(f"g{n}-<슬러그>", tags=["gate"])`. 모델뿐 아니라 표본 수·라벨 분포도 남긴다
4. **Artifact 1장 발행** — 링크를 사용자에게 준다
5. 원장(`ANALYSIS_GATES.md`) 갱신
6. **멈춘다**

## 이 프로젝트의 함정 (G1 점검 항목)

앞선 작업에서 실제로 데였던 것들이다. 매번 확인한다.

| 함정 | 내용 |
|---|---|
| **원천** | 분석은 **BigQuery** (`calm_ml.bq`). Supabase 는 7일만 보관 — 실측 15,471행/120기기 vs BQ 77,425행/204기기 |
| **사람 단위 키** | `client_id`(BQ) / `user_pseudo_id`(GA4). **`user_id` 금지** — 익명 uid 재발급으로 237기기가 uid 604개, 리텐션 7배 과소평가 |
| **session_logs 중복** | upsert 라 BQ 에 같은 세션 여러 행 → `ROW_NUMBER() OVER (PARTITION BY session_id ORDER BY updated_at DESC) = 1` |
| **play_sec 은 벽시계** | 탭 켜두면 계속 오름. 라벨엔 `game_logs` 의 `span_sec` 을 쓴다 |
| **variant 무효** | `i18n.js:detectLang()` 이 한국어 브라우저를 `assignVariant()` 앞에서 걸러 양쪽이 같은 화면을 봄 → **A/B 결론 금지** |
| **개발자 기기 혼입** | 상위 3개 client_id 가 세션의 37%. 클라이언트당 세션 상한(cap)으로 방어 |
| **per-sample 타임스탬프 없음** | `logger.js` 가 배치 INSERT 시각만 남김 → 시간 윈도우 대신 행 수(K=10) 근사 |
| **유급 베타테스터** | 이탈하지 않는다. 모델 표본이 아니라 적용·관찰 대상 |
