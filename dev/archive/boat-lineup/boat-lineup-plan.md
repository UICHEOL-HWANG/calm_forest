# 🛶 나룻배 라인업 개편 설계

- 날짜: 2026-10-27
- 상태: 설계 확정, 구현 전
- 시안: `sims/boat-lineup-compare.html`(라인업·조립·코스 지도·획득 기간), `sims/boat-redesign-compare.html`(조형 3안 비교), 조형 소스 `sims/boat-models.js`

## 1. 왜 바꾸나

`boat_runs` 143판(50명, 2026-08-15 ~ 10-26)을 보면 앞은 너무 어렵고, 강화하면 너무 쉬워진다.

| 지표 | 값 |
|---|---|
| 강화 0개 판의 완주율 | 36.9% (111판) |
| 강화 1개 이상 판의 완주율 | 100% (32판) |
| 첫 판 완주율 / 난파율 | 36% / 42% |
| 전체 충돌 중 1구간 비율 | 40% (대부분 40~80m 첫 장애물) |
| 완주 판 평균 스퍼트 | 52초에 3회 (최대 15회 가능) |
| 강화를 산 시점 | 7명 중 5명이 첫 판 직후 |

- 지금 강화 3종(⭐8~22)은 완주 한 판(⭐ 약 70)이면 산다. 사면 끝이고, 그 뒤로는 도전할 게 없다.
- 별조각은 나룻배 전용 화폐인데 강화를 다 사면 쓸 데가 없다.
- 강화한 사람은 이미 여러 판 탄 사람이라, 완주율 100%가 강화 덕인지 실력 덕인지는 갈라낼 수 없다. 표본도 작다.

## 2. 목표

1. 배마다 **강을 타는 방법**이 달라야 한다. 능력치 차이가 아니다.
2. 오래 모으는 재미. 9척 전부를 모으는 데 매일 3판 완주는 약 3달, 매일 1판 완주는 약 9달 걸린다.
3. 첫 판은 덜 억울하게, 숙련자에게는 급류라는 목표를 준다.
4. 무엇을 사도 완주율이 100%로 튀지 않는다. 쉬워지는 효과는 작게, 노는 방법이 바뀌는 효과는 크게.

하지 않는 것: 현금 결제 배(필요하면 나중에 따로 다룬다), 하루 3판 제한 변경, 다른 미니게임 경제 변경.

## 3. 전체 구조

```
배 1척 고르기 ─┬─ 부품 3칸(뱃머리 · 깃발 · 고물)
               ├─ 친구 1자리(뗏목만 2자리)
               └─ 코스 고르기(잔잔한 물길 · 급류)
```

나루터 창고 UI는 지금의 강화 목록을 **배 고르기 → 꾸미기 → 출발** 화면으로 바꾼다.

배마다 "최강"이 없어야 한다. 구현 후 같은 시드 50개 코스에서 봇(직선 회피 규칙 고정)으로 배별 완주율·평균 별을 돌려 보고, 기본 나룻배 대비 완주율 ±10%p, 평균 별 ±15% 안에 들게 수치를 맞춘다. 이 기준은 테스트로 고정한다.

## 5. 부품 3칸

| 칸 | 부품 | 효과(1단계 → 3단계) |
|---|---|---|
| 뱃머리 | ⚓ 쇄빙 뱃머리 | 바위를 스치면 램프 대신 속도만 줄어든다. 판마다 1번 → 2번 |
| 뱃머리 | 🐟 나무 물고기 | 소용돌이 끌림 −20% → −40% |
| 깃발 | 🎐 순풍 깃발 | 스퍼트 대기 −0.3초 → −0.8초 |
| 깃발 | ⭐ 별 깃발 | 별 콤보 유지 +0.5초 → +1.2초 |
| 고물 | 🥅 별 뜰채 | 놓친 별 회수 10% → 25% |
| 고물 | 🔔 뱃종 | 바위 경고 거리 20m → 35m |

- 부품은 어느 배에나 단다. 칸마다 하나만.
- 단계 비용은 별 + 강 재료. 쉬워지는 효과(쇄빙)는 3단계가 되어도 판마다 2번까지만.
- **별 콤보**는 새 규칙이다. 별을 1.5초 안에 연달아 먹으면 콤보가 오르고, 10콤보마다 별 +1. 종이배 해금 조건(콤보 30)이 이 규칙을 쓴다.

## 7. 급류 코스

| 항목 | 잔잔한 물길 | 급류 |
|---|---|---|
| 속도 | 지금과 같음 | ×1.2 |
| 장애물 간격 | 지금과 같음 | ×0.72 |
| 1구간 장애물 | 바위만, 첫 장애물 70m | 바위·통나무, 첫 장애물 40m |
| 고유 지형 | 없음 | 🪨 갈림길(270~330m), 💧 작은 폭포 2곳(180m, 450m) |
| 코스 전체 별 수 | 기준 | 잔잔한 물길과 같게(±10%) |
| 강 재료 출현 | ×1 | ×1.5 |
| 열리는 조건 | 처음부터 | 잔잔한 물길 첫 완주 |

- **급류 보상은 별이 아니라 재료로 준다.** 시안 지도는 간격만 좁혀서 별이 64개 대 121개로 늘었다. 여기에 별 배율까지 얹으면 매일 3판을 급류로 타는 사람은 46일 만에 9척을 다 모은다. 그래서 급류는 별 줄이 나올 확률을 낮춰 코스 전체 별 수를 잔잔한 물길과 맞추고, 대신 강 재료를 ×1.5로 준다. 기간은 별이 정하므로 3달 목표가 유지되고, 급류를 타면 재료가 필요한 해금(뗏목·호두 껍질 배·등불 배)이 조금 빨라진다.
- 급류에는 별도 리더보드(12장)와 급류 전용 해금 조건(비단잉어·조롱박 등 배)이 있어 탈 이유가 충분하다.
- **갈림길:** 넓은 쪽은 바위가 드문드문 있고, 좁은 쪽은 별이 줄지어 있지만 벽에 닿기 쉽다.
- **작은 폭포:** 배가 0.8초 떠올라 있는 동안에는 좌우로만 움직이고, 착지 지점에 장애물이 있으면 충돌로 친다.
- **코스 수:** 하루 3판 안에서 판마다 코스를 고른다.
- **시드:** 날짜 + 회차 + 코스로 만든다(`river:<회차>:<calm|rapid>`). 그날 같은 코스를 탄 사람끼리 같은 코스다.

## 8. 난이도 조정(잔잔한 물길)

- 첫 장애물을 46m에서 70m로 미룬다.
- 1구간에는 바위만 둔다(통나무는 2구간부터).
- 아슬아슬 보너스: 바위·통나무 가장자리를 0.6m 안으로 스치고 지나가면 스퍼트 게이지가 0.35 찬다.
- 그만두기 21%는 원인(조작이 어려워서인지 그냥 나간 건지)부터 확인하고, 이번 범위에서는 고치지 않는다. `boat_exit` 이벤트에 그만둔 거리와 충돌 수가 이미 있다.

### 다 모은 뒤
- **배 숙련도:** 그 배로 완주할 때마다 오른다(10 / 25 / 50 / 100 / 200회). 단계마다 색칠 1종(예: 금빛 비단잉어)이 열린다. 능력은 바뀌지 않는다.
- **부품 3단계 강화:** 단계마다 강 재료 15 / 30 / 60과 별 300 / 600 / 1,200.

### 재료 처리 변경
- 지금 `shell`(별 +2), `moon_fish`(물고기 +2, 별 +3)는 줍는 순간 다른 자원으로 바뀐다. 개편 후에는 `boat.mat`에 재료로 쌓는다.
- `lotus`(씨앗 +2), `driftwood`(나무 +2)는 마을에서 쓰는 자원이므로 지급은 유지하고, 같은 수만큼 `boat.mat`에도 쌓는다.
- 📖 도감 등록 규칙은 그대로 둔다.

## 10. 기존 강화 이전

| 기존 | 이전 |
|---|---|
| `up.oar` 1·2 | 🎐 순풍 깃발 1·2단계 |
| `up.hull` 1·2 | ⚓ 쇄빙 뱃머리 1·2단계 |
| `up.lamp` 1 | 🔔 뱃종 1단계 + 별 300 환급 |

- 처음 불러올 때 한 번만 이전하고 `boat.v = 2`로 표시한다. `up` 필드는 지우지 않고 남긴다(구버전 클라이언트가 덮어써도 되돌릴 수 있게).
- 기존 램프 +1(선체 강화)은 사라지고, 쇄빙 뱃머리로 바뀐다. 공지에 적는다.

## 11. 저장 구조

```js
boat: {
  // 기존 필드 유지
  date, count, clearsToday, best, clears, up, chestDate,
  v: 2,
  sel: { boat: 'ferry', bow: null, flag: null, stern: null, crew: null, course: 'calm' },
  own: { ferry: 1 },
  parts: { ram: 1, wind: 2 },
  crew: { otter: 1 },
  mat: { lotus: 0, driftwood: 0, shell: 0, moon_fish: 0 },
  mastery: { ferry: 0 },
  stat: { rapidClears: 0, rapidNightClears: 0, rapidPerfect: 0, nightClears: 0, raftClears: 0, comboBest: 0 },
  bestRapid: 0,
}
```

- `applySave`는 `{ ...기본값, ...saved.boat }` 다음에 하위 객체 7개(`sel/own/parts/crew/mat/mastery/stat`)를 각각 기본값과 합친다. 하나라도 빠지면 기존 세이브가 `undefined`를 들고 진행한다(설산 코인 무한 버그와 같은 유형).
- 세이브 크기는 몇백 바이트 늘어나는 정도라 512KiB 상한과 무관하다.
- **4곳 동시 배포:** 옛 클라이언트가 새 필드를 지우지 않는지 확인해야 한다. `boat`는 통째로 합쳐서 저장하므로 옛 클라이언트도 모르는 키를 보존한다. 단 옛 클라이언트가 새 배를 고른 세이브로 달리면 `ferry`로 탄다. 이 경우는 허용한다.

## 12. 기록과 트래킹

### `boat_runs` 새 컬럼(마이그레이션 먼저)

| 컬럼 | 타입 | 내용 |
|---|---|---|

| `mats` | jsonb | 이 판에 얻은 재료 |
| `course_v` | smallint | 코스 생성 규칙 버전(지금 = 1, 개편 = 2) |

- 리더보드 함수(`leaderboard` boat 보드)는 `course = 'calm' or course is null`로 거른다. 급류는 별도 보드(`boat_rapid`)를 추가한다. 함수 본문은 `pg_get_functiondef`로 운영 DB의 현재 본문과 비교한 뒤 바꾼다.
- `econ_logs.source` 허용값에 `boat_unlock`, `boat_part`, `boat_crew`를 추가한다(코인 지출만 기록).

### GA4
- `boat_start`, `boat_end`에 `boat_id`, `course`를 추가한다. 커스텀 키 한도(23개)를 넘지 않게, 부품 구성은 GA4에 넣지 않고 `boat_runs.loadout`에만 남긴다.
- 새 이벤트 3개:
  - `boat_unlock`: `boat_id`, `days_since_first`, `runs_total`
  - `boat_part_up`: `part`, `level`
  - `boat_skill`: `boat_id`, `skill`, `dist_m`, `seg`. 판마다 너무 많아지지 않게 판당 최대 10회만 보낸다.
- 다음 날 BigQuery에서 새 파라미터가 실제로 들어왔는지 다시 확인한다.

## 15. 테스트

- **단위 테스트:** 코스 생성(같은 시드 = 같은 코스, 급류 장애물 수, 급류 별 수가 잔잔한 물길 ±10% 안, 1구간에 통나무 없음), 해금 판정, 재료 적립, 기존 강화 이전(한 번만 실행, 결과 값), `applySave` 하위 객체 복원, 부품 효과 상한(쇄빙 판당 2회).
- **공정성 시뮬레이션:** 봇 50시드 × 배 9척, 4장 기준.
- **획득 기간 시뮬레이션:** 실측 속도로 하루 1판·3판 플레이어를 돌려 표의 날짜와 ±10% 안인지 확인.
- **헤드리스 한 판:** 배마다 1판씩 끝까지 타서 `boat_runs` 행 형태(dev 세션은 전송 안 함 → 페이로드만 확인)와 콘솔 오류 0.
- **모바일 실측:** 스킬 버튼 자리, 1인칭 시야 가림, 드로우콜(배 조형 추가 후 나룻배 대비 +10콜 이하).
