# 첫 로딩 줄이기 (boot-bundle) 계획

## 문제
- 운영 첫 화면이 JS 파일 **250개**(압축 약 1.25MB, 해제 약 3MB)를 따로 받는다. 측정 2026-10-24, 모바일 화면, `?dbg=1`.
- `js/` 파일 수 57개(9/20) → 394개(10/24). 공간별 분리 이후 요청 수가 폭증했다.
- `_headers` 가 전 파일 `no-cache` → 재방문해도 250개를 매번 재검증(304 왕복)한다.
- three.js 를 unpkg 에서 **압축 안 된 빌드**(1.27MB)로 받는다(min 빌드 gzip 166KB).
- 광고 유입(인앱 브라우저·모바일 회선)에서 이탈 원인일 수 있다. 가설이며 단계 0 에서 확인한다.

## 목표 (성공 기준)
- 첫 방문 JS 요청 250 → **10개 이하**
- 첫 방문 JS 전송량 약 1.25MB + three → **약 0.7MB 이하**(gzip 기준)
- Lighthouse 모바일(느린 4G 모의) "상호작용 가능" 시간 **이전 대비 40% 이상 단축**
- 게임 동작 변화 0: 기존 테스트 전부 통과, 5개 플랫폼 실기기 부팅·로그인·저장 확인

## 하지 않는 것
- 게임 코드 구조 변경(공간별 파일은 그대로 둔다). 묶기는 **배포 산출물에서만** 한다.
- 대시보드·sims 페이지는 손대지 않는다(원본 `js/` 를 계속 배포하므로 그대로 동작).

## 단계
### 0. 기준선 측정 (코드 변경 없음)
- Lighthouse 모바일로 운영 첫 방문 점수·시간·요청 수 기록.
- 10/25 GA4 데이터로 광고 유입의 `session_start` 대비 `game_logs` 첫 기록 비율(입구 통과율) 산출 → 배포 후 같은 지표로 비교.
- 부팅 단계 이벤트가 없으면 `boot_ready`(로딩 화면이 사라진 시점, 경과 ms) 이벤트 1개 추가를 검토. 파라미터 2개 이하.

### 1. 배포용 묶기 (효과 가장 큼)
- `scripts/lib/bundle-boot.mjs` 신설: 출력 폴더(dist, dist-toss, dist-itch, dist-cap)를 받아
  1. index.html 의 큰 인라인 모듈을 꺼내 esbuild 진입점으로 쓴다.
  2. `--bundle --format=esm --minify --splitting`, `https://*` 는 외부(토스 SDK·supabase 동적 import 유지).
  3. 산출물은 `js/b/[name]-[hash].js`, index.html 인라인 모듈을 `<script type="module" src>` 한 줄로 교체.
  4. 로딩 화면 번역용 작은 부트 스크립트는 그대로 둔다(i18n-boot 테스트 유지).
- 4개 빌드 스크립트 **마지막 단계**에서 호출(플랫폼별 문자열 치환이 끝난 뒤 묶기).
- 시험 묶기 결과: 0.7초, 222개 모듈 → 7개 파일, gzip 약 504KB(three 제외). 경고는 i18n-en 중복 키뿐.

### 2. three.js 정리
- three 를 묶음에 포함(min 상당) → importmap·unpkg 왕복 제거, 앱 오프라인과도 일치.
- 예상: three 전송 약 300KB → 약 166KB.

### 3. 캐시 헤더
- `_headers` 에 `/js/b/*` → `Cache-Control: public, max-age=31536000, immutable`(파일명에 해시).
- index.html·나머지는 기존 `no-cache` 유지 → 배포 즉시 반영은 그대로.

### 4. (선택) 한국어 사용자에게 영어 사전 안 보내기
- `i18n-en.js`(묶음 안 208KB) 를 LANG==='en' 일 때만 동적 import. `t()` 가 동기 호출되는 지점 조사 후 결정. 효과·위험을 보고 별도 승인.

### 5. 검증 → 배포
- `npm test` 전부, 묶음 부팅 스모크(로그인 화면·게스트 입장·저장 왕복) 웹 미리보기.
- Lighthouse 재측정해 성공 기준 대조.
- **배포는 10/31 광고 1주차 판정 이후**, 5곳 동시(웹·토스·Play·iOS·itch). 토스는 bundle_upload(memo).

## 위험
- 모듈 평가 순서·순환 import 차이 → 부팅 스모크와 콘솔 오류 0 으로 확인.
- 인라인 모듈이 기대던 전역·DOM 타이밍 → `type="module" src` 는 defer 동작이라 같다.
- 묶기 실패 시 배포가 막혀야 한다 → 빌드에서 오류면 종료 코드 1.
