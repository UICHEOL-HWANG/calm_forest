## 1. 한 문장
처음 물고기를 낚는 순간 집 앞마당에 연못이 생기고, 내가 잡은 물고기가 그 안에서 헤엄친다.

## 2. 동작

| 상황 | 결과 |
|---|---|
| 연못 켜짐(§6) + 연못 물고기 도감 0종 → 첫 `fishing_catch` | 연못 생성 · HUD 토스트 1회 · `pond_created` |
| 연못 켜짐 + 첫 `sea_catch` (연못 물고기 0종) | 같음 — 바다 물고기로도 연못이 생긴다 |
| 이미 연못 있음 + 새 연못 어종 도감 등록 | 그 종 1마리 추가 · 연못 위 이모지 말풍선 🐟 (글자 없음) · `pond_fish_added` |
| 바다 최고 무게 경신 | 대어 1마리를 그 종으로 교체 · 말풍선 🌊 · `pond_fish_added` (kind=sea) |
| 기존 유저(이 배포 전 기기) 첫 접속 | 도감에 물고기가 있으면 연못이 이미 있는 상태로 보인다. 토스트 1회 |
| 연못 꺼짐(대조) | 아무것도 바뀌지 않는다 |

- 안내 토스트(승인 문구 3번): **🌊 내 연못이 생겼어요 — 새 물고기를 잡을 때마다 식구가 늘어요**
  - en: **🌊 Your own pond is here! Every new fish you catch joins the family**
  - i18n 은 한국어 원문 키 사전(`js/i18n-en.js`) — 통문장 하나, 조합 글루 금지
- 월드 말풍선은 이모지만(규칙) — 종 이름 같은 글자 안내 없음

- 토스트 1회 여부만 `gameState.hintsSeen.pond` (기존 hintsSeen 맵 재사용, 새 최상위 필드 아님)

## 4. 자리·조형
- 중심: 집 터 `HOUSE_POS(-8,0,-8)` 기준, **7단계 집 반경 3.9 + 연못 반경 2.0 + 통로 0.6 = 6.5 이상** 떨어진 앞마당. 후보 (-3.0, -3.8) — **구현 첫 단계에서 실제 게임 캡처로 확정**(마을 길·NPC 동선·야외 장식 배치 구역·미니맵과 겹침 확인)
- 야외 장식(`outdoor`)이 그 자리에 이미 놓인 기존 유저: 장식을 옮기지 않는다. 연못을 후보 2·3 중 빈 곳으로 (후보 목록은 캡처 단계에서 정함)
- 충돌체: `solids.js` 원형 1개(반경 2.1) — 연못 위를 걸어 지나가지 않게
- 조형: 시안 B 그대로 — 바닥·물·돌 테두리·연잎·갈대. 돌 14개·연잎 3개는 **재질별 병합**(드로우콜 규칙) → 연못 본체 ≤ 4 메시
- 물고기: 기존 `fishMesh(rarity)` (1 메시/마리, 무지개만 2) · 대어는 같은 형태에 바다 종 색 · 원 궤도 유영, 화면 밖이면 갱신 생략
- 밤: 물 발광은 블룸 임계 0.85 아래로(나룻배 교훈)
- 그림자: 물고기는 그림자 끔(작은 소품 지글거림 교훈)

## 5. 이웃 구경
- `neighbor_showcase` 응답에 `pond: { fish: [rarity…], sea: {sp, w} | null }` 추가 — `_nb_yard` 처럼 타입 검사 후 화이트리스트 (rarity 는 `FISH_KINDS` id 만, 최대 7)
- 이웃 화면은 집주인의 무리를 모른다 → 물고기가 있으면 그린다. 대조 무리 집주인의 연못이 남에게 보일 수 있음 = 사전등록 한계에 적음 (이웃 구경은 분석 코호트에서 0명)
- SQL 은 풀러로 직접 실행 (`sql/migrations/migrate_neighbor_pond.sql`, DO 블록 하나)

## 6. 실험 연결 (E3 공간 연결 묶음)
- `js/exp-e3.js` (순수 함수) + `js/exp-e3-boot.js` — E2 패턴 그대로
  - `armForE3(clientId)` FNV-1a, 솔트 `e3:` · 무리 `off` / `on`
  - 대상: **이 배포 이후 새 기기** 전 플랫폼(웹·토스·안드로이드·iOS·itch — 분석은 GA4 가 있는 곳만)
  - 기존 기기 = 항상 `on`(배정 안 함, 속성 없음)
  - 기록: `localStorage cf_e3` · GA4 사용자 속성 `exp_space` (`off`/`on`) — `allUserProps()` 빌더에 합류(속성 덮어쓰기 사고 방지)
- 공간 연결 기능은 모두 `spaceLinkOn()` 하나로 켠다 — 로드맵 2~6번도 같은 스위치
- dev QA: `?dbg&e3=on|off`

## 9. 테스트 (TDD — 먼저 실패하는 테스트)
- 물고기 목록: 도감 0종 → 연못 없음 · 1종 → 1마리 · 계절 어종 포함 7종 상한 · 순서 = 첫 발견 순 · 모르는 id 무시
- 대어: `sea.best` 비어 있음 → 없음 · 무게 최대 1종 선택 · 동률은 SEA_SPECIES 순서
- 배정: 같은 clientId → 같은 무리 · 기존 기기 → on·속성 없음 · 저장 기록 우선 · 50:50 분포(10,000 id 에서 48~52%)
- `spaceLinkOn()` off 일 때 연못 코드가 아무 메시도 만들지 않음
- 자리: 후보 좌표가 7단계 집 반경과 겹치지 않음 · 마을 고정 물체 충돌체와 겹치지 않음
- 이웃 SQL: 잘못된 타입·모르는 id·8개 이상 → 걸러짐 (pg 로 직접 호출)
- 실기: PC·모바일 세로 캡처로 게임 거리 가독성 확인, 드로우콜 증가량 측정(목표 ≤ 15)
