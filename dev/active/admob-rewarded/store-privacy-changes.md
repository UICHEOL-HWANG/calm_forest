# 애드몹 보상형 광고 · 스토어 개인정보 변경 목록

작성 2026-11-09 · 상태: 목록만 정리, 콘솔 입력은 사용자 승인 뒤
근거: Google 애드몹 SDK가 수집·공유하는 항목(Google "Play 데이터 보안 양식 작성 안내", "Apple App Store 데이터 공개 안내")

이 앱에서 애드몹 SDK가 하는 일
- Android: 광고 ID(AAID)를 읽는다. SDK가 `com.google.android.gms.permission.AD_ID` 권한을 매니페스트에 자동으로 합친다
- iOS: 사용자가 추적을 허락하면 IDFA를 읽는다. 허락하지 않으면 IDFV만
- 두 플랫폼 공통: IP로 추정한 대략적 위치, 광고 상호작용(노출·클릭·시청), 앱 성능·충돌 정보를 Google에 보낸다

## 0. 스토어보다 먼저: 개인정보처리방침(웹, /privacy)

`pages/privacy.html` 71행이 "광고를 게재하지 않습니다"라고 적고 있다. 앱 광고가 나가기 전에 고쳐야 한다(심사관이 방침과 라벨을 대조한다).

| 바꿀 곳 | 내용 |
|---|---|
| 2. 이용 목적 | "광고를 게재하지 않습니다" 삭제 → "스토어 앱(Android·iOS)에서 이용자가 직접 고른 경우에만 보상형 광고를 보여 줍니다. 배너·전면 광고는 없습니다" |
| 3. 처리위탁·국외 이전 표 | 행 추가: Google LLC — AdMob(미국) / 광고 식별자(AAID·IDFA, iOS는 추적 허락 시), 대략적 위치(IP 기반), 기기 정보, 광고 상호작용 / 보상형 광고 게재·광고 성과 측정 / Google 정책에 따름 |
| 거부 방법 | Android: 설정 > Google > 광고 > 광고 ID 삭제 · iOS: 설정 > 개인정보 보호 및 보안 > 추적. 거부해도 게임 이용에 제한 없음 |
| 영어판 | 같은 변경을 영문 방침에도 |

## 1. Google Play Console

> 상태(2026-11-10): 광고·광고 ID·데이터 보안 세 항목 저장 후 사용자가 검토 제출 완료. 애드몹 포함 AAB는 아직 업로드 전.

### 앱 콘텐츠 > 광고
- "앱에 광고가 포함되어 있나요?" → **예**. 스토어 등록정보에 "광고 포함" 표시가 붙는다

### 앱 콘텐츠 > 광고 ID
- "앱이 광고 ID를 사용하나요?" → **예**, 용도: **광고 또는 마케팅**, **애널리틱스**, **사기 방지·보안**
- 이 선언이 없으면 targetSdk 33 이상 앱의 AD_ID 권한 업로드가 거부된다

### 앱 콘텐츠 > 타겟층 및 콘텐츠
- 확인만: 타겟 연령에 13세 미만이 들어 있으면 가족 정책 대상이 되어 애드몹 설정(아동 대상 처리 태그)을 바꿔야 한다. 13세 이상만이면 변경 없음

### 앱 콘텐츠 > 데이터 보안 (추가·변경할 항목)
| 데이터 유형 | 수집 | 공유 | 용도 | 비고 |
|---|---|---|---|---|
| 기기 또는 기타 ID | 예 | **예**(Google) | 광고 또는 마케팅, 애널리틱스, 사기 방지 | GA4로 "수집"이 이미 체크돼 있으면 "공유"와 광고 용도만 추가 |
| 대략적인 위치 | 예 | **예**(Google) | 광고 또는 마케팅, 애널리틱스 | IP 기반 추정 |
| 앱 활동 > 앱 상호작용 | 예 | **예**(Google) | 광고 또는 마케팅, 애널리틱스 | 광고 노출·클릭 |
| 앱 정보 및 성능 > 비정상 종료 로그, 진단 | 예 | **예**(Google) | 애널리틱스, 사기 방지 | |
- 공통 질문: 전송 중 암호화 = 예(변경 없음), 삭제 요청 = 기존 /delete-account 그대로
- "선택 사항인가요?" → 아니요(광고 SDK가 앱에 항상 들어 있으므로)

## 2. App Store Connect

### 앱 개인정보 보호(라벨) > 추가할 데이터 유형
| 카테고리 > 유형 | 용도 | 사용자에 연결 | 추적에 사용 |
|---|---|---|---|
| 식별자 > 기기 ID | 타사 광고, 분석 | 아니요 | **예** |
| 사용 데이터 > 광고 데이터 | 타사 광고, 분석 | 아니요 | **예** |
| 사용 데이터 > 제품 상호작용 | 타사 광고, 분석 | 아니요 | **예** |
| 위치 > 대략적인 위치 | 타사 광고, 분석 | 아니요 | **예** |
| 진단 > 충돌 데이터, 성능 데이터 | 분석 | 아니요 | 아니요 |
- "추적에 사용 = 예"가 생기면 라벨 맨 위에 "사용자를 추적하는 데 사용되는 데이터" 칸이 생긴다. ATT 허가를 묻는 앱인데 이 칸이 비어 있으면 거절 사유(5.1.2)
- GA4 등으로 같은 유형을 "분석"으로 이미 넣었다면 그 항목에 용도·추적만 더한다

### 빌드·심사 정보
- Info.plist에 `NSUserTrackingUsageDescription`(ko·en)·`GADApplicationIdentifier`·`SKAdNetworkItems`(Google 권장 50개) 추가됨(이 브랜치)
- 심사 메모 초안: "보상형 광고는 사용자가 버튼을 눌러야만 재생된다. 추적 허가는 첫 광고 직전에 한 번만 묻는다. 거부해도 광고와 게임 모두 이용할 수 있다"
- 개인정보 매니페스트(PrivacyInfo.xcprivacy): Google Mobile Ads SDK가 자체 매니페스트를 포함한다. 아카이브 뒤 Xcode "개인정보 보고서"로 합쳐진 결과만 확인

## 3. 애드몹 콘솔

- 개인정보 보호 및 메시지 > GDPR 메시지: EEA·영국 이용자가 있으면 게시해야 동의창(UMP)이 뜬다. 코드는 메시지가 없으면 그냥 지나간다
- 개인정보 보호 및 메시지 > IDFA 설명 메시지: 쓰지 않는다(코드가 직접 ATT를 묻는다). 쓰게 되면 ATT 창이 겹치지 않게 코드의 ATT 호출을 빼야 한다
- 미국 주 규정 메시지: 미국 이용자 비중이 작으면 보류 가능

## 4. 이 브랜치가 하지 않은 것
- 스토어 콘솔 입력, 방침 수정, 버전 올리기, 업로드, 심사 제출 — 모두 사용자 승인 뒤
