# 🦉☕ AI 콘텐츠 사전 생성 크론 — 계획

## 문제 (2026-09-25 실측)
1. **버그**: 의뢰 3→5 올린 날(9/24) 프롬프트가 "세 가지/나머지 둘" 그대로 → 모델이 3개 → `sanitize 후 3개만 남음` → 조합 절반 `[]` 폴백. **수정 완료(미커밋)**.
2. **구조**: 첫 방문자가 Gemini 를 즉석 호출 + 엣지 PoP 별 캐시. 날짜 바뀌는 순간 여러 API가 동시에 불러 **분당 15회 한도(프로젝트·모델 공유)** 초과 → 429.
   - 429 본문 실측: `GenerateRequestsPerMinutePerProjectPerModel-FreeTier`, quotaValue 15, model `gemini-3.5-flash-lite`.
   - 같은 15회를 쓰는 곳: cafe-guests · daily-quests · night-note · dex-notes · npc-gen 크론.

## 핵심 발견 — 조합이 24가 아니라 6
- 날씨는 `weatherOf(date)` 날짜 해시(js/game.js:184) → 모든 유저 동일. 서버가 같은 해시로 계산하면 날씨 축이 사라짐.
- 하루 조합 = lang(2) × phase(3) = **6** (의뢰 6 + 카페 6).

## 설계
### 저장: `public.ai_daily_content` (Supabase)
| 컬럼 | 설명 |
|---|---|
| kind | 'quests' \| 'cafe' |
| date | 게임 날짜(YYYY-MM-DD) |
| lang, phase | ko/en · settling/settled/thriving |
| slot | 의뢰 'day' · 카페 morning/noon/evening |
| variant | 0..7 플레이어별 변형 |
| weather | 생성 당시 날씨(기록용) |
| payload | jsonb — API 가 내려주는 배열 그대로 |
| model, created_at | 추적 |
- unique(kind,date,lang,phase,slot,variant). RLS on·정책 없음 → service_role(워커)만 읽기/쓰기 (npc_dialogues 와 같은 규칙: 화면에 그대로 뜨는 콘텐츠라 anon 쓰기 금지).
- 30일 지난 행은 크론이 삭제(무한 증식 방지).

### 생성: 크론 1개 추가 (아래 💰 절의 표현식)
- 할 일 = (KST 오늘, 내일) × kind × lang × phase × slot 중 **없는 행만** 채우기. 두 번째 실행은 첫 실행 실패분 보충.
- 20:00 인 이유: 기기 로컬 날짜를 쓰므로 KST 보다 빠른 시간대(NZ +3h)가 21:00 에 내일로 넘어간다.
- **페이싱 6.5초/회 (≈9 RPM)** — 한도 15 중 6 은 라이브(night-note·dex-notes·폴백)에 남긴다.
- 실행당 Gemini 호출 상한 `MAX_CALLS = 40`, 실패 조합은 다음 실행이 다시 집는다.
- 서브리퀘스트(무료 50/실행): Gemini ≤40 + 사용량 조회 1 + select 1 + upsert 1(일괄) + delete 1 + 실행기록 1 + 메일 1 = **≤46**.
- 실행 시간 ≈ 12~24회 × 6.5s ≈ 1.5~2.6분 (크론 wall 15분 이내, fetch 대기·sleep 은 CPU 미계상).
- 결과는 기존 `npc_gen_runs` 처럼 실행 기록 테이블에 성공/실패 모두 남김 + 실패 시 notify 메일.
- 생성 로직(프롬프트·sanitize·generate)은 각 API 파일에서 export 해 크론·API 가 **단일 출처**로 공유.

### 제공: 기존 API 경로 그대로 (클라이언트 수정 없음 → 토스·itch·안드로이드 번들 재배포 불필요)
`/api/daily-quests`, `/api/cafe-guests` 읽기 순서:
1. 엣지 캐시 → 2. **Supabase 행** (date, lang, phase[, slot]) → 3. 없으면 기존 즉석 생성(폴백, 지금과 동일) → 4. 그래도 실패면 `[]` (게임 로컬 풀).
- 클라이언트가 보내는 `weather` 는 무시하고 서버가 날짜로 계산(디버그 `?weather=` 만 영향 없음).

### 하루 호출량
- 크론: 24회/일(+재시도). 라이브 폴백은 사실상 0.
- 지금(첫 방문 몰림, PoP·조합별 즉석) 대비 급감, 분당 한도에 절대 닿지 않는 속도.

## ☕ 카페 시간대 교체 (2026-09-25 결정: 자리 4개 유지)
- slot = 기기 로컬 시각 기준 morning(<11시) / noon(<17시) / evening. 날짜와 같은 로컬 기준.
- 하루 주문 자리는 4개 그대로. 시간대가 바뀌면 **아직 서빙 안 한 자리만** 새 손님·주문·대사로 교체.
  서빙한 자리는 서빙 시점 스냅숏(`gameState.cafe.doneOrders[i]`)으로 고정 → 주문판이 어긋나지 않음.
- 경제 변화 0: 하루 서빙 최대 4, 완주 보너스 하루 1회. 새 문구 없음("내일 새 손님이 와요" 그대로 참).
- 로컬 폴백 손님도 slot 을 해시 salt 에 넣어 교체.
- 서버: cafe 행이 slot 3개 → 하루 조합 = 의뢰 6 + 카페 18 = **24**. 크론 2회(MAX_CALLS 30/회)로 여유.
- 옛 클라이언트(slot 파라미터 없음)는 서버가 KST 현재 시각의 slot 을 준다 → 토스 심사 기간에도 안 깨짐.
- 클라이언트가 바뀌므로 4곳(웹·토스·itch·안드로이드) 재배포 필요.

## 💰 무료 한도 최대 활용 — 플레이어별 변형 (2026-09-25 결정)
- 하루 한도(RPD)는 태평양 자정(KST 16~17시)에 초기화 → 크론은 KST 20시부터.
- `GEMINI_RPD`(기본 500, 사용자 확인 후 교체) × **0.6 = 크론 예산**, 0.4 = 즉석 호출 여유분(다음 날 부족 방지).
- 크론 예산 사용량 = `ai_pregen_runs.gemini_calls` 를 마지막 태평양 자정 이후로 합산. 넘으면 그날은 멈춤.
- 변형 수 V = min(8, floor(크론 예산 / 24 / 1.2)) — RPD 500 → V=8 상한까지 가능, 실제 채움은 순서대로.
- 채우는 순서: ① 오늘 없는 조합 변형0 → ② 내일 전 조합 변형0 → ③ 내일 변형1 … → 중간에 끊겨도 모든 조합은 최소 1벌.
- 실행 용량: 실행당 Gemini ≤40(서브리퀘스트 50) · 6.5초 간격(≈4.3분) · 크론 `"0,20,40 11-13 * * *"`(KST 20:00~22:40, 9회 → 최대 360회).
- 클라이언트는 기기 고정 버킷 `v`(0~7)를 보내고 서버가 `v % 있는 변형 수` 로 고른다. 옛 클라이언트는 v=0.
- 의뢰도 변형 대상 — 버킷이 기기 고정이라 하루 동안 바뀌지 않음(진행도 안전).

## 범위 밖 (메모만)
- npc-gen 주간 크론도 15회를 페이싱 없이 연달아 부름 → 같은 한도 공유. 별도 태스크로.
- night-note·dex-notes 는 캐시 수명이 길고 호출이 드물어 유지.
