# 판매가 → 판매량 반응 모델 (G0 초안, 결과 보기 전)

**작성** 2026-10-12 · 상태: ✅ G0 서명(2026-10-12) · G1 통과 · 결과가 나와도 기준은 고치지 않는다
연결: Airflow 예비명단 ③ 시세·인플레(형태 변경, 사용자 2026-10-12) · 코인 경제 C2(9/5 이후 소득의 54%가 판매) · 정의서 §5-5

## 0. 분석 목적
1. **문제** — 코인 소득의 절반이 판매에서 나온다(C2). 판매가가 밸런싱의 1순위 레버인데, 유저가 가격에 반응하는지(비쌀 때 더 파는지) 모른다
2. **왜 중요한가** — 반응한다면 시세 전광판이 설계대로 '팔 타이밍' 재미를 주고, 기본 판매가를 올리면 판매·소득이 함께 는다. 반응하지 않는다면 시세 변동은 소음일 뿐이고 기본 판매가만 소득을 좌우한다
3. **무엇을 결정하나** — ① 기본 판매가(`SELL_PRICE`) 조정 시 소득 변화를 어떻게 예측할지(탄력성 값) ② 시세 변동폭(0.70~1.30)을 유지·확대·축소할지
4. **성공 기준** — 가격 1% 변화에 판매량이 몇 % 움직이는지(탄력성)를 신뢰구간과 함께 말할 수 있다
5. **범위 밖** — 시세 예측(시세는 코드가 날짜 해시로 정함 — 예측할 대상이 아님) · 구매 가격 · 상인 첫 방문 고정가(`via=merchant`)

## 1. 왜 인과에 가깝게 잴 수 있나 (코드 확인)
- `priceRate(k) = 0.70 + (dateHash('price:' + k) % 61) / 100` — **품목 × 날짜 해시**로 정해지는 0.70~1.30배. 유저 행동·수요와 무관 → 사실상 품목·날짜별 무작위 가격
- 같은 날 활동량(누가 접속했나)은 날짜 고정효과로, 품목별 기본 수요(작물이 원래 많이 팔림)는 품목 고정효과로 걷어내면 남는 것은 **같은 날 품목 사이의 시세 차이**

## 2. 대상·정의
| 항목 | 정의 |
|---|---|
| 원천 | GA4 `shop_sell` (`item`·`qty`·`rate`(%)) · 기간 2026-08-06 ~ 10-11 (`rate` 기록 시작 8/6) |
| 제외 | 페르소나·개발자(공식 규칙) · 베타 기간 베타 기록 · `via = merchant`(첫 방문 고정가) · `rate` 없는 32건 |
| 분석 단위 | 품목 × 날 (그날 판매된 수량 합). 그날 시세는 품목·날짜별 하나 — 판매가 없던 품목·날은 시세를 코드 식으로 재계산해 0 으로 채움 |
| 품목 | 8/6~10/11 에 판매가 있는 품목 중 판매일 ≥ 10일 (작물·물고기·목재·채집물·돌·석탄 등) |

## 3. 가설과 판정 기준 (결과 보기 전 고정)
| # | 가설 | 모델 | 지지 | 판정 불가 | 반대 |
|---|---|---|---|---|---|
| **P1** | 시세가 높은 품목·날에 더 많이 판다 (가격 탄력성 > 0) | 포아송 회귀: 판매 수량 ~ log(시세) + 품목 고정효과 + 날짜 고정효과 | 계수 > 0 이고 날짜 단위 부트스트랩 95% CI 하한 > 0 | CI 가 0 포함 | CI 상한 < 0 |
| **P2** | 시세가 높을 때 한 번에 더 많이 판다 (몰아 팔기) | 판매 1건의 수량 ~ log(시세) + 품목 고정효과 (기기 단위 부트스트랩) | 같은 기준 | 같은 기준 | 같은 기준 |

- 부트스트랩 2,000회(날짜 또는 기기 정렬 후) · 판매가 있는 날 < 30 이면 **방향만**
- 보조(판정 미사용): 판매 0 을 뺀 모델 · 상위 3기기 제외 민감도(코인 C1 집중도 때문에) · 품목별 계수

## 4. 미리 밝혀 두는 한계
- 인벤토리(팔 수 있는 양)를 모른다 — 시세가 높아도 가진 게 없으면 못 판다 → 탄력성이 0 쪽으로 작게 잡힐 수 있다
- 판매는 소수 기기에 몰려 있다(코인 C1) → 상위 3기기 제외 민감도로 확인
- 시세 전광판을 본 유저만 반응할 수 있다 — 전광판 노출은 기록이 없다
- 시세 해시는 날짜가 바뀌는 자정 기준 — KST 날짜로 맞춘다 (G1 에서 코드 식 재계산과 기록된 `rate` 일치율 확인)
