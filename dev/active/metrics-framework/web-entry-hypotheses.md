# 웹 진입 분석 — 목적·가설 (G0 초안, 결과 보기 전)

**작성** 2026-10-12 · 상태: ✅ G0 서명(2026-10-12) · G1 제한부 통과 · 결과가 나와도 기준은 고치지 않는다
연결: `analysis-candidates.md` §1-A (A1~A4) · H-N1 G2(자동 로그인이 끊기면 토스 진입 −30%p) · 다음 실험 E2

## 0. 분석 목적

1. **문제** — 웹으로 처음 온 기기의 다수가 게임에 들어오지 못한다 (진입 웹 37% vs 토스 89%)
2. **왜 중요한가** — 메타 광고는 웹 경유 단일 깔때기로 집행한다. 입구에서 새면 광고비 대부분이 첫 화면에서 사라진다. 첫 5분 실험(E1)은 진입한 사람만 다룬다
3. **무엇을 결정하나** — E2 에서 무엇을 바꿀지
   - 로그인 화면 자체가 장벽 → 로그인 화면을 건너뛰고 바로 게스트로 시작 (토스 자동 로그인과 같은 효과를 웹에)
   - 화면 전에 떠남 → 로딩·첫 화면 문제 (로그인은 건드려도 소용없음)
   - 특정 환경(앱 안 브라우저·모바일)만 새는 것 → 그 환경만 손봄
4. **성공 기준** — 진입 못 한 웹 기기가 어느 단계에서 떠났는지 숫자로 나누고, 그 결과로 E2 하나를 사전 기준과 함께 설계할 수 있다
5. **범위 밖** — 인과 판정(E2 의 몫) · 진입 이후 행동(첫 5분 진단에서 끝남) · 토스

## 1. 대상·정의

| 항목 | 정의 |
|---|---|
| 웹 기기 | GA4 `user_pseudo_id`. 한 번이라도 `platform=toss` 면 제외. `platform=android`(앱)·`itch` 는 따로 표시하고 주 분석에서 제외 |
| 기간 | 첫 방문 **2026-09-04 ~ 10-11** (`login_screen` 기록이 9/4 시작) · 진입률 추세만 7/27~ 전체 |
| 진입 | 기기에 `user_id` 가 처음 붙음 (`login` 이벤트, 게스트 익명 포함) — 첫 5분 진단과 같은 규칙 |
| 단계 | ① 첫 방문(`first_visit`) → ② 로그인 화면(`login_screen` reason=no_session) → ③ 진입 |
| 제외 | 페르소나 계정 · 개발자(churn_events localhost) · 이미 세션이 있어 화면 없이 진입한 기기는 ②를 건너뛴 것으로 따로 셈 |
| 접속 주소 | 거르지 않음 (지인 포함, 기존 결정) |

## 2. 가설

| # | 가설 | 지표 | 결정과 연결 |
|---|---|---|---|
| **W1** | 진입 못 한 웹 기기의 대부분은 로그인 화면까지 왔다가 떠났다 (화면이 장벽) | 미진입 기기 중 ②에 도달한 비율 | 높으면 → E2 = 로그인 화면 건너뛰기 |
| **W2** | 로그인 화면에서 떠난 사람은 화면을 오래 보지 않았다 (읽고 거절한 게 아니라 바로 나감) | ② 도달 후 이탈자의 화면 체류 시간 중앙값 | 짧으면 → 문구·버튼 배치보다 화면 제거가 맞음 |
| **W3** | 앱 안 브라우저(인스타·카톡 등, GA4 `Safari (in-app)`·`Android Webview`)는 일반 브라우저보다 진입률이 낮다 | 브라우저 묶음별 진입률 차 | 낮으면 → "외부 브라우저로 열기" 안내 또는 앱 안 브라우저만 게스트 자동 시작 |
| **W4** | 모바일 웹은 PC 보다 진입률이 낮다 | 기기 종류별 진입률 차 | 낮으면 → 모바일 첫 화면·로딩 우선 |

## 3. 판정 기준 (결과 보기 전 고정)

- W1: ② 도달 비율 ≥ 60% 이고 95% CI 하한 > 50% → **지지** · CI 가 50% 포함 → **판정 불가** · 상한 < 50% → **반대** (화면 전 이탈이 더 큼)
- W2: 체류 중앙값 ≤ 10초 이고 부트스트랩 CI 상한 ≤ 20초 → **지지** · 중앙값 > 30초 → **반대** · 그 밖 → **판정 불가**
  - 체류 = 화면 이후 마지막 이벤트 시각 − 화면 시각 (진입 못 한 기기만)
  - **G1 뒤 추가 고정 (2026-10-12, 사용자 결정, G2 결과 보기 전):** 화면 뒤 이벤트가 없는 기기(G1 기준 35%)는 두 가지로 계산 — **하한** = 0초로 넣음 · **상한** = 측정 불가로 빼고 계산. 두 계산이 모두 지지면 **지지**, 모두 반대면 **반대**, 갈리면 **판정 불가**
- W3·W4: 차이 ≤ −15%p 이고 CI 상한 < 0 → **지지** · CI 0 포함 → **판정 불가** · 반대쪽 CI → **반대**
- 공통: 기기 단위 부트스트랩 2,000회 95% CI(기기 정렬 후) · 비율 단독은 Wilson · 칸당 n < 30 → **방향만**

## 4. 미리 밝혀 두는 한계

- `login_screen` 은 9/4 부터 → 그 전 웹 기기는 단계를 나눌 수 없다
- 같은 사람이 여러 기기·브라우저로 오면 기기가 여러 개로 잡힌다 (첫 방문 기기 기준)
- GA4 가 앱 안 브라우저를 모두 구분하지는 못한다 (카톡 등이 `Chrome`/`Safari` 로 잡힐 수 있음) → W3 는 차이를 작게 볼 방향
- 광고 차단기·추적 거부 기기는 아예 안 보인다
- 🔎 구조 확인 중 발견(결과 아님): 안드로이드 앱 기기 18대가 모두 `login_screen reason=pgs_fail` — Play Games 자동 로그인이 한 번도 성공하지 않았을 수 있음. 주 분석 밖, G1 에서 따로 확인
