## 1부. 발표 흐름 (5막)

### 1막 — 문제: 새로 온 사람 대부분이 첫 5분 안에 떠난다
- 북극성 = **하루 평균 수확·포획·제작한 유저 수** — "매일 잠깐 와서 무언가를 손에 쥐고 가는 사람"을 셉니다
  - 접속자 수는 켜기만 해도 오르지만, 이건 **가치를 얻고 간 사람**만 셉니다. 연타해도 한 사람·하루 = 1
- 북극성 × 7 = **폭(몇 명) × 빈도(며칠) × 품질(온 날 중 획득한 날 비율)** — 항상 정확히 맞는 등식이라 무엇이 움직였는지 정확히 짚습니다
  - 8/17 주 하락은 품질(27%), 9/28 주 하락은 폭(신규 16 → 7명) — 같은 "하락"인데 원인이 달랐습니다
- 그래서 문제는 **신규**: 방문자의 약 80%가 그 주 처음 온 사람이고, 다음 주에 남는 사람은 매주 3~5명
- 신규가 어디서 새나 (첫 방문 → 7일)
  - 방문 447 → 게임 진입 203 (**45%**, 웹은 36%) → 캐릭터 선택 155 → 첫 획득 79 (진입의 **39%**)
  - 첫 획득을 한 사람의 **75%가 진입 5분 안에** 했습니다 → **첫 5분이 갈림길**
- 첫 주에 획득한 사람은 28일 동안 "획득한 날"이 2.42일, 못 한 사람은 0.01일 (참여 LTV — 인과는 아님)
- 🎯 역량 ① 지표 설계

### 2막 — 어디서 새나: 입구와 첫 5분, 두 곳
- **입구 — 로그인 화면**
  - 토스 인증서 사고(9/5~9/13, 자동 로그인이 끊김)를 자연 실험으로 썼습니다. 같은 기간 웹과 비교하니 토스 진입이 **약 30%p 떨어졌습니다** → 토스 진입 89%는 "로그인 화면이 없어서"
  - 웹에서 진입 못 한 실제 유저 셋 중 둘은 로그인 화면을 **0~2초 만에** 떠났습니다 (사후 숫자 — 판정이 아니라 설계 근거)
- **첫 5분 — 획득할 곳까지 못 간다**
  - 획득 못 한 사람의 **절반 이상이 2분 안에** 떠났고, 그중 절반 남짓은 아무 플레이도 하기 전이었습니다
  - 2분 넘게 머물고도 못 얻은 사람의 **86%는 텃밭·낚시터·채집 숲·바다·광산 어디에도 가지 않았습니다**
  - 튜토리얼을 건너뛴 사람은 5분 안 첫 획득 **21%**, 코치를 시작한 사람은 **53%** — 단 코치를 끝까지(17단계) 완료한 사람은 12%뿐이고, 수확은 8단계에 있어 대부분 그 전에 그만둡니다 (스스로 고른 갈림길 — 인과 아님)
- 🎯 역량 ② 라이프타임 분석 (첫 방문 → 진입 → 첫 5분 → 7일 → 28일)

### 3막 — 그래서 무엇을 바꾸나: 실험 두 개를 결과 보기 전에 고정
- **E1 첫 5분 수확 실험** — 첫 화면을 **다 자란 밭 앞**에서 시작. 2분 안에 떠나는 사람에겐 10초 안에 할 거리를, 머무는 사람에겐 이미 획득 장소에 서 있게
  - 주 지표 5분 안 첫 획득 31% → 50% · 무리당 100명 · 최대 12주 · 진짜 질문은 "그다음 2~3주에 더 돌아오나"
- **E2 웹 로그인 화면 건너뛰기** — 웹 첫 방문은 로그인 없이 바로 게스트로 시작 (토스 자동 로그인과 같은 효과를 웹에)
  - 주 지표는 진입률이 아니라 **첫 세션 플레이 행동** 31% → 56% (진입은 처치가 기계적으로 올리니까) · 무리당 61대
  - ⚠️ 위험도 미리 쟀습니다: 계정으로 들어온 사람의 1~7일 재방문 48% vs 게스트 11% (방향만) → 게스트가 늘면 재방문이 깎일 수 있어 **7일 재방문을 가드레일로**
- 두 실험은 서로 독립 배정(2×2), 판정은 목표 표본에 도달했을 때 한 번만
- 🎯 역량 ① A/B 설계

### 4막 — 이 숫자를 믿을 수 있나: 오염을 찾고 막은 이야기
- **원본 숫자는 거짓말을 했습니다**
  - 9/28 주 원본 주간 방문자 418명 → 공식 15명: 자동 플레이 봇 계정(페르소나)이 섞였음
  - "코인 인플레가 384 → 96 으로 줄었다" → **착시**. 베타 테스터(보상 1.5배)가 섞였고, 빼면 25 → 225 로 오히려 늘었음. 그것도 경제 전체가 아니라 **상위 3대가 순증가의 52~97%** 를 만든 숫자
  - 웹 첫 방문 112대 중 63%가 개발 기기(localhost)이거나 해외 접속
- **자동으로 잡을 수 있나** — 하루 기기 수에 평균±3σ 관리도를 돌리자 봇 유입을 **첫날** 잡았고, 공식 값엔 경보가 0 (필터가 정확히 걷어냄). 오경보는 30일에 0.9회
  - 기기당 코인 순증가에는 같은 방법이 안 통했습니다(오경보 30일에 7회) — 그런데 그 '오경보' 하나는 **아무도 몰랐던 자동 접속 95대**였습니다
- **분석이 스스로를 속인 경우도 기록했습니다**
  - 난이도 분석: 자동 난이도 조절이 실패 뒤 쉬워지는 탓에 "쉬울수록 실패"처럼 보였음 → 무작위로 배정된 난이도만 떼어 보니 바다·안개에선 난이도 조절이 작동
  - 개발자 제외 규칙이 로그인한 기기만 거르고 있었음 → 진입 안 한 개발 기기가 웹 진입률을 깎고 있었음
- 지표 SQL 은 별도 구현(Codex)과 Python 정답지 두 벌이 **같은 숫자**를 내는지로 검수
- **분석에서 운영으로** — 이 관리도를 Airflow DAG 로 만들어 매일 05:00 에 돌리고, 튀면 슬랙으로 "원본만 튀었으니 오염 가능성" 같은 해석까지 붙여 보냅니다 (2026-10-12 가동)
- 🎯 역량 ③ 로그·파이프라인

### 5막 — 마무리: 모른다고 말하는 원칙
- 모든 분석은 **가설 → 판정 기준 고정 → 데이터 점검 → 결과** 순서. 결과가 나와도 기준은 고치지 않았습니다
- 그래서 "판정 불가"·"방향만"도 그대로 남겼습니다 — 표본이 작은 게임에서 이게 정직한 답
  - 예: 웹 진입 W1 은 기준 60%에 0.5%p 모자라 판정 불가 · 릴스 발행일 효과는 하루 1~4대라 구분 불가 → 그래서 광고는 **10% 홀드아웃**으로 설계
  - 이미 돌린 A/B 도 그대로 말합니다: 힌트 배너는 재방문 56% vs 56% — **판정 불가**. 효과가 없다는 게 아니라 ±15%p 보다 작은 효과는 이 표본으로 못 가린다는 뜻 → 그래서 다음 실험(E1·E2)은 표본 계산부터
- 단순한 게 이긴 사례: 28일 가치를 첫날에 맞히는 모델을 만들었더니, 변수 10개 모델이 '첫날 획득 행동 수' 하나보다 낫지 않았습니다(스피어만 0.44 vs 0.47) → 선행 지표는 '첫날 획득' 하나로
- 다음: E1·E2 결과(배포 후 약 10~12주) · 광고 집행은 안드로이드·iOS 입점 후 홀드아웃과 함께 · 기본 판매가 → 총 소득 반응
- 🎯 분석 태도

## 2부. 분석별 근거 (2026-10-12)

> 1부 각 막의 숫자가 어느 분석에서 나왔는지. 기록 전체는 `docs/analysis/ANALYSIS_GATES.md`

### 2-1. 첫 5분 진단 — 왜 첫 획득까지 못 가나 (1막·2막)

> 진행 방식: 가설을 먼저 적고, 판정 기준을 결과 보기 전에 고정한 뒤(사전 등록), 데이터가 잴 수 있는지 점검하고(G1), 그다음에 결과를 봤습니다(G2). 기각·판정 불가도 그대로 보고합니다.

#### 질문
신규의 59%가 시작은 했지만 첫 획득까지 못 가고 떠납니다. 왜? — 이 답에 따라 실험에서 무엇을 바꿀지가 갈립니다: **붙잡는 장치**(들어오자마자 붙잡기) vs **첫 획득 안내**(획득할 곳까지 데려가기)

#### 알아낸 것 (쉬운 말로)
1. **막힌 게 아니라 일찍 떠났다** — 획득 못 한 119명 중 59%가 첫 세션을 2분 안에 끝냈습니다. 획득한 사람은 진입 후 평균 2.1분에 첫 획득을 했으니, 이 사람들은 획득할 시간도 되기 전에 나간 겁니다
2. **그중 절반 남짓은 아무 플레이도 하기 전이었다** — 인트로·닉네임 단계(27초)에서, 토스는 게임 첫 화면을 보자마자(11초) 나갔습니다 → 첫 화면에 바로 할 거리가 필요
3. **무엇부터 했는지는 상관없었다** — 대화부터 한 사람 44% vs 밭일부터 한 사람 49%. 갈림길은 "무엇부터"가 아니라 "뭐라도 했나"
4. **머문 사람은 획득할 곳에 가지 않았다** — 2분 넘게 머물고도 5분 안에 못 얻은 51명 중 86%가 텃밭·낚시터·채집 숲·바다·광산 어디에도 가지 않았습니다 → 고칠 건 "장소까지 데려가기"
5. **수확으로 시작한 사람이 더 돌아오는 경향** — 2~3주 차 획득한 날 0.46 vs 0.27 (표본이 작아 방향만)
6. **다시 오게 만드는 것 (R1~R5)** — 통과한 가설 없음. "첫 주에 다른 분야를 하나 더 해 본 사람"(20% vs 7%), "코인을 써 본 사람"(21% vs 0%)이 유력한 방향

#### 실수로 생긴 실험 두 개 (자연 실험)
- **토스 인증서 사고** — 9/5~9/13 토스 자동 로그인이 끊겼습니다. 같은 기간 웹과 비교하니 토스 진입이 약 **30%p 떨어졌습니다**. 토스 진입률 89%의 상당 부분은 "로그인 화면이 없어서"였다는 뜻 → 웹 진입 36%의 원인도 로그인 화면일 가능성
- **퀘스트 챕터화** — 이야기를 앞에 세웠더니 대화는 늘었지만(32→50%) 첫 획득은 줄지 않았습니다. 다만 대조군이 없고 그 사이 다른 변화가 많아 결론은 못 냅니다 → "대조군 없는 전후 비교가 왜 약한가"의 사례

#### 그래서 → 실험 E1
첫 화면을 **다 자란 밭 앞에서 시작**하게 합니다. 2분 안에 떠나는 사람에게는 10초 안에 할 거리를, 머무는 사람에게는 이미 획득 장소에 서 있게 — 두 문제를 한 번에 겨냥. 주 지표 5분 안 첫 획득 31%→50%, 무리당 100명.
진짜 질문은 첫 획득이 오르는 것(처치가 직접 주니까 어느 정도 예상)보다 **그다음 2~3주에 더 돌아오느냐**입니다.

### 2-2. 웹 진입 — 입구에서 어디서 새나 (2막 → E2)
- 웹 첫 방문 169대 중 진입 25%. 진입 못 한 기기의 59.5%가 로그인 화면까지 왔다가 떠남 — 기준 60%에 0.5%p 모자라 **판정 불가**
- 화면 체류 시간은 '이벤트 없이 사라진 35%'를 0초로 넣느냐 빼느냐에 따라 0초 vs 2,116초로 갈려 **판정 불가**
- 판정 뒤 오염 발견: 개발자 제외가 로그인 기기만 걸러 **localhost 개발 기기 45대**와 **해외 크롤러 추정 56대**가 남아 있었음
  - 걷어낸 사후 숫자(판정 아님): 진입 46% · 진입 못 한 사람의 68%가 로그인 화면에서 **0~2초** 만에 떠남 · "PC가 모바일보다 낮다"는 결과는 크롤러가 만든 것이었음
- → **E2**: 로그인 화면 없이 게스트로 시작 (주 지표 첫 세션 플레이 행동 31% → 56%, 무리당 61대)

### 2-3. 튜토리얼 (B4) — 건너뛰면 덜 얻나 (2막)
- 5분 안 첫 획득: 건너뜀 21% (98명) vs 코치 시작 53% (72명), 차이 −31%p (CI −45~−18) → **지지**
- 코치를 끝까지(17단계) 완료한 사람 9/72 = 12% → **지지** · 그만둔 사람은 1단계(이동)에 20명 몰림
- 코치에서 8단계(수확)까지 간 17명은 94%, 그 전에 멈춘 사람도 43% → 튜토리얼이 수확을 시킨 효과 + 코치를 고른 사람이 원래 적극적인 효과가 섞임
- → 튜토리얼을 없애기보다 **수확을 앞당기는 재배치·축소** — E1 과 같은 방향, 다음 실험 후보

### 2-4. 로그인 유저 vs 게스트 (C6) — E2 의 위험 (3막)
- 웹 1~7일차 재방문: 계정(구글) 48% (21명) vs 게스트 11% (98명) — 계정 칸이 30명 미만이라 **방향만**
- 첫 5분에 획득한 사람끼리도 50% vs 9% (방향만)
- 열성 유저가 로그인을 고르는 효과 + 게스트는 다른 기기로 오면 못 이어지는 측정 편향이 섞임
- → E2 의 7일 재방문 가드레일이 실제로 걸릴 수 있음. '나중에 계정 연결' 안내를 처치에 붙일지 검토

### 2-5. 데이터 신뢰 — M5 지표 SQL 검수 (4막)
- Codex 가 SQL 로, 제가 Python 으로 같은 정의를 따로 계산 → 북극성·W·F·Q·신규/유지/복귀가 4주 모두 정확히 일치
- 차이 6건은 SQL 버그가 아니라 **정답지가 규칙 일부를 빠뜨린 것**(퍼널·경제에 베타 제외 누락) → 공식은 베타 제외로 통일하고 베타는 따로 보는 출력(`beta`)을 추가

### 2-6. 이상 탐지 — 관리도로 오염을 자동으로 잡나 (4막)
- 정답지 2건(봇 유입 10/2~10/9 · 베타 9/9~9/15)을 실행 기록에서 먼저 고정
- 하루 기기 수 + 평균±3σ(직전 14일): 봇 유입 **첫날 경보**, 사고 밖 오경보 30일에 0.88회, 공식 값엔 경보 0 → 바로 운영 가능한 수준
- 기기당 코인 순증가: 베타 첫날 경보는 났지만 오경보 30일에 7회 + 공식 값도 같은 날 경보 → 이 지표엔 3σ 가 맞지 않음
- 사전 기준 판정은 "탐지 지지 · 오경보 운영 불가" — 지표마다 맞는 방법이 다르다는 교훈

### 2-7. 코인 경제 — 인플레가 정말 있나 (4막)
- 실제로 플레이한 기기만 (자동 지급만 받고 사라진 132기기 제외 — 그중 95대가 8/31 자동 접속)
- **집중**: 상위 3대가 주 순증가의 52~97% (11주 모두 50% 이상) → 기기당 평균은 몇 명이 만든 숫자 → 가드레일을 중앙값 + 상위 3대 비율로
- **소득원**: 9/5 코인 첫 루프 뒤 판매가 소득의 54% (전엔 일일 보너스·배지 중심) → 밸런싱 1순위 레버는 판매가
- **소비**: 소비 ÷ 소득 43% → "소비처가 거의 흡수 못 한다"는 아님
- 소비처가 생긴 뒤 잔고가 덜 쌓였나는 잔고 열과 금액 합계 계산이 방향부터 갈려 말할 수 없음 (잔고 연결 86%)

### 2-8. 난이도 반응 (X2-P) — 분석이 스스로 속을 뻔한 사례 (4막)
- 자동 플레이 봇 계정 플레이로 게임별 모델: 사전 기준 판정은 낚시 반대 · 바다 판정 불가 · 안개 지지
- 반대가 나온 이유: 자동 난이도 조절(DDA)이 실패 뒤 쉬워져 "쉬울수록 실패" 상관이 생김
- 무작위로 배정된 난이도만 떼어 보면 바다 68 → 86% · 안개 22 → 74% 로 난이도 조절이 작동, 낚시는 이미 85% 라 오를 여지가 없음
- 교훈: 효과는 **무작위 배정된 성분**으로만 추정

### 2-9. 릴스·카드뉴스 발행일 (F2) — 무료 발행으로 유입을 잴 수 있나 (5막)
- 인스타 앱 안 브라우저는 출처가 direct 로 잡혀 출처로 나눌 수 없음 → 발행일(당일+다음 날) 8일 vs 나머지 20일 비교
- 하루 신규 2.0 vs 1.25대(1.6배) · 진입률 38% vs 44% — 하루 1~4대라 **방향만**
- → 효과를 재려면 **홀드아웃이 필요**하다는 근거 (메타 광고 계획의 10% 홀드아웃)

### 2-10. 판매가 → 판매량 반응 (4막 · 경제)
- 시세는 코드가 품목 × 날짜 해시로 정함(0.70~1.30배) → 사실상 무작위 가격 실험. 기록된 시세가 코드 식과 1,339건 100% 일치
- 같은 날 품목 사이 시세 차이로 본 탄력성 **+4.37 (CI +1.59~+6.61) → 지지**: 시세 70~85% 날은 평소 0.42배, 116~130% 날은 1.94배 판매
- 한 번에 몰아 파는 건 아님(P2 판정 불가) → **비싼 날을 골라 판다** = 전광판이 설계대로 작동
- 주의: '팔 날을 옮기는' 효과라 기본 판매가를 올려도 총 판매가 4배가 되지는 않음 · 베타 기간 판매가 전체의 1/3 이라 베타 계정을 빼야 했음(GA4 판매 이벤트엔 베타 태그가 없음)
- 후속 — 총 소득: 주 합계로 묶으면 시세 변동이 1/3 로 줄어 '옮기기냐 더 팔기냐'는 **판정 불가**. 대신 유저가 실제로 판 평균 시세가 **1.13 (CI 1.02~1.23) → 지지**: 시세 변동이 판매 소득을 13% 더 주는 '타이밍 보너스' (상위 3기기 빼도 1.085)

### 2-11. 힌트 배너 A/B (5막)

### 2-12. 참여 LTV 조기 예측 (1막 · 5막)

### 발표에서 조심할 말
- "59%가 2분 안에 떠난다" → **"절반 이상이 2분 안에 떠난다"** (신뢰구간 하한이 50%)
- 판정 불가 = "효과 없음"이 아님 → "이 표본으로는 모른다"
- 전부 관찰 비교 → 인과는 E1 실험이 답함
- localhost·내부망 접속도 지인 유저로 포함했다는 점 (사용자 결정) — 단 웹 진입 분석에서 localhost 진입 안 한 기기는 개발 서버 기기로 드러남(2-2), E2·F2 는 처음부터 제외
- "인플레가 줄었다"·"PC 가 더 낮다"처럼 **원본 숫자로 했던 말은 정정된 숫자로** 말하기 (2-2·2-5·2-7)

## 3부. 지표 하나하나 쉽게

> 형식: **묻는 것** / 뜻 / 지금 값 / 읽는 법 / 받을 질문 → 답

### 북극성 — 하루 평균 수확·포획·제작한 유저 수
- **묻는 것:** 매일 잠깐 와서 무언가를 얻고 가는 사람이 몇 명인가
- **뜻:** (사람 × 날) 중 획득 행동이 있는 칸 수 ÷ 7
- **지금:** 10주 평균 2.33명/일 · 범위 1.00~3.29 · 최근 1.86
- **읽는 법:** 한 주 등락은 무시. 최근 4주 평균이 직전 4주의 95% 신뢰구간 밖으로 나가야 "변했다"
- **질문:** "1.86명이면 너무 작지 않나?" → 규모가 작은 건 사실. 그래서 신뢰구간을 같이 보여 주고, 주간 등락으로 결론 내지 않습니다

### 획득 행동 16종
- **묻는 것:** "손에 쥐고 나간 날"을 무엇으로 판정하나
- **뜻:** 농사(수확·달걀·꿀) / 낚시·채집 / 만들기(제작·요리·카페·조각·밤사이 가공 수령) / 마을(퀘스트 완료·천문대·밤손님)
- **뺀 것:** 물 주기·씨 뿌리기·벌목(얻는 게 없음), 꾸미기·잡담(그것만 한 날은 4.3%뿐), 도감 발견(수확과 중복 계산)
- **질문:** "수확 1번과 천문대 1번이 같나?" → 하루에 했는지만 봅니다. 무게를 매길 자리가 없습니다

### L1 폭 — 주간 방문 유저 수
- **묻는 것:** 이번 주 몇 명이 게임 안까지 들어왔나
- **지금:** 주 평균 23.6명 (10~36)
- **아래 칸:** 신규(이번 주가 처음) 10주 193명 / 유지(지난주에도 옴) 주 평균 3.6명 / 복귀(나머지, 쉬었다 온 사람) 주 평균 0.7명
- **질문:** "WAU랑 뭐가 다른가?" → 페이지만 연 사람이 아니라 게임 안까지 들어온 사람, 그리고 같은 사람을 기기·계정으로 두 번 세지 않게 합친 값

### L1 빈도 — 1인당 방문일
- **묻는 것:** 온 사람은 일주일에 며칠 오나
- **지금:** 1.47일 (주별 1.21~1.70)

### L1 품질 — 방문일 중 획득 비율

### 활성화 — 7일 내 첫 획득
- **묻는 것:** 새로 온 사람이 첫 주 안에 재미(첫 획득)까지 가나
- **흐름:** 방문 → 게임 진입 → 캐릭터 선택 → 첫 획득
- **지금:** 진입한 사람의 39% (웹 42% · 토스 34%)
- **아래 칸 — 첫 획득까지 시간:** 진입부터 첫 획득까지 중앙값 **2.1분**. 7일 안에 첫 획득을 한 사람의 **75%가 진입 5분 안에** 했고, 90%가 첫 세션 안에 했습니다. 5분을 넘기면 7일을 더 기다려도 10%p 만 늘어납니다 → **첫 5분이 갈림길**
- **질문:** "활성화가 재방문의 원인인가?" → 아직 모릅니다. 그래서 첫 5분 수확 실험을 합니다
- **질문:** "왜 하필 5분인가?" → 감으로 정한 게 아니라, 활성화의 4분의 3이 실제로 5분 안에 일어나서입니다
