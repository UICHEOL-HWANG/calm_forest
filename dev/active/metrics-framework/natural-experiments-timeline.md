원천: 앱인토스 콘솔 번들 이력 74건(라이브 반영 시각 `lastDeployedAt`) · git `main` 커밋 날짜

## 거르는 기준 (결과 보기 전 고정)

1. 배포 날짜가 분명하다
2. 첫 5분·첫 주 행동에 직접 닿는 변화다 (분석 목적의 주 결과와 맞음)
3. 앞뒤 7일 안에 다른 큰 변화가 없다 (겹치면 "묶음 처치"로만 해석)
4. 처치를 받지 않은 비교 집단이 있다 (웹↔토스 시차, 한쪽에만 생긴 사고 등)

## 발견 1 — 웹↔토스 배포 시차는 대조군이 되지 못한다

- git 커밋 → 토스 라이브 반영까지 **중앙값 0.2시간** (번들을 올리면 대부분 수십 분 안에 승인·출시)
- 하루 가까이 벌어진 것은 3건뿐: 🍂 4계절 순환 21.5시간 · 🪙 코인 첫 루프 19.0시간 · 🎨 주민 색·마을 지도 13.7시간
- 하루도 안 되는 창에 들어오는 신규는 0~3명 → 이중차분 불가. **처음 제안한 설계는 데이터로 기각**

## 발견 2 — 토스에만 생긴 사고가 진짜 대조군을 만든다

- 🚨 **토스 mTLS 인증서 삭제 사고 (9/5 ~ 9/13, 8일)**: 토스 계정 검증이 4010 으로 실패 → 자동 로그인 대신 "바로 플레이하기"/게스트로 떨어짐 (메모리 기록)
- 같은 기간 웹은 정상 → **웹을 대조군으로 한 이중차분** 가능: (토스 사고 중 − 사고 후) − (웹 같은 기간 차이)
- 같은 기간 배포(코인 루프·초보자 안내서·주민 지도 등)는 웹·토스에 같은 날 들어갔으므로 차분에서 빠진다
- 한계: 토스 출시(9/4) 바로 다음 날 시작이라 **사고 전 기간이 하루뿐** → "사고 중 vs 복구 후" 비교. 복구 후 기간에 다른 변화가 섞였는지는 웹 추세로 확인
