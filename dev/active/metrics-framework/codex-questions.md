# M5 검수 질문

2026-10-08 · `analytics/codex` · 정의서는 수정하지 않음.

SQL을 정답지에 맞추기 위해 제외 규칙을 약화하지 않았다. 아래 항목을 확정하기 전에는
M5 전체를 완료로 체크할 수 없다. 집계 검증은 `sql/analytics/metrics/run.py --baseline`,
원인 분리는 `--baseline --reference-differences`로 재현한다. 사용자 ID·CSV는 저장하지 않는다.

## Q1. GA4 퍼널에도 공통 베타 제외를 적용하는가?

- 브리프: 공통 규칙 전부를 official에 적용한다. 베타는 9/9~9/15 세션만 제외한다.
- 정답지 `FUNNEL_SQL`: 페르소나·개발자만 제외하고 베타는 제외하지 않는다.
- SQL: GA4 `user_properties.ab_variant`(이벤트 파라미터 `variant` fallback)를 사용한다.
  같은 `user_pseudo_id`·`ga_session_id`·KST 날짜에서 베타로 확인된 이벤트가 있으면
  그 날의 해당 세션을 제외한다. 속성이 아직 설정되지 않은 앞 이벤트만 남기는 오류를 피한다.
- 결과: 웹+토스 **407 → 174 → 147 → 63**, 웹 **325/101/88/38**, 토스 **82/73/59/25**.
  검수표는 **415/182/153/74**, 웹 **333/109/94/49**다.
- 베타 제외를 이벤트의 속성 있는 행에만 적용해 보면 415/182/**152**/74가 된다.
  이 방식은 같은 베타 세션의 앞 이벤트를 official에 남겨 SL의 세션 제외와 일관되지 않다.
- 확인 필요: 공통 베타 제외를 적용한 퍼널 기준선을 갱신할지, 퍼널을 예외로 정의할지?

## Q2. 경제 지표의 공통 개발자·베타 제외와 정답지 중 어느 것이 기준인가?

- 정답지 `ECON_SQL`: 플랫폼·페르소나만 제외한다. 개발자·베타 제외가 없다.
- SQL: EC의 `client_id`, `variant`, KST `created_at`으로 공통 규칙을 그대로 적용한다.
- 코인 순증가/경제 기기: **24.97 / 104.48 / 224.55 / 101.81**.
  검수표: **384 / 228 / 210 / 96**.
- 소비 비율: **5/36, 4/31, 4/29, 4/16** (13.89 / 12.90 / 13.79 / 25.00%).
  검수표: **26 / 23 / 13 / 24%**.
- `checks/reference_differences.sql`는 reference·developer_only·beta_only·official
  네 단계의 집계를 반환해 각 제외의 영향을 구분한다.
- 확인 필요: 공통 규칙을 유지하고 경제 기준선을 갱신할지, 경제 지표를 예외로 정의할지?

## Q3. 계측 전의 세이브 실패를 0과 NULL 중 무엇으로 표시하는가?

- 정의서 부록 A: `save_load_failed`는 9/14 배포부터 존재, 이전은 측정 불가.
- 검수표는 9/7 주도 0으로 표시한다.
- SQL: **NULL / 0 / 0 / 0**. 9/14 주도 배포 전 시간은 미측정이라는 한계를 적었다.
  실패 판단에 사용하는 복구 기록은 population 필터와 무관하게 같은 세션의 전체 기록에서 찾는다.
  그렇지 않으면 베타 속성이 붙은 복구 행이 빠져 자동 복구를 실패로 잘못 세게 된다.
- 확인 필요: 계측 전 NULL을 유지할지, 관측 건수 0과 측정 불가 표시를 별도 열로 병기할지?

## Q4. 코호트의 플랫폼은 어느 이벤트로 결정하는가?

- 정답지: 첫 7일의 `ANY_VALUE(platform)` 후 NULL→web. 둘 이상의 플랫폼은 결정적이지 않다.
- 이벤트별 빈 속성→web만으로 코호트를 귀속하면, Android·itch의 초기 빈 속성 방문이
  웹으로 남아 웹+토스 방문 합계가 434가 된다.
- 검토용 구현: 첫 7일 안에 **처음 기록된 비어 있지 않은** platform 속성으로 코호트를 귀속하고,
  하나도 없으면 web. 이벤트 날짜는 전부 `event_timestamp`의 KST 날짜다.
  베타 제외를 끄면 이 방식은 기준선 웹333·토스82를 재현한다.
- 확인 필요: 이 결정적 귀속 규칙을 채택할지? 승인 전에는 확정 정의로 취급하지 않는다.

## Q5. 플랫폼별 신규는 게임 전체의 신규인가, 해당 플랫폼에서의 신규인가?

- all의 신규·유지·복귀는 정답지와 정확히 일치한다.
- 검토용 플랫폼 분해는 각 플랫폼의 전체 방문 이력으로 첫 주와 지난주를 찾는다.
  계정이 웹에서 토스로 이동하면 토스에서는 신규가 될 수 있다.
- 확인 필요: 플랫폼별 신규/유지/복귀를 해당 플랫폼의 이력으로 볼지, 게임 전체의 이력으로 볼지?
  양쪽 모두 all의 기준선을 바꾸지는 않지만 플랫폼 분해의 의미가 달라진다.
