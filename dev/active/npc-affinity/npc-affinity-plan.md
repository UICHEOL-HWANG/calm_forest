# npc-affinity 계획

설계 원문: `docs/superpowers/specs/2026-11-12-npc-affinity-design.md` (이 파일은 그 요약과 진행 순서)

## 목표
집 완성 뒤 주민과 며칠에 걸쳐 친해질 이유를 만든다. 호감도에 이름 붙은 단계(아는 사이 1 · 이웃 3 · 친구 6 · 단짝 10 · 가족 15)를 주고, 단계마다 주민이 📮 소식함으로 편지와 보상을 보낸다. 단짝은 주민 전용 꾸미기, 가족은 탁상 액자.

## 확정된 결정 (2026-11-12, 사용자)
- 방향: A 관계 단계 + C 편지
- 표시: 대화창 칩 + 📒 주민 수첩
- 편지: 소식함 "편지" 칸 (단계 오른 순간은 HUD 알림 + ☰·소식함 빨간 점)
- 아이템: 단짝 전용 1개 × 11 + 공통 틀 탁상 액자 × 11
- 선물 하트 상한: 주민당 하루 +2
- 올빼미: 일일 의뢰 5건 다 끝내면 하루 +1
- 기존 ❤️3마다 답례는 없앤다

## 진행 순서
1. 문구 후보 검수 (칩·수첩·알림·상한 대사·이웃/친구 편지 22통·아이템 이름 11개)
2. 꾸러미·친구 보상 값을 판매가표로 재계산, 💎·코인 발행량 추정
3. P1 구현 (TDD): `js/affinity/stages.js` → 선물 상한·올빼미 +1 → 칩 → 📒 수첩 → 소식함 편지 칸 → 소급 → 계측
4. P1 실게임 검증 (PC·375px·가로 폰·토스 웹뷰), 코드 리뷰
5. P1 배포 (새 꾸미기 id 없음 → 단독 가능, 5곳 규칙은 deploy-checklist 대로)
6. 다음 날 BQ 재검증
7. P2 아트: 단짝 11종 + 액자 틀, 4명씩 묶어 3안 렌더 비교
8. P2 문구: 단짝/가족 편지 22통
9. P2 구현·검증, 5곳 동시 배포, E3 사전등록에 배포일 기록

## 위험
- 새 꾸미기 id 22개 → 옛 클라이언트가 지운다 → P2 는 5곳 동시 배포 필수
- `hintsSeen` 밖에 새 최상위 필드를 만들면 옛 클라이언트가 지운다
- GA4 파라미터 키 상한 23
- 소식함은 서버 공지와 클라이언트 편지가 섞인다 → 탭으로 분리, 읽음 기준(`noticeSeenId` vs `affRead`) 따로
- 경제: 이웃 꾸러미 11명 × 1회 + 친구 💎 2개. 한 번뿐인 보상이라 일일 발행엔 영향 작음, 그래도 가드레일로 본다
